# func_8009094C

## Boundary

- USA VRAM range: 0x8009094C .. 0x80090A08 inclusive (0xC0 = 192 bytes, 48 instructions).
- USA ROM offset: 0x9154C.
- Terminates with a return whose delay slot performs the last byte store of the
  copied record, so that store belongs to this function.
- The assigned size of 192 was correct; no boundary correction was needed.
  Direct callers target 0x8009094C, and no branch from the preceding function
  reaches into this body.

## Callers and callees

- One direct call site in the USA build (from func_80090880, which sets an
  unrelated byte flag and then passes its second argument through as the only
  parameter).
- No callees; leaf function.

## Globals and access widths

- `D_80149CB0` — single byte, written with zero. Declared `u8`.
- `D_8014D720` — base of a byte-addressed buffer. Three distinct accesses:
  * a 32-bit word written with 1 at byte offset 0x3C;
  * a run of single bytes cleared from offset 0 upward;
  * a six-byte record plus a one-byte terminator written after that run.
  Declared `extern u8 D_8014D720[]` and the word at 0x3C reached through a
  32-bit cast, which is what shares one address register between all three uses.

## Regional addresses

The body is instruction-for-instruction identical in every version; only the
two globals move.

## Recovered behaviour

The function rebuilds the front of the shared byte buffer so that it holds a
single fixed six-byte record at a caller-chosen position.

1. The one-byte flag is cleared.
2. The 32-bit field at offset 0x3C of the buffer is set to 1.
3. A six-byte record is composed on the stack with the fixed contents
   1, 3, 0, 255, 255, 255.
4. The first *count* bytes of the buffer (count is the only parameter) are
   cleared one byte at a time. A count of zero or less clears nothing.
5. The six-byte record is copied into the buffer immediately after the cleared
   run, and the byte that follows the record is set to 254, which acts as the
   end marker of the record list.

Because the record type is byte aligned, the copy into the buffer is a
byte-safe block move while the stack copy of the record is word aligned; that
asymmetry is a property of the types, not of any special construct.

Two source-shape facts were needed for the byte-exact result:

- the three locals must be declared in the order pointer, record, loop counter.
  The stack slot chosen for a local aggregate depends on the declaration order
  of the surrounding locals, and only this order places the record at the
  offset the original uses;
- the buffer pointer is advanced by six between the record copy and the
  terminator store, which is why the record copy is expressed relative to the
  advanced pointer.

## Status

Exact. Verified byte-identical against USA, Japan, Europe and lrg_rev1.
