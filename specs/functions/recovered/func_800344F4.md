# func_800344F4

## Boundary

- USA VRAM range: 0x800344F4 .. 0x8003464C inclusive (0x15C = 348 bytes, 87 instructions).
- USA ROM offset: 0x350F4.
- Ends with a return whose delay slot releases a 56-byte frame; the two
  instructions before it restore the two callee-saved double registers the
  routine borrows for loop-invariant floating-point values.
- Three direct call sites, all targeting 0x800344F4. Assigned size 348 was
  correct; no boundary correction.

## Callers and callees

- Three direct callers. Two pointer arguments, no result.
- Leaf function; no callees.

## Globals and access widths

- `D_800D6960` — read as a 32-bit word at offset 0x1C, once per matrix row, and
  tested against bit 0x4000. The base address is materialised once.
- Two single-precision constants at 0x800AAAD0 and 0x800AAAD4. These are **not**
  program data: they are the compiler's own read-only constant pool for this
  translation unit, holding minus and plus one millionth in that order. Writing
  them as float literals in the source reproduces both the pool contents and the
  register assignment; declaring them as external symbols instead changes which
  floating-point registers every loop-invariant value receives.

Argument layout:

- argument 1 — a pointer to 32 signed 16-bit values: sixteen whole parts
  followed by sixteen fractional parts starting 0x20 bytes in.
- argument 2 — a four by four array of single-precision floats.

## Recovered behavior

Converts a four by four single-precision matrix into the split fixed-point form
the graphics hardware consumes.

It walks the matrix row by row and column by column. Each element is read, and
for the first column of every row the routine consults bit 0x4000 of the global
flag word: when that bit is set the element is negated, which mirrors the
matrix horizontally. The flag is re-read for every row rather than cached.

The element is then clamped. Positive values above thirty-two thousand are
pinned to thirty-two thousand, and positive values below one millionth are
flushed to zero. Values that are not positive are treated symmetrically:
below minus thirty-two thousand they are pinned to minus thirty-two thousand,
and above minus one millionth they are flushed to zero. The effect is a
saturating range with a small dead band around zero.

The clamped value is scaled by 65536 and truncated to a 32-bit integer, which is
written to a stack slot. The upper half of that slot is appended to the whole
part table and the lower half to the fractional part table; both tables advance
by one entry per element, so after sixteen elements the whole parts fill the
first 32 bytes of the destination and the fractional parts the next 32.

Source-shape notes established by matching:

- The two halves have to be read back out of the stack slot through two separate
  pointer variables, one aimed at the slot and one aimed at the slot plus two.
  Indexing a single pointer produces one base register with displacements 0 and
  2 instead of the original's two base registers.
- The row and column counters are 16-bit; both loops sign-extend the counter
  after each increment.
- The zero used in the comparison and the zero assigned by the dead-band cases
  must be distinguishable to the compiler: writing the sign test against the
  integer literal zero and the assignments against the float literal zero
  yields the two separate zero registers the original holds. Using the same
  spelling in both places shares one register and loses two instructions plus
  one of the callee-saved register saves.
- The local declaration order decides the stack slot the 32-bit temporary lands
  in, because the compiler lays locals out downward from the top of the frame in
  declaration order. The temporary must be the seventh declaration, preceded by
  the two counters and four pointers.

## Section placement

Because the two epsilons are compiler-generated constants, this unit emits a
`.rodata` section that must be linked at the constant-pool address in the table
above (0x800AAAD0 for USA and lrg_rev1). The verification harness's generated
linker script only positions `.text`, so the unit needs an explicit `.rodata`
placement; with it, the linked `.text` is byte-identical and the function symbol
lands at its canonical address.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision,
given the `.rodata` placement described above.
