# func_8005EE18

## Boundary

VRAM 0x8005EE18 .. 0x8005EEFC (exclusive), ROM 0x5FA18, size 228 bytes (57
instructions). The body ends with the return jump whose delay slot releases the
stack frame. The single direct call site targets 0x8005EE18. One interior label
(0x8005EEC8) has no callers and no branches to it: it is the stranded copy of a
branch-likely delay slot, not a function boundary.

## Callers

One direct call site at 0x8005F01C, which loads the pointer argument from a
caller stack slot and ignores the result.

## Callees

- `func_8000FF54(s32 index, f32 *triple)`, already recovered elsewhere in the
  project; it takes an index and the address of three consecutive floats.

## Globals

None. The routine only walks the buffer it is handed and writes to its own
stack.

## Buffer format

The argument points at a stream of 32-bit cells that are read either as signed
words or as floats:

- a leading run of arbitrary words terminated by the sentinel 0xFFFFFFFF;
- the word after the sentinel is a section tag, and the routine only continues
  when it equals 0x44617461;
- the next word is a signed element count;
- then `count` items follow. An item whose first word is 0x4C537472 is four
  cells long: the tag and three floats. Any other item is a single cell.

## Stack use

Three consecutive floats are staged in a local array at the top of the frame
and its address is handed to the callee; the array must be declared after the
scalar locals to land at the offset the original uses.

## Regional addresses

| version  | entry      | ROM     | callee        |
|----------|------------|---------|---------------|
| usa      | 0x8005EE18 | 0x5FA18 | func_8000FF54 |
| japan    | 0x8005F980 | 0x60580 | func_8000FF54 |
| europe   | 0x800642FC | 0x64EFC | func_800103B4 |
| lrg_rev1 | 0x8005EE18 | 0x5FA18 | func_8000FF54 |

The Japanese and European bodies were read in full at those addresses and are
the same shape as USA; only the European callee is relocated.

## Recovered behavior

The routine skips forward over the buffer until it reaches the terminator
value, then looks at the word that follows it. If that word is not the expected
section tag the routine does nothing further.

Otherwise it reads the element count that follows the section tag and steps
through exactly that many elements, keeping a running element index.

For an element carrying the recognised item tag, the three floats that follow
the tag are copied into a small local buffer and handed to the consumer along
with the element's index; the cursor then advances past all four cells. Any
other element is skipped by a single cell. A non-positive element count means
no elements are visited at all.

The pointer advance for a recognised item is computed before the consumer is
called and applied afterwards; writing it as a plain post-call increment
compiles one instruction shorter and loses the match.

## Status

Exact in USA, Japan, Europe and lrg_rev1 under the standard IDO 5.3 -O2
profile. No per-unit compiler flags required.
