# func_80094E44

## Boundary

USA VRAM 0x80094E44-0x80094ED0, ROM 0x95A44, size 140 bytes (35 instructions).
The body ends with a return whose delay slot holds the final partial-word store,
after the stack frame has already been released. The single direct call site
targets 0x80094E44 and the preceding function returns before it, so the boundary
is correct.

## Callers / callees

One caller, which passes an unsigned byte loaded from its own frame. No callees;
leaf function.

## Globals

- D_8014C530: a 64-byte serial command block. Written as individual bytes at
  offsets 0 through 3 and 16, as three partial words spanning offsets 4 through
  15, and as one 32-bit word at offset 0x3C.

## Regional addresses

- Japan: 0x80095B34, ROM 0x096734, 140 bytes; the block moves to 0x8014F7A0.
- Europe: 0x8009A394, ROM 0x09AF94, 140 bytes; the block moves to 0x801551D0.
- lrg_rev1: shares the USA addresses and symbols.

Both regional bodies were read independently and are identical to the USA body
apart from the relocated block address.

## Recovered behaviour

The function formats a single read request into the shared serial command block
and arms it. It first sets the block's trailing status word to one, which is the
value the hardware interprets as "execute this block". It then fills in a small
command record: a transmit length of two bytes, a receive length of eight bytes,
the read opcode, and the byte-sized address argument supplied by the caller. The
eight payload bytes of that record are deliberately left alone, since they are
the window the device will write its reply into.

The first four bytes of the block are cleared one at a time, which skips the
four leading channels; the twelve-byte command record is then copied into the
block starting at offset four, and the byte immediately after it is set to the
end-of-block marker 0xFE.

Because the copy destination is reached through a byte cursor, the compiler
stores it with partial-word instructions even though the block itself happens to
be aligned.

## Implementation notes for the matching build

The original frame is 24 bytes with the twelve-byte command record sitting eight
bytes above the stack pointer. A lone twelve-byte local is placed twelve bytes
above the stack pointer instead, so the original must have declared a further
four-byte automatic above the record that the surviving code never touches; the
recovered source declares it and casts it to void. Folding those four bytes into
the record as a sixteen-byte structure does not work: the copy source then loses
its known alignment and the compiler switches to partial-word loads as well.

## Status

exact in USA, Japan, Europe and lrg_rev1.
