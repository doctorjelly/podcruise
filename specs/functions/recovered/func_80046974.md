# func_80046974

## Boundary
- USA VRAM `0x80046974` .. `0x800469B4` (exclusive), ROM `0x47574`, size 64 bytes.
- One 0x18-byte frame, one call, then three global writes; the frame teardown sits
  in the return's delay slot, so the last word of the function is the stack
  adjustment rather than an empty slot.
- One direct call site, targeting `0x80046974`; no interior labels.

## Callers
One call site inside a larger start-up sequence that runs several initialisers back
to back. No result is consumed.

## Callees
- `func_80018324(buffer, size)` — pointer plus a 32-bit count; called here with the
  literal size `0x5064`.

## Globals
- `D_8011A288` — the base of a large block; its address is passed to the helper.
- `D_8011A29C` — 32-bit word, written with `0x97`.
- `D_8011A2A0` — 32-bit pointer slot, written with the address of `D_8011A2A8`.
- `D_8011A2A8` — only its address is taken.

Note that the three later symbols sit at `+0x14`, `+0x18` and `+0x20` from the block
base, but the original build materialises each of their addresses independently,
which is the signature of separately declared globals rather than members of one
aggregate. (The sibling routine `func_8007E0AC` performs the same three operations
on an aggregate and produces different register usage as a result.)

## Recovered behaviour
The routine prepares one fixed subsystem record. It first hands the record's base
address and a fixed length of `0x5064` bytes to the shared preparation helper, then
stamps the record's identifier word with the constant `0x97` and points the record's
link slot at the following storage area. Nothing is read back and no result is
returned.

## Status
Exact on USA, JP, EU and lrg_rev1.
