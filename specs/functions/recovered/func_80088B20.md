# func_80088B20

## Boundary
USA VRAM 0x80088B20..0x80088B6B inclusive (76 bytes, 19 instructions), ROM
0x89720. The body ends with the return jump plus an empty delay slot, the frame
adjustment is the first executed instruction, and both direct call sites target
0x80088B20, so the assigned boundary is correct.

## Callers
Two call sites, each passing a single object pointer and ignoring any result.
Two structurally identical neighbours (0x80089610 and 0x80089670) build the same
request object from the same owner fields with a different first field value and
an extra byte or half-word field, which corroborates the layout below.

## Callees
`func_8008FC3C`, called with three arguments: the owner's embedded queue at
offset 0x14, the address of a locally built request, and a zero third argument.
Inside that callee the request is copied sixteen bytes at a time, so the request
object is exactly sixteen bytes; its third argument is compared against
0x7FFFFFFF, so it is a signed 32-bit value.

## Globals and access widths
None.

## Object layout used
Owner: an embedded queue at 0x14, a 32-bit record index at 0x3C, and a pointer
to an array of 48-byte records at 0x40.
Request (sixteen bytes, stack local): a 16-bit kind at 0x00 and a record
pointer at 0x04; the remaining eight bytes are filled in by the callee.

## Regional addresses
* JP 0x80089810 (ROM 0x8A410); dispatcher at 0x8009092C.
* EU 0x8008E070 (ROM 0x8EC70); dispatcher at 0x8009518C.
* lrg_rev1 shares the USA addresses.
Both regional bodies were read directly; they differ from the USA body only in
the relocated call target.

## Recovered behavior
The routine posts a "kind 1" request for the owner's currently selected record.
It builds a small request object on its own stack, sets the request kind to 1,
points the request at element `index` of the owner's 48-byte record array, and
hands the request to the queue dispatcher `func_8008FC3C` with a zero parameter.
It returns nothing.

## Notes on shape
Reading the record array base into a local before indexing it is what
reproduces the original frame size and stack offsets: the compiler reserves an
eight-byte frame slot for that local even though the value never leaves a
register, which pushes the request object eight bytes higher in the frame.

## Status
Exact on USA, JP, EU and lrg_rev1 with the accepted `ido53_o2` profile.
