# func_80093C00 — write the CPU status control register

## Boundary

- USA VRAM `0x80093C00` .. `0x80093C0F`; ROM `0x94800`; size 16 bytes.
- Ends with `jr $ra` plus a `nop` delay slot; the single direct caller targets
  `0x80093C00`. **No boundary correction needed.**
- The disassembler already flags this unit as a handwritten function and the
  first instruction as a handwritten instruction.

## Callers

One direct call site, inside `func_8008B580` (USA `main_8BDB0.s`). The caller
first reads the same register via `func_80093C10`, ORs the result with
`0x20000000`, and passes that as the only argument. That is the classic
"read-modify-write one status bit" idiom used during system start-up.

## Callees

None.

## Globals and access widths

None. The function touches no ordinary memory; its only effect is on a
coprocessor 0 control register.

## Regional addresses

| version    | VRAM         | ROM        | size |
|------------|--------------|------------|------|
| us         | `0x80093C00` | `0x94800`  | 16   |

All regional bodies are the same four words.

## Recovered behavior

Takes one 32-bit word and installs it wholesale into the processor's main
status/mode control register — the register that carries the interrupt-enable
mask, the current and previous privilege/exception levels, and the
coprocessor-usable bits. One idle slot follows the write so that the new mode
is in effect before the return. Nothing is returned.

## Status

**skipped** — not recoverable as C. The body is a single privileged
system-control-register transfer. The compiler has no C construct that emits
it; every real implementation of this routine is hand-written assembly, which
the project's IP and source rules forbid reproducing here (no inline assembly).
It should be carried as a handwritten assembly unit in the build rather than as
a `src/functions/*.c` file.
