# func_80087754

## Boundary

USA VRAM 0x80087754 - 0x800877AB (88 bytes, ROM 0x88354). The body ends with the
return instruction whose delay slot carries the frame release, so the last four
bytes are part of the function. All eight direct call sites target 0x80087754,
the preceding function terminates before it, and the only internal branch target
is the loop head four instructions in. The boundary is correct.

## Callers

Eight direct call sites, all in the file that begins at ROM 0x18B28
(0x80030D48, 0x80030E84, 0x800443B8, 0x80046314, 0x80046744, 0x8004A6FC and
two further sites). The single argument is variously a null pointer, a pointer
to a static object such as the one at 0x8011AC60 or 0x8011A288, or a pointer
loaded from another structure, so the parameter is an opaque pointer that this
function only forwards.

## Callees

* `func_80018114` (0x80018114) - called once per table entry with the entry
  address and the forwarded argument.

## Globals

* `D_80120DF0` (0x80120DF0) - base of a table of four records, each 0x170 bytes,
  addressed only as whole-record addresses (no member access here).
* `D_801213B0` (0x801213B0) - the address one past the end of that table; it
  appears in the original as the loop's stop value, which is the table base plus
  0x5C0. The recovered C names only the table base, and the assembler recreates
  the same end address.

In every version the end address is exactly 0x5C0 above the base, i.e. four
records of 0x170 bytes, and the loop stride is 0x170. The regional bodies were
read independently and match the USA shape.

## Recovered behaviour

The function walks the four fixed records of the table at D_80120DF0 in order
and calls the helper once for each, passing the record's address and the
caller's argument unchanged. There is no early exit and no return value; the
trip count is a compile-time constant, so the original build emitted the loop
without a guard test, advancing a pointer by one record per pass and stopping
when it reaches the address just past the last record. The argument is held in a
callee-saved register because it must survive every call.

## Status

Exact on USA, Japan, Europe and lrg_rev1 with the project's accepted profile.
