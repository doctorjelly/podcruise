# func_80029A3C — reset one record of either of two per-slot tables

## Boundary — corrected

- USA VRAM range: `0x80029A3C` .. `0x80029C23` (inclusive), **488 bytes**.
- ROM offset `0x2A63C`, translation unit `main_18B28.s`.
- There are three return sites: the selector's default exit at
  `0x80029A50`/`0x80029A54` (empty delay slot), the end of the first table's
  block at `0x80029B34`/`0x80029B38` (empty delay slot), and the end of the
  second table's block at `0x80029C1C`/`0x80029C20` (empty delay slot). The last
  of these is the end of the function; the next function begins at `0x80029C24`
  with its own global load.
- **The assigned extent (56 bytes) was wrong and was corrected to 488.** Two
  separate defects combined. First, the generated inventory double-counts
  instructions for this ROM range because two translation units cover it, so the
  assigned size is twice the size of the entry block alone. Second, and more
  importantly, the heuristic labelling cut the function at its first return and
  presented the two case bodies as separate routines at `0x80029A58` and
  `0x80029B3C`. Neither is a function: neither has any call site, and each is
  reached only by a forward conditional branch taken from inside the entry block
  at `0x80029A3C`/`0x80029A48`. The entry block is also not self-contained — it
  loads the constant 1 into an argument register that both case bodies then
  store — so the three fragments are one function.
- The 488-byte extent is confirmed by construction: the recovered C compiles to
  exactly these 488 bytes at this address.

## Callers

Six distinct direct call sites: `0x8001BD0C`, `0x8001CF6C`, `0x8001CF7C`,
`0x8002808C`, `0x800280B0`, `0x800395C4`. Every one passes a small selector
constant (0 or 1) as argument 1 and a record index as argument 2, and none uses
a result, so the routine takes two 32-bit integers and returns nothing.

Two of the call sites are the bodies of index loops: the loop at `0x8002808C`
sweeps selector 0 over a range of indices and the loop at `0x800280B0` sweeps
selector 1 over indices 0 through 3.

## Callees

None (leaf).

## Globals and access widths

| Symbol | Shape | Use |
| --- | --- | --- |
| `D_80113E60` | array of 44-byte records | selector 0 target; one record written per call |
| `D_80113680` | object with a 0x14-byte header followed by four 44-byte records | selector 1 target; one record written per call |

Both tables use the same 44-byte record and the same field layout. Within a
record this routine writes: three bytes at offset 0x00; single bytes at 0x03,
0x04, 0x05, 0x06, 0x07, 0x08, 0x09, 0x0A, 0x0B and 0x1C; four 16-bit values at
0x0C, 0x0E, 0x10 and 0x12; two 32-bit words at 0x14 and 0x18; seven bytes from
0x1D; seven bytes from 0x24; and, for the second table only, one byte at 0x2B.
The byte at 0x07 is written as signed -1, whereas the bytes at 0x05 (first
table) and from 0x24 are written as unsigned 0xFF.

That the second table's records start 0x14 bytes past its symbol is not a guess:
`func_8002D968` is called on `0x80113694`, `0x801136C0`, `0x801136EC` and
`0x80113718`, which are exactly `D_80113680 + 0x14 + 44*n` for n = 0..3. Those
calls compare the first three bytes of each record, which is the field this
routine clears in its last loop.

## Recovered behaviour

The routine resets one record of a per-slot table to its idle state. Argument 1
chooses the table: zero selects the first table, one selects the second. Any
other value is ignored and the routine returns without touching anything.
Argument 2 is the index of the record within the chosen table.

For either table the reset is the same sequence of field writes: two status
bytes cleared, an identity byte set (to 0xFF in the first table, to the record's
own index in the second), another status byte cleared, a signed byte set to -1,
a 32-bit field set to 0x22E01, a second 32-bit field set to 400, and a flag byte
set to 1. Four adjacent 16-bit counters are then zeroed, three consecutive flag
bytes are set to 1 with the byte after them cleared, and two parallel seven-entry
byte arrays are filled — the first with zeros, the second with 0xFF. Finally the
three-byte identifier at the start of the record is cleared. The second table
additionally clears one trailing byte that the first table's block leaves alone;
that trailing byte is the only behavioural difference between the two branches
besides the identity byte and the table itself.

Nothing is read back and there is no result. The order of the field writes is
preserved exactly as the original emitted them, because it is observable in the
compiled form.

## Status

Exact in USA, Japan, Europe and lrg_rev1. Boundary corrected from 56 bytes to
488 bytes.
