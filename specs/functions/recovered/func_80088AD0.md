# func_80088AD0

## Boundary

- USA VRAM range: 0x80088AD0 .. 0x80088AF7 inclusive (0x28 = 40 bytes, 10 instructions).
- USA ROM offset: 0x896D0.
- Four setup instructions, a four-instruction loop whose branch target is the
  first of them, and a return with an empty delay slot.
- Assigned size 40 was correct; no boundary correction.

## Callers and callees

- Eight direct call sites in the USA build, not six as the assignment recorded.
  They are spread through the boot and level-transition code (for example at
  0x8002E594 and 0x800310C0), always immediately before or after handing a
  buffer to hardware.
- No callees (leaf function).

## Globals and access widths

- None. The routine addresses a fixed physical window by absolute constant and
  reads or writes no data symbol.

## Regional addresses

## Recovered behavior

Flushes the processor's entire data cache. It walks the whole cached kernel
window from its base for eight kilobytes, the exact size of the data cache, in
sixteen-byte steps, the exact size of a cache line, and issues one privileged
cache-maintenance operation per line. The operation selected is index
write-back-invalidate on the data cache: any dirty line is written out to main
memory and every line is then marked invalid, so afterwards nothing the
processor has cached can be stale with respect to memory or hide a pending
write from a DMA engine. The loop condition stops one line short of the end and
the step happens in the branch delay slot, so the final line is processed
exactly once. Takes no arguments and returns nothing.

## Status

Skipped. This is not compiler output and cannot be recovered as C.

The body is hand-written assembly: the cache-maintenance instruction it is
built around is a privileged operation with no C expression that can produce
it, and the project rules forbid inline assembly, register bindings and other
compiler-steering tricks. The disassembly evidence agrees independently — the
Japanese, European and large-cartridge listings all carry an explicit
hand-written marker on this body, and every version flags the cache instruction
itself as hand-written.

The correct disposition is to keep this function as assembly permanently rather
than to count it as an unmatched C target. It is one of the small library
routines shipped in hand-written form with the console's system library, and
it should be excluded from the C-recovery inventory instead of being retried.
