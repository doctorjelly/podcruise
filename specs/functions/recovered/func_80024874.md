# func_80024874

## Boundary

VRAM 0x80024874 .. 0x80024954 (exclusive), ROM 0x25474, size 224 bytes (56
instructions). The body terminates with the return jump whose delay slot is the
stack-frame release, so the assigned boundary is correct. Both direct call sites
target 0x80024874, and no branch from the preceding function crosses into it.

## Callers

Two direct call sites in USA, both inside the same translation unit
(0x80024A24 and 0x8002521C). Each passes a single pointer argument and ignores
the result, so the function returns nothing.

## Callees

- `func_8002DAD0(pointer, signed byte, unsigned byte) -> s32`. The callee's own
  entry spills argument 2 and argument 3 into their home slots and immediately
  narrows them (sign-extend from 8 bits for argument 2, mask to 8 bits for
  argument 3), which fixes both parameter widths.

## Globals and access widths

- `D_800A21B4` — array of unsigned bytes, read with an 8-bit unsigned load and
  used as a signed count.
- `D_800A22E8` — two-dimensional array of 32-bit words with a row of seven
  entries (row stride 28 bytes).
- `D_8011A240` — structure; only the 32-bit word at offset 0x30 is touched
  (cleared once, then incremented).

## Subject object fields

- offset 0x5D — signed byte, compared against a table entry.
- offset 0x5E — signed byte, used as the row selector for both tables and
  passed on to the callee. It is re-read after every call, so the source reads
  the field rather than caching it.

## Recovered behavior

The subject carries a group selector (byte at 0x5E) and a current choice (byte
at 0x5D). A shared counter word is reset to zero on entry.

The routine walks the slots of the selected group. The number of slots for that
group comes from a per-group byte table; if the group has no slots the routine
simply returns with the counter left at zero.

For each slot in turn it looks up the slot's identifier in a per-group table of
seven 32-bit entries. If that identifier equals the subject's current choice,
the walk stops immediately and the routine returns, leaving the counter at
whatever it had reached.

Otherwise it asks a predicate whether the subject qualifies for that slot,
passing the subject, its group selector, and the slot number. Every slot the
predicate accepts adds one to the shared counter.

Because the group selector is re-read from the subject on each pass, a
predicate call that changes it redirects both the slot table and the slot count
for the remaining iterations.

## Status

Exact in USA, Japan, Europe and lrg_rev1 under the standard IDO 5.3 -O2
profile. No per-unit compiler flags required.
