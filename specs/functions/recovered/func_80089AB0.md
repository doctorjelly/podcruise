# func_80089AB0

## Boundary

USA VRAM 0x80089AB0 - 0x80089BA3 inclusive, ROM 0x8A6B0, 244 bytes (61
instructions). The return instruction is at 0x80089B9C and its delay slot at
0x80089BA0 carries the final store, so the last observable effect happens in
the delay slot. One direct caller. Boundary as assigned: correct.

## Callers and callees

One direct caller; leaf function, no return value.

## Arguments

One unsigned byte. The entry masks the incoming register to eight bits, which
is the compiler's normalisation of a sub-word parameter and therefore fixes the
declared width at one byte.

## Globals and access widths

* D_80149C70 - a 15-element array of 32-bit words (60 bytes). Cleared word by
  word, then reinterpreted as a sequence of eight-byte byte-aligned records.
* D_80149CAC - 32-bit word, written as 1.
* D_80149CB1 - unsigned byte, the number of records to write; read afresh on
  every loop test.

## Regional addresses

* Japan: VRAM 0x8008A7A0, ROM 0x8B3A0; globals D_8014CEE0, D_8014CF1C,
  D_8014CF21.
* Europe: VRAM 0x8008F000, ROM 0x8FC00; globals D_80152910, D_8015294C,
  D_80152951.
* lrg_rev1: shares the USA addresses and the USA global names.

All three regional bodies were disassembled independently and match the USA
body instruction for instruction, differing only in the relocated halves of the
global addresses.

## Recovered behavior

The routine rebuilds a fixed 60-byte command buffer as a run of identical
eight-byte request records followed by a terminator.

It first clears all fifteen words of the buffer, then writes 1 into the
adjacent status word. It builds one eight-byte template of unsigned bytes:
0xFF, 1, 3, the argument byte, then four more 0xFF bytes. A cursor is placed at
the start of the buffer and the template is copied to the cursor once per
device, for as many devices as the count byte reports, advancing the cursor
eight bytes each time; a count of zero writes no records. Finally the byte at
the cursor is set to 0xFE, marking the end of the command list.

Because the destination is only byte-aligned, each eight-byte copy is issued as
two unaligned word stores. The loop counter, the cursor and the template all
live in the stack frame rather than in registers, and the count byte is
re-read from memory on every iteration.

## Translation-unit note

This body does not reproduce under the project's accepted ido53_o2 profile: at
-O2 the loop counter and cursor are promoted to registers and the first loop is
strength-reduced, which no source shape can undo. Recompiling the identical
source with -O1 (all other flags unchanged) reproduces the original exactly,
including the stack layout, on USA, Japan, Europe and lrg_rev1. The translation
unit that holds this routine was therefore built at a lower optimisation level
than the rest of the game; the matching configuration needs a per-unit flags
override for it.

## Status

Exact on USA, Japan, Europe and lrg_rev1, using per-unit flags that replace
-O2 with -O1.
