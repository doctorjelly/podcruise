# func_80096930

## Boundary

USA VRAM 0x80096930-0x800969FF (208 bytes, ROM 0x97530). The body opens with the
frame adjustment and ends with the return and a byte store in its delay slot.
One direct call site targets 0x80096930. The assigned boundary is correct.

## Recovered behavior

The function builds a request block: it fills the shared buffer with one
identical eight-byte record per device and terminates the buffer.

The single argument is an unsigned byte. It is remembered in the first global
byte, a cursor is aimed at the start of the shared record buffer, and the second
global word is set to one to mark the buffer as prepared.

A local template record is then assembled: its first byte is all ones, its
second byte is one, its third byte is three, its fourth byte is the argument,
and its remaining four bytes are all ones. Read as a serial request that is a
one-byte send length, a one-byte receive length, a command selector, one
argument byte and four bytes of receive space pre-filled with a fill pattern.

The function then copies that template into as many consecutive records of the
shared buffer as the device-count global says exist, advancing the cursor one
record per copy, and finally writes the terminator byte - all ones except the
lowest bit - into the first byte of the record just past the last one written.
When the count is zero or negative no records are copied and the terminator
lands at the very start of the buffer.

## Source shape notes

Like its neighbours in this region the function is built at optimization
level 1: counter, cursor and template all live in stack slots and are reloaded
per basic block, and the template's address is recomputed inside the loop. At
level 2 the same source is 184 bytes. The unit therefore carries a per-unit
flags override (-O1).

Three shape details mattered: the cursor must be declared before the template
so it takes the higher stack slot; the cursor assignment must precede the
argument store so the buffer address is materialised one instruction earlier;
and the cursor advance must sit at the end of the loop body while only the
counter advances in the loop header, which is what emits the counter store
before the cursor store.

## Status

exact - byte-identical in USA, Japan, Europe and lrg_rev1, with the per-unit
-O1 flags override recorded in the result unit objects.
