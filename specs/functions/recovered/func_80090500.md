# func_80090500

## Boundary

- USA VRAM range: 0x80090500 .. 0x8009059C inclusive (0xA0 = 160 bytes, 40 instructions).
- USA ROM offset: 0x91100.
- Terminates with a return whose delay slot is empty; the two filler words
  before it are the hazard delay required after writing the processor status
  register, so they are part of the function.
- Assigned size 160 was correct; no boundary correction.

## Callers and callees

- Thirteen direct call sites in the USA build.
- No callees (leaf function).

## Parameters

One 32-bit mask word. The function returns the previous mask, so callers use it
as a save-and-set pair around critical sections.

## Globals and access widths

- `D_800A7B50` — 32-bit word, read once. Holds the set of interrupt sources the
  system is permitted to enable; the code uses its complement, so a set bit
  means "this source is withheld".
- `D_800ADF90` — table of 16-bit entries indexed by a scaled slice of the
  requested mask; supplies the value written to the peripheral interrupt mask
  register.
- A memory-mapped hardware register at 0xA430000C, read once and written once
  (the peripheral interrupt mask register).

## Recovered behavior

Sets the interrupt mask and returns the mask that was in force.

It reads the processor status register and keeps the bits that describe the
globally enabled interrupt sources and the master enable, then folds in the
currently masked peripheral sources, in both cases screened by the permitted
set so that sources the system withholds never appear in the answer. That
composite is the value handed back to the caller.

It then applies the request: the peripheral part of the requested mask is
looked up in the table and written to the peripheral interrupt mask register,
and the processor part of the requested mask, again screened by the permitted
set, replaces the corresponding field of the processor status register. Two
filler words follow the status write to cover the pipeline hazard.

## Status

Skipped. The function reads and writes the processor status register directly;
those moves have no expression in plain C and the brief forbids inline
assembly, so no source file was produced. Behavior above is recorded for
documentation; the function should stay in hand-written assembly.
