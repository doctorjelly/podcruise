# func_800819A4

## Boundary

- USA VRAM `0x800819A4` .. `0x80081A28` inclusive, ROM `0x825A4`, size 136 bytes
  (34 instructions).
- Terminates with `jr $ra` whose delay slot performs the final store into the
  third argument, so the store is part of the function.
- The preceding label ends with its own return before `0x800819A4`, and every
  observed call site reaches the entry with a direct `jal`, so the assigned
  boundary is correct. No correction needed.

## Callers

Three direct call sites in the USA build (`0x8000192C`, `0x80008DB4`,
`0x80082074`). Two of them pass a stack buffer as the third argument, one passes
a pointer held in a saved register.

## Callees

None. The body is straight-line floating point work with no calls and no frame.

## Globals

None. The function touches only memory reached through its three pointer
arguments.

## Interface

Three pointers to 32-bit floating point data:

1. a four-component record: three components plus a fourth scalar at offset 12;
2. a three-component record;
3. a three-component destination record, written and then read back.

Nothing is returned.

## Recovered behavior

The routine takes an oriented plane, expressed as a three-component direction
followed by a scalar, and a three-component position, and writes the position
displaced along the plane direction so that it satisfies the plane equation.

It first forms the sum of the three products of matching components of the
position and the plane direction. Subtracting that sum from the plane's scalar
gives a signed displacement. Each component of the destination is then set to
the corresponding plane-direction component scaled by that displacement, and in
a second pass each destination component is increased by the matching component
of the position.

The original code performs the second pass by reading each destination
component back out of memory rather than reusing the value it had just stored;
the recovered source reproduces that as two separate statement groups over the
destination.

The Japanese, European and lrg_rev1 bodies were read independently and are word
for word the same as the USA body; the function references no relocated symbol,
so only the entry symbol needed remapping.

## Status

Exact in all four versions. Two source-shape experiments were needed: the order
of the operands of the three component products, and naming the accumulated sum
as its own local, which is what lets the load of the plane's scalar be scheduled
between the second and third multiply instead of after them.
