# func_8003E54C

## Boundary

- USA VRAM `0x8003E54C`..`0x8003E59B` (80 bytes, 20 instructions), ROM `0x3F14C`.
- Ends with the return instruction followed by an empty delay slot.
- The assignment boundary was correct: no branch leaves the range, the single
  internal label is the early-out target inside the body, and every direct
  caller targets `0x8003E54C`.

## Callers and callees

- 10 direct call sites in the USA build, all inside the same overlay region
  around `0x800551C4`..`0x80055668`. Each site passes a small literal selector
  in the first slot and two values produced by float-to-integer truncation in
  the second and third slots.
- No callees; leaf function.

## Globals and access widths

| Symbol | Access | Meaning |
| --- | --- | --- |
| `D_800A4984` | 32-bit read then 32-bit write | number of records currently queued |
| `D_80118958` | two 16-bit writes at +0 and +2 of a 4-byte record | per-record pair of coordinates |
| `D_80118C50` | 8-bit write | per-record selector byte |

`D_80118958` is addressed with a 4-byte stride (index scaled by four), so it is
an array of two 16-bit values per record. `D_80118C50` is a parallel byte array
addressed by the same index.

## Recovered behavior

The routine appends one record to a fixed-capacity queue.

It reads the current record count. If the count is 190 or more the queue is
full and the routine does nothing at all. Otherwise it writes the second and
third arguments into the two 16-bit slots of the record at that index,
truncating each argument to 16 bits, writes the first argument into the
parallel byte array at the same index (the parameter is a byte-wide selector,
so only its low eight bits are meaningful), and then stores the incremented
count back so the next call appends to the following slot.

Nothing is returned and no other state is touched.

## Argument types

The first parameter is byte-wide; the compiler masks it to eight bits before
the byte store and spills the incoming word to the caller-provided home slot,
which is the signature of a narrow parameter rather than an explicit mask in
the source. The second and third parameters are full 32-bit integers that are
narrowed only by the 16-bit stores, which is why no sign-extension appears.

## Status

Exact. Byte-identical in USA, Japan, Europe and lrg_rev1.
