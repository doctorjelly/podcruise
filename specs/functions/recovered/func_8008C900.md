# func_8008C900

## Boundary

- Assigned boundary was WRONG. Corrected USA range is `0x8008C900` ..
  `0x8008C927` (40 bytes, 10 instructions), ROM `0x8D500`; the assignment gave
  24 bytes.
- The conditional branch at `0x8008C908` jumps past the function's own `jr $ra`
  into the heuristic label `func_8008C918`, which has zero direct callers and is
  reached only by that branch. `func_8008C918` is therefore the second arm of
  this function, not a function of its own. Two alignment padding words follow at
  `0x8008C928`.
- The corrected body ends with `jr $ra` and an empty delay slot.

## Callers

Two direct call sites in the USA build, at 0x80087E20 and 0x80087E44, both
inside the same caller and both feeding the result straight into the same
follow-up call as its first argument. Callees: none.

## Globals and access widths

- `D_800A7B80` - read once as a 32-bit word, used only as a zero / non-zero test.
- `D_800A7B88` - read once as a 32-bit word, only on the non-zero path; this is
  the global the assigned inventory attributed to `func_8008C918`.

Every regional body was read independently: all four have the identical
ten-instruction shape with the same split into a zero-returning arm and a
global-returning arm, differing only in the addresses of the two globals.

## Recovered behavior

Takes no arguments and returns a 32-bit value. It reads the first global, a
flag-like word. When that word is zero the routine reports zero. When it is
non-zero the routine instead reports the contents of the second global, a word
stored eight bytes further on. Nothing is written and no other state is touched;
this is a guarded accessor that hands out a cached value only once the guard has
been armed, and yields zero (a null-like answer) beforehand. Both call sites
treat the answer as a handle passed on to another routine, which is consistent
with the zero result meaning "not available".

## Status

Behavior recovered, and byte-identical - but only at `-O1`.

The recovered C is byte-for-byte identical to the original in all four builds
under IDO 5.3 with `-G 0 -O1 -mips2 -non_shared -Xcpluscomm -signed
-Wab,-r4300_mul`. Under the accepted `-O2` profile the size is right (40 bytes)
and every instruction is the same, but the code generator speculatively hoists
the second global's address computation out of the conditional arm into the
delay-slot region ahead of the branch, so the first difference lands at offset
0x8. Five source shapes were tried at `-O2` (both branch polarities, a
conditional expression, a single-exit local, and an explicit else); all five
produce the same hoist, and the IDO 7.1 profile does too. The hoist is an
optimisation-level property, not a source-shape property: this translation unit
was built at `-O1`.
