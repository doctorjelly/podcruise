# func_8008D450

## Boundary

- USA VRAM range: 0x8008D450 .. 0x8008D504 inclusive (0xB8 = 184 bytes, 46 instructions).
- USA ROM offset: 0x8E050.
- Terminates with a return whose delay slot is empty; the word before the
  return restores the processor register the entry sequence saved, so it is
  part of the function.
- Assigned size 184 was correct; no boundary correction.

## Callers and callees

- One direct call site in the USA build, at 0x800883C4, on the path taken when
  a supplied address is not inside the directly mapped window. The caller
  passes one address and uses the returned word as a translated address.
- No callees (leaf function).

## Globals and access widths

None in ordinary memory. The function works entirely through processor control
registers.

## Regional addresses

The body is bit-for-bit identical in all four images.

## Recovered behavior

Translates one virtual address to a physical address using the processor's
address translation table, and reports failure as all ones.

It saves the current translation-lookup key register, installs the supplied
address's page number into it while preserving the current address-space
identifier, and asks the hardware to search the translation table. If the
search reports no matching entry the function answers negative one. Otherwise
it reads the matching entry back, derives the page mask, chooses the even or
odd half of the entry according to the address bit the mask selects, and checks
the chosen half's valid flag. An invalid half again answers negative one. A
valid half is expanded into a physical page base and combined with the offset
of the supplied address within the page to give the physical address. The saved
lookup key register is restored before returning on every path.

## Status

Skipped. The body consists almost entirely of processor control register moves
and two address-translation instructions (a table probe and a table read).
Those have no expression in plain C, and the brief forbids inline assembly, so
no source file was produced. Behavior above is recorded for documentation; the
function should stay in hand-written assembly.
