# func_800521C0

## Boundary
USA VRAM 0x800521C0..0x80052207 inclusive (72 bytes, 18 instructions), ROM
0x52DC0. The body closes with the return jump followed by an empty delay slot,
and both direct call sites target 0x800521C0, so the assigned boundary is
correct. Nothing executes before the frame adjustment.

## Callers
Two distinct call sites (each appearing in three overlapping generated listings
for the same code): one near 0x800522B8 and one inside the loop at 0x80054690.
Both pass a single pointer and immediately consume the single-precision result,
comparing it against a converted integer field.

## Callees

single-precision result returned directly. That callee also returns a
single-precision value derived from the same object, so the two share a return
type.

## Globals and access widths

## Object layout used
The argument points at a record in which offset 0x08 holds a 32-bit flag word
(only bit 1, mask 0x2, is examined) and offset 0x74 holds a single-precision
float.

## Regional addresses
* JP 0x80052E30 (ROM 0x53A30); helper at 0x80052DA4, global at 0x800B0090.
* EU 0x80056E70 (ROM 0x57A70); helper at 0x80056DE4, global at 0x800B5A9C.
* lrg_rev1 shares the USA addresses.
All three regional bodies were read and are instruction-for-instruction the
same shape as the USA body, differing only in the relocated addresses.

## Recovered behavior
Given one record, the routine reports a remaining-distance style float. When
bit 0x2 of the record's flag word at offset 0x08 is clear it delegates entirely
to the helper `func_80052134` and hands back whatever that helper produces.
When the bit is set it instead subtracts the record's float at offset 0x74 from
the global reference float `D_800ACE38` and returns that difference. There are
no side effects.
