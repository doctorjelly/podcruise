# func_8008A420

## Verified boundary and references

The USA body spans VRAM `0x8008A420` through `0x8008A5F7`, ROM `0x8B020`,
and is 472 bytes. It returns at `0x8008A5F0`; restoring the 368-byte frame at
`0x8008A5F4` is the executed delay slot. `func_8008A5F8` begins next.

No direct USA `jal` targets the entry, so it is reached indirectly. Its direct
callees are `func_8008A5F8`, `func_80091354`, `func_80091FD0`,
`func_80092050`, `func_800926A0`, `func_80092850`, and `func_800928F0`. It
addresses no global data directly. The normalized regional equivalents begin
at `0x8008B110` in Japan and `0x8008F970` in Europe; LRG retains the USA
address and bytes.

## Behavior

Reject an empty insertion request, then ask the storage helpers to prepare and
locate its encoded entry. Follow the entry's link chain, refreshing both link
views on each step, until a free terminator is reached or a helper reports an
error. Reject chains that run beyond the object's current limit; otherwise
mark the entry and write it back, preserving the helpers' result codes.

The C explicitly snapshots the current link limit before the first iteration
and refreshes it after each completed traversal. That retains changes made by
the called helpers while giving IDO the original back-edge scheduling.
