# func_8008F980

## Boundary

- USA VRAM `0x8008F980` through `0x8008FA57`, ROM `0x90580`, 216 bytes.
- The return is at `0x8008FA50`; its stack-restoring delay slot at
  `0x8008FA54` belongs to the function.
- Two zero words at `0x8008FA58` and `0x8008FA5C` are alignment padding. The
  next function begins at `0x8008FA60`.

## References

`func_8008D5A8` installs this address as the entry callback for handler kind
six. There are no direct calls because the shared handler subsystem invokes it
through that stored pointer. The function calls only the callback stored at
offset `0x04` of each entry. It reads the handler count at `0x14` and its entry
pointer array at `0x1C`; it touches no globals.

## Behavior

The fifth argument is an output-word cursor. The function writes two command
pairs: constants `0x020006C0` and `0x02000800`, each followed by twice the
third argument. It then walks the handler's entry array. Every entry receives
itself, arguments two through four, and the current output cursor. The cursor
returned by one callback becomes the input cursor for the next. The final
cursor is returned; an empty handler therefore returns the position directly
after the four header words.

## Access widths

All handler fields, entry pointers, callback pointers, command words, and the
returned cursor are accessed as 32-bit words. The loop counter and handler
count are signed words.

## Status

Behavior recovered, not byte-matching. IDO 5.3 emits 220 bytes for this source
against the 216-byte USA body and first differs at byte `0x04`: it keeps the
fifth argument in a saved register, whereas the original uses a temporary for
the header and a different saved register for the advancing cursor. No exact
claim is made.
