# func_8003F64C

## Boundary

- USA VRAM range `0x8003F64C` .. `0x8003F713` inclusive, 200 bytes (0xC8).
- Ends with a return instruction whose delay slot restores the stack pointer
  (frame size 0x30), so the final word belongs to this function.
- Both direct call sites target `0x8003F64C`; nothing branches into the middle
  of the body from the preceding function. The assigned boundary is correct.

## Callers

- One caller in the USA build (the disassembly reader reports the same site in
  two overlapping section views). It calls with no arguments set up and does not
  consume the result, so the function is `void func_8003F64C(void)`.

## Callees

- `func_80008F28` — no arguments, result unused.
- One indirect call through a function pointer read from the group record at
  offset 0x20. It is invoked with a single pointer argument.

## Globals and access widths

- `D_800A2170` — a 32-bit word holding a pointer to a null-terminated array of
  group-record pointers. Read once, as a full word.

## Record layout used

Group record (only the touched fields are known):

| offset | width | meaning |
| ------ | ----- | ------- |
| 0x08   | s32   | number of items to visit |
| 0x0C   | s32   | byte distance between consecutive items |
| 0x10   | ptr   | pointer to the first item |
| 0x20   | ptr   | visit callback, or null to skip the group |

Item record:

| offset | width | meaning |
| ------ | ----- | ------- |
| 0x06   | s16   | flag bits; bits 0x1000 and 0x0100 suppress the visit |

## Recovered behaviour

The routine walks a global, null-terminated table of group records. For each
group it fetches the group's visit callback; a group whose callback is null is
skipped entirely.

For a group with a callback, the routine steps over the group's items. It starts
at the group's first item and advances by the group's own byte stride after each
item, so the item records need not be contiguous. The item counter is kept as a
signed 16-bit value that wraps at 16 bits, and the loop continues while that
counter is below the group's current item count; the count is re-read from the
group after every callback, so a callback that shortens the list stops the walk
early.

An item is visited only when neither of the two flag bits 0x1000 and 0x0100 is
set in its 16-bit flag field; otherwise it is stepped over untouched. The
callback receives the item pointer as its only argument.

Once a group's items have been walked, the routine calls `func_80008F28` before
moving on to the next group. That call is made once per group with a callback,
not once per item.

## Status

Byte-exact against the USA ROM, and against the Japan, Europe and lrg_rev1 ROMs
after remapping the moved symbols. No per-unit compiler flags were needed; the
accepted `ido53_o2` profile reproduces the body.
