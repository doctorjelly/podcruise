# func_80033C70 — install the first menu page's descriptor and layout constants

## Boundary

- USA VRAM range 0x80033C70 .. 0x80033D2F inclusive, 192 bytes (0xC0).
- Preceded by two alignment no-ops after the previous function's return, so the
  entry is a real function start; ends with the return jump whose delay slot
  performs the last of the layout stores.
- Boundary as assigned is correct; no correction needed.

## Callers

One call site (VRAM 0x80033CC8 in the USA build, reached from the module split
at ROM 0x18B28). The caller tests bit 0x1000 of a global flag word and calls
this function only when that bit is set; the sibling function func_80033D30 is
called immediately afterwards under bit 0x800.

## Callees

None. The function is a leaf and takes no arguments.

## Globals and access widths

- `D_800A31E0` — a large table written as 32-bit words at byte offsets 0x1A4,
  0x1A8, 0x1AC, 0x1B4, 0x1B8 and 0x1D0. Three of those receive small integer
  identifiers and two receive the addresses of other globals.
- `D_800A5CA0` — a large table written as 32-bit floats at byte offsets 0x36C,
  0x384, 0x388, 0x38C, 0x390, 0x394, 0x398, 0x39C, 0x3A0, 0x3A4.
- `D_800AA640`, `D_800AA648` — only their addresses are taken; the contents are
  never touched here.
- `D_800AAA90`, `D_800AAA94`, `D_800AAA98`, `D_800AAA9C`, `D_800AAAA0`,
  `D_800AAAA4`, `D_800AAAA8`, `D_800AAAAC`, `D_800AAAB0` — each read once as a
  32-bit float.

The European build has no corresponding function of this shape. Its nearest
equivalent begins at VRAM 0x80037230 and is 332 bytes: it writes the same three
identifiers to the same offsets but then reads a language-selection word and
picks one of three alternative payload addresses for each of the two pointer
slots, and it stores its floats into individually named globals instead of one
based table. That is a genuinely different function, so europe is excluded.

## Recovered behaviour

The function performs a fixed, unconditional initialisation of one entry in a
descriptor table and of a block of layout parameters that belong with it.

Into the descriptor table it writes three consecutive small identifiers — 0x11B,
0x11A and 0x11E — followed, one slot further on, by the addresses of two static
payload objects, and finally a fourth identifier 0x120 at a slot well past the
others. The two identifiers written first are adjacent and descending, which
together with the pointer pair reads as "title id, subtitle id, body id, body
data, extra data" for a single page of a fixed screen.

Into the layout table it copies ten single-precision values. Nine of them come
from named float globals that hold the tuned coordinates or sizes for this page;
the tenth slot is set to exactly zero rather than copied. The destination
offsets are not contiguous: one value goes to a slot roughly 0x18 words before
the rest, and the remaining nine occupy two runs (four slots, then five) with a
small gap. The write order in the compiled code places the zero before its
neighbouring copy purely because the zero constant is materialised early; the
observable result is order-independent because every destination is distinct.

Nothing is read back and nothing is returned; the function exists only to stamp
a compile-time constant configuration into two shared tables.

## Status

Exact. Byte-identical in usa, japan and lrg_rev1. Europe deliberately excluded
(structurally different function).
