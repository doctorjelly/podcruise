# USA formatter translation unit

The conversion helper `func_80092B10` consumes a format conversion and aligned
argument cursor, preparing the field text and its padding counts. Its caller
`func_80093180` scans literal text and conversions, parses flags, width,
precision and qualifiers, invokes the helper, and emits text and padding through
the supplied callback while counting emitted characters.

| Function | ROM start | VRAM start | Bytes |
| --- | --- | --- | ---: |
| `func_80092B10` | `0x93710` | `0x80092B10` | 1648 |
| `func_80093180` | `0x93D80` | `0x80093180` | 1608 |

Both bodies were already exact individually, but the driver needed its helper
compiled in the same unit for IDO's interprocedural register allocation. Its
private helper copy differed from the independently recovered exact helper.
The combined wrapper includes the exact helper followed by the existing driver,
without duplicating the helper or retaining the standalone synthetic call context.
The original standalone source paths remain available with the wrapper macro unset.

IDO 5.3 with `-G 0 -O3 -mips2 -non_shared -Xcpluscomm -signed
-Wab,-r4300_mul` reproduces both bodies exactly. The pool begins at `0x800AE030`;
a four-byte unused data prefix preserves the switch-table offset without
emitting an extra function. The remaining 220 compiled pool bytes independently
compare equal to the canonical USA ROM. Only matched text is packed for the
hybrid build; the original pool data remains in the ROM data segment.

The USA split selects one C object at ROM `0x93710`, packing the contiguous
3,256-byte span, and resumes assembly at `0x943C8` for eight padding bytes.
The linker map places `unit_80092B10.o` at `0x80092B10` with size `0xCB8`.
The full rebuild matches canonical SHA1
`3542d5597c8a56ea8f5c63bceae97a24c4c08d58` with 1,181 C substitutions.
This adds one substitution; exact coverage remains 1,181 functions and 361,112
bytes because both functions were already counted as exact.
