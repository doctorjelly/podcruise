# func_8008C2F0

## Boundary

- USA VRAM `0x8008C2F0` .. `0x8008C31B` (44 bytes, 11 instructions), ROM `0x8CEF0`.
- Terminates with `jr $ra` and a register-move delay slot that restores the
  first argument as the return value.
- The label is a genuine entry: nine direct `jal` sites target it, the preceding
  function ends with its own return four bytes earlier, and no branch from the
  preceding function reaches into it. Boundary as assigned is correct.

## Callers

0x80097000, 0x80097030, 0x8009709C, 0x8009711C, 0x80097224, 0x80097568 and one
more in the same group). Callees: none. Globals touched: none.

## Recovered behavior

A byte-granular block copy. Three arguments: a destination address, a source
address, and an unsigned element count expressed in bytes. When the count is
zero the routine does nothing. Otherwise it walks forward through both blocks
one byte at a time, reading an unsigned byte from the source and storing it at
the matching offset of the destination, until the count is exhausted. The
destination address that was passed in is handed back to the caller unchanged,
which makes the routine usable as an expression. Both walking cursors are
private copies; the caller's argument registers are not consumed, which is why
the returned pointer is the original one and not the advanced one. The copy is
strictly ascending, so overlapping blocks are only safe when the destination
starts at or below the source.

## Access widths

Source is read with an unsigned byte load and the destination is written with a
byte store, so the element type is an unsigned 8-bit quantity, not a signed
char. The count is a full 32-bit value decremented by one per byte.

## Status

Behavior recovered, and byte-identical - but only when loop unrolling is off.

The recovered C is byte-for-byte identical to the original in all four builds
under IDO 5.3 with `-G 0 -O2 -mips2 -non_shared -Xcpluscomm -signed
-Wab,-r4300_mul -Wo,-loopunroll,0`. Under the currently accepted profile
(the same flags without `-Wo,-loopunroll,0`) IDO unrolls the copy loop by four
with a remainder prologue and emits 116 bytes instead of 44; the first
difference is at offset 0x7.

Eight source shapes were tried against the accepted profile. Every shape whose
exit test reads the decremented counter directly (`while (n != 0) {...; n--;}`,
`do {...} while (--n != 0);`, `for (i = 0; i < n; i++)`) is unrolled. The shapes
that defeat the unroller (`while (n-- != 0)`, `while (n-- > 0)`) materialise the
pre-decrement test into a separate boolean register and produce 56 bytes with a
first difference at offset 0x1. There is therefore no accepted-profile source
shape for this body: the original translation unit was built with unrolling
disabled.
