# func_80016D78

## Boundary

- USA VRAM range 0x80016D78 - 0x80016D9F (inclusive), size 40 bytes, ROM 0x17978.
- Body ends with the return instruction plus a filled delay slot; the delay
  slot performs the last of the four stores, so the return is not a bare
  two-instruction stub.
- The preceding function (func_80016CAC) completes its own frame teardown and
  returns immediately before this label, and no branch inside it reaches past
  its own return into this entry, so 0x80016D78 is a genuine entry point.
- No stack frame is created; the routine uses only the caller-provided argument
  home area.
- Boundary as assigned is correct.

## Callers

Six direct call sites in the USA build. Sampled sites pass a pointer formed as
`base + constant` into an object being filled in (for example base+0xB4 and
base+0xC4 of the same record), followed immediately by four freshly computed
floating point values, one of which is placed in the fifth-argument stack slot
by the caller. Callers frequently pass the same value for several of the four
components.

## Callees

None. This is a leaf routine.

## Globals

None referenced. The routine touches only the memory the caller points at.

## Recovered behavior

The routine writes a four-component single-precision vector. Argument one is
the destination address; arguments two through five are the four component
values, in order. Component one is stored at offset 0, component two at offset
4, component three at offset 8 and component four at offset 12. Nothing is read
from the destination first, no bounds or null checking is performed, and no
value is returned. The fourth and fifth components arrive in places that force
the routine to spill and reload them before storing, which is a calling
convention artefact and not observable behavior.

## Argument evidence

Argument one is an address (used only as a base for stores). Arguments two,
three and four arrive in the integer argument registers and are moved into
floating point registers before being stored as 32-bit floats, which by this
project's established convention means they are `f32` parameters in positions
two through four. Argument five is read as a 32-bit float directly out of the
fifth argument stack slot.
