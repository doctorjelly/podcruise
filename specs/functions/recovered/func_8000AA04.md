# func_8000AA04

## Boundary

- **Boundary corrected.** The assignment gave 80 bytes
  (`0x8000AA04` .. `0x8000AA53`). That is wrong: the sole conditional branch in
  the first block jumps *past* the block's own return, to `0x8000AA54`, which
  the disassembler had promoted to a separate label `func_8000AA54`. Per the
  boundary rules, a label that is only an internal branch target of the
  preceding block is not a function entry.
- Corroboration: `0x8000AA54` has **zero** direct call sites in the whole USA
  text, while `0x8000AA04` has 219.
- Corrected USA VRAM range: `0x8000AA04` .. `0x8000AA77` inclusive
  (116 bytes / 29 words). USA ROM offset `0xB604`.
- The body has two exits. The first is a return at `0x8000AA4C` whose delay slot
  performs the second floating point store. The second is the return at
  `0x8000AA70` with an empty delay slot, ending the function.
- The next function begins at `0x8000AA78` and is entered by a call, so the
  corrected end is confirmed.

## Callers / callees

- Callers: 219 direct call sites (all to `0x8000AA04`).
- Callees: none. This is a leaf.

## Globals and access widths

- `D_8009B784` — 32-bit float, written once.
- `D_8009B788` — 32-bit float, written once.
- `D_800D2190` — base of the same array of 32-byte records used by the rest of
  this group. Two 16-bit fields at record offsets `0x00` and `0x02` are written.

## Recovered behaviour

A position setter for the record table, with one reserved index that redirects
to a pair of global floats instead.

Parameters: a 16-bit signed record index and two 16-bit signed coordinates.

1. If the index is exactly -201, the two coordinates are converted from integers
   to single-precision floating point and stored in the two globals
   `D_8009B784` and `D_8009B788`. This is a sentinel selector: -201 is one below
   the negated table capacity of 200 used by `func_8000A44C`, and the two globals
   act as the "screen" or "global" position that stands in for a record.
2. Otherwise, if the index is negative the routine does nothing.
3. Otherwise the two coordinates are stored, still as 16-bit integers, into the
   first two fields of the selected record.

Note the asymmetry that identifies the sentinel path as deliberate: the global
destination is floating point while the per-record destination is a pair of
16-bit integers, so the same call site can address either with the same
arguments.

The routine returns nothing.

## Status

Exact at the corrected 116-byte boundary. USA, Japan, Europe and `lrg_rev1` all
verified byte-identical.
