# func_80088110

## Boundary

- VRAM 0x80088110 .. 0x80088144 (exclusive), ROM 0x88D10, size 52 bytes.
- Leaf, no frame. The return instruction's delay slot carries the store of the
  cursor field.
- A padding word precedes it after func_800880E0 and another follows.
- Only one direct call site; it targets 0x80088110. The unconditional branch
  inside the body targets 0x80088130, which is inside the routine, so the
  interior labels are not function boundaries. Boundary confirmed.

## Callers and callees

- One direct call site. Leaf.
- Three arguments: the region record to initialise, a raw start address and a
  byte capacity.

## Globals and access widths

- None.
- Region fields written, all 32-bit: aligned base at 0x00, cursor at 0x04,
  capacity at 0x08, and a zeroed field at 0x0C.

## Recovered behavior

Prepares a bump-allocation region over a caller-supplied block of memory, and
is the companion of func_80087FC0, which consumes exactly these fields.

1. The number of bytes needed to reach the next sixteen-byte boundary is
   computed as sixteen minus the low four bits of the start address.
2. If that padding is a full sixteen, the start address was already aligned and
   is stored as the region base unchanged; otherwise the padded address is
   stored. The test is written against the padding, not against the low bits,
   which is why the constant sixteen is held in a register and compared with
   the subtraction result.
3. The cursor is set to the region base by reading the field back out of the
   record rather than reusing the value just stored.
4. The caller's capacity is stored at 0x08 and the field at 0x0C is cleared.

Note that the capacity is stored as given, measured from the unaligned start
address, so the alignment padding is taken out of the usable space rather than
added to it.

## Status

Exact in usa, japan, europe and lrg_rev1. Matched on the first attempt.
