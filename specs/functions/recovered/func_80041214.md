# func_80041214

## Boundary

USA VRAM 0x80041214..0x80041258 (68 bytes), ROM 0x41E14. The body ends with the
return instruction and an empty delay slot. Six direct call sites target
0x80041214 exactly. Boundary as assigned is correct.

Note for the record: the word at 0x80041244 is unreachable at run time. It is
the untaken copy of the store that the compiler hoisted into a branch-likely
delay slot at 0x80041230 — exactly the "stranded copy" pattern the project brief
describes — and it is genuinely emitted, so it counts toward the 68 bytes.

## Callers

Six sites, all inside the same subsystem: 0x80041A08 (an early-out path of
func_800419EC) and 0x80041C0C, plus their duplicates in the mirrored overlay
segments. Every site passes a single pointer argument.

## Callees

`func_8004110C`, a two-argument routine: it snapshots a long run of float fields
of the same record into a shadow area and, at its own tail, writes its second
argument into the record's word at offset 0x7C. Other call sites of
`func_8004110C` pass a literal 1 as that second argument, which confirms the
arity.

## Globals and access widths

None. The function only touches the record it is handed.

## Record fields used

* offset 0x7C — 32-bit word, written.
* offset 0x80 — 32-bit word, read.

All three regional bodies were read independently and are instruction-for-
instruction the same shape, differing only in the call target.

## Recovered behavior

Applies a pending mode change to a record. The routine reads the record's
requested mode word. If the request is one of the two "active" modes (the value
two or the value one) it delegates to the heavyweight transition routine,
passing the record and the requested mode along, so that routine can copy the
record's live float state into its shadow copy and commit the mode itself. For
any other requested value the transition is not needed and the routine simply
commits the mode directly by copying the request word into the record's current
mode word. Nothing is returned.

The two accepted values are tested in the order "two first, then one", which is
what produces the observed comparison order.

## Status

Exact in USA, Japan, Europe and lrg_rev1 with the accepted ido53_o2 profile; no
per-unit flags needed.
