# func_80086178

## Boundary

- USA VRAM range: 0x80086178 .. 0x800862D4 inclusive (0x160 = 352 bytes, 88 instructions).
- USA ROM offset: 0x86D78.
- Ends with a return whose delay slot performs the last store; no frame
  adjustment at all, so the routine is a pure leaf.
- Three direct call sites, all targeting 0x80086178. The two visible callers
  fill the four 32-bit fields at 0x20..0x2C immediately before the call, which
  confirms both the entry point and the argument layout. Assigned size 352 was
  correct; no boundary correction.

## Callers and callees

- Three direct callers. One pointer argument, no result.
- Leaf function; no callees.

## Globals and access widths

- `D_80114470` — a pair of signed 16-bit values read at offsets 0 and 2; the
  base address is materialised once and both are read through it. They are the
  current display width and height.
- `D_8009B7E8` — one 32-bit word, read once and tested against zero.
- `D_800D5710` — one 32-bit word, read twice through a materialised base
  address, once per flag bit tested.

Structure reached through the argument:

- 0x10, 0x12, 0x14 — signed 16-bit scale terms.
- 0x18, 0x1A, 0x1C — signed 16-bit offset terms.
- 0x20, 0x24, 0x28, 0x2C — signed 32-bit bounds, written by the caller.
- 0x16 and 0x1E are never touched.

## Recovered behavior

Turns a rectangle held in the object into the scale and offset terms a viewport
needs, rescaling for the current display size.

The two display dimensions are divided, in double precision, by the nominal
320 by 240 to give a horizontal and a vertical scale factor. Each of the four
rectangle bounds is converted to single precision, multiplied by the scale
factor for its axis, and truncated back to an integer. From the scaled left and
right edges the routine writes twice the width plus eight into the first scale
term and twice the sum of the edges into the first offset term; the scaled top
and bottom edges give the second scale and offset terms the same way.

If the global flag word is non-zero those four values are overridden with a
full-screen configuration: the two scale terms become fixed constants, and each
offset term becomes either its fixed constant or zero depending on one bit of
the mask word — bit 0 for the horizontal offset, bit 1 for the vertical.

Two further constants — a depth scale and a depth offset — are stored
unconditionally at the end, whichever path was taken.

Source-shape notes established by matching:

- The two scale factors have to be locals whose initialisers are interleaved
  with the first two edge computations, in declaration order: horizontal scale,
  left edge, vertical scale, top edge, right edge, bottom edge. Computing both
  scales up front costs four bytes because the second display read is scheduled
  too early; repeating the division expression at each use gets the schedule
  right but reverses the operand order of every multiply.
- The four stores must be written scale, scale, offset, offset. Writing them in
  the pairwise order scale/offset, scale/offset produces the same instructions
  with two temporaries interchanged.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
