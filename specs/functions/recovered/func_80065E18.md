# func_80065E18

## Boundary

USA VRAM 0x80065E18 - 0x80065E53 inclusive (60 bytes, 15 instructions), ROM
0x66A18. The final store is the delay-slot instruction of the return, so the
body ends cleanly on the return pair. The single direct caller jumps to
0x80065E18, and nothing branches into the middle of the range from the
preceding function. Boundary as assigned is correct.

## Callers

One direct call site, inside the routine at 0x8006B620, which passes the base
of the object it is iterating over as the only argument.

## Callees

None. This is a leaf.

## Globals and access widths

- `D_800A3080` - a single 32-bit float, read once.
- `D_800A3084` - three consecutive 32-bit floats, read in ascending order
  through a single materialised base address.

Both are read-only here.

## Parameters and return

One argument: a pointer to a large object. No return value.

All three regional bodies were read independently and are instruction-for-
instruction the same shape as USA, differing only in the two global addresses.

## Recovered behavior

The routine copies a four-component floating point setting out of module-level
storage into a fixed block near the end of the caller's object, at byte offsets
0x190 through 0x19C.

The first component is not copied verbatim: the scalar at `D_800A3080` is
scaled by one quarter before being stored at offset 0x190. The remaining three
components are copied unchanged from the three-float group at `D_800A3084`
into offsets 0x194, 0x198 and 0x19C, in that order.

The quarter factor is a single-precision literal, not a promoted double, and
the three-float group is addressed as one array rather than as three unrelated
scalars - the original computes the group's base address once and reads the
three members from it.

## Status

Exact on USA, Japan, Europe and lrg_rev1.
