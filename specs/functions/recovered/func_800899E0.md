## Recovered behavior

The function translates a table of eight-byte source records into a table of
four-byte destination records and reports, as a bit set, which entries it
accepted.

Arguments are a pointer to a single status byte and a pointer to the first
destination record.

It clears the status accumulator, points a cursor at the first entry of the
global source table, and iterates once for every entry the global count says is
present (nothing happens at all when the count is zero).

Each pass copies the whole eight-byte source record into a local scratch record
and then derives a two-bit code from the third byte of that scratch copy: the
top two bits are isolated and shifted down by four, so the code lands in the
value range 0, 4, 8 or 12. That code is written into the fourth byte of the
current destination record and then read back out of memory.

When the code reads back as zero the entry is accepted: the fifth and sixth
scratch bytes are combined little-endian into the destination's leading
half-word, the seventh scratch byte is copied into the destination's third
byte, and the bit whose position equals the loop index is set in the status
accumulator. When the code is non-zero only that code byte has been written and
the rest of the destination record is left alone.

The destination pointer advances one four-byte record per pass regardless of
acceptance, and the count is re-read from the global on every pass, so a change
made to the count while the loop runs is honoured. After the loop the
accumulated status byte is stored through the first argument.

## Source shape notes

The whole function keeps its counter, its cursor and its status byte in stack
slots and reloads them per basic block, and re-reads the code byte it has just
stored. That is optimization level 1, not level 2; at level 2 the same source
compiles to 172 bytes with everything in registers. The unit therefore carries
a per-unit flags override (-O1), the same override other workers established
for neighbouring functions in this region.

Two further shape details mattered. Stack slots are handed out in descending
address order following declaration order, so the cursor has to be declared
before the scratch record to land above it. And the two stores that close the
loop come out in the reverse of source order, so the counter and cursor
increments have to be written counter-first to be emitted cursor-first.

## Status

exact - byte-identical in USA, Japan, Europe and lrg_rev1, with the per-unit
