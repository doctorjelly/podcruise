# func_8002A7D4 — matching blocker

- USA ROM `0x2B3D4..0x2B96F` is one 1,436-byte function. The disassembler's
  `func_8002A7E4` label is an interior split: the 16-byte prefix establishes
  floating-point values consumed by the following body.
- The reviewed C candidate has the correct linked symbol size and address,
  but differs from the USA ROM in 10 instruction words, first at byte `0x13`.
- Narrowing scalar locals and removing temporaries changed the stack frame
  and worsened the comparison; those variants were discarded. The remaining
  issue is local/frame layout. Keep the USA split as assembly.

## Bounded declaration-order audit

All ten current differences are stack immediates: ROM frame `0xA8` versus C
`0xC0`, with both text-buffer pointers in C exactly `+0x18` above the ROM.
Moving `text[48]` and `line[32]` together after all six scalar declarations
puts both buffers at their canonical stack offsets and reduces the mismatch
to only two words: prologue `addiu sp,sp,-0xC0` versus `-0xA8` at `+0x10`, and
epilogue `addiu sp,sp,0xC0` versus `0xA8` at `+0x598`. The body is otherwise
byte-identical and still 1,436 bytes.

Moving the arrays after only `base` did not improve the ten-word baseline.
With both arrays after all scalars, marking scalars `register`, using a K&R
parameter declaration, and grouping the array declarations on one source
line all left the same two-word frame mismatch. The variant was not retained;
the parent independently restored and reran the ten-word baseline. Future
work needs evidence for why IDO reserves an unused extra 24 bytes in that
otherwise exact frame, not more local-order permutations.
