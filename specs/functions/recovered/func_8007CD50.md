# `func_8007CD50`

## Verified facts

The canonical USA function occupies VRAM `0x8007CD50` through `0x8007D30F`,
ROM `0x07D950` through `0x07DF0F`, for 1,472 bytes. Its return is at
`0x8007D308`; the delay slot at `0x8007D30C` is a `nop`. The next established
entry begins immediately at `0x8007D310`.

Japan has a same-size structural equivalent at VRAM `0x8007D9F0`, ROM
`0x07E5F0`, and Europe at VRAM `0x80082230`, ROM `0x082E30`. Their returns and
delay slots have the same relative offsets. The USA LRG revision retains the
USA address and bytes.

## Behavioral specification

Clear the object's value at offset `0x14`, then dispatch on the signed type code
stored in its subordinate record. Individual cases either delegate the whole
operation, toggle state bits, mark the subordinate record, adjust attached
nodes, perform a random two-way choice, reset timers, issue an auxiliary action,
or construct a short tagged three-word request. Unrecognized codes leave the
initial cleared value as the only change. The third argument is preserved by
the calling convention but does not affect any case.

Describing this as an event/effect dispatcher is an inference from the broad
type-code switch and its heterogeneous side effects. The cases, values, object
offsets, and helper calls are directly recovered facts; address-based names are
retained because the wider subsystem semantics are not established.
