# func_8008AB84 — 64-bit left shift helper

## Boundary
- USA VRAM `0x8008AB84`..`0x8008ABAF` (44 bytes), ROM `0x8B784`.
- Ends with `jr $ra` whose delay slot holds the final arithmetic that produces
  the upper half of the result, so the return sequence is the last two words of
  the body and the boundary is confirmed.
- The single direct `jal` in the ROM targets `0x8008AB84`, and no branch from
  the preceding function (`func_8008AB48`, which ends at `0x8008AB83`) reaches
  into this range. Assigned boundary correct.

## Callers / callees
- One direct call site, inside `func_800811DC` (at `0x80081234`).
- No callees; leaf function, no stack frame is allocated (only the four
  caller-provided argument home slots are used).

## Globals
- None.

## Regional addresses
- Japan `0x8008B874` / ROM `0x08C474`.
- Europe `0x800900D4` / ROM `0x090CD4`.
- lrg_rev1 shares the USA address `0x8008AB84` / ROM `0x8B784`.
- All three regional bodies were read independently and are word-for-word
  identical to the USA body; no symbol referenced by this function moves.

## Recovered behavior
Takes two 64-bit signed integers. The first is the value, the second is the
shift distance. Returns the value shifted left by that distance, as a 64-bit
signed integer.

Both arguments arrive split across the two halves of the O32 argument area, so
the first thing the routine does is spill all four argument words into the
caller-provided home slots and re-read each pair as one doubleword; the result
is split back into an upper and a lower half for return. This is the standard
compiler support routine for `<<` on `long long` when the caller is compiled
for a 32-bit ISA, so all of that plumbing is generated, not written.

## Build note
This body uses true 64-bit register operations, which IDO 5.3 will not emit
under the project's usual `-mips2` profile — under `-mips2` the same source
compiles to an out-of-line call to the shift helper (i.e. to this very
function). Compiling the unit with `-mips3 -o32` instead of `-mips2`, with all
other flags unchanged, reproduces the original bytes exactly. This mirrors the
way the N64 SDK builds its own 64-bit support file.

## Status
Exact in USA, Japan, Europe and lrg_rev1.
