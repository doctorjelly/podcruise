# func_80051FF4

## Boundary — corrected

- Assigned size was 28 bytes (0x80051FF4 .. 0x8005200C). That is wrong: the
  first conditional branch jumps forward to 0x80052010, which the label scan
  treated as a separate function.
- True USA VRAM range: 0x80051FF4 .. 0x8005205C inclusive (0x6C = 108 bytes,
  27 instructions), ending with a return whose delay slot is empty.
- USA ROM offset: 0x52BF4.
- The four heuristic labels inside the range (0x80052010, 0x80052028,
  0x80052040, 0x80052058) have zero direct callers; every direct call in the
  build targets 0x80051FF4. The last of them is the shared exit that the final
  conditional branch reaches, and the value returned there is set up before
  the branch, which is what makes the tail part of this function.

## Callers and callees

- Widely used: twenty-five distinct direct call sites in the USA build.
- Takes no arguments and returns a small integer.
- No callees (leaf function).

## Globals and access widths

Four consecutive 32-bit slots, each read as a full word and tested against
zero. They hold object pointers: the neighbouring routine compares a pointer
argument against the same four slots, and another nearby routine dereferences
the first slot at offset 0x84.

- `D_8011B1BC`, `D_8011B1C0`, `D_8011B1C4`, `D_8011B1C8`.

## Recovered behavior

Counts how many of the four registration slots are occupied, assuming they
fill in order. The slots are examined from the first to the fourth; the result
is the position of the first empty one, so an empty first slot yields zero and
four occupied slots yield four. Callers use it as the current participant
count.

## Recovery notes

The four slots must be written as four separate named objects rather than as
one four-element array: an array makes the compiler form the base address once
and index it, whereas the original recomputes a split high/low address for
every slot, which is what separate objects produce.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
