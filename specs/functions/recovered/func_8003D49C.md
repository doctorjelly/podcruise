# func_8003D49C

## Boundary

- USA VRAM range `0x8003D49C`..`0x8003D4F3` (inclusive), ROM `0x3E09C`, size 88
  bytes. Matches the assignment.
- The body ends with a return whose delay slot holds the second of the two
  floating-point stores.

## Callers

One direct call site in the USA build.

## Callees

None. Leaf function.

## Globals and access widths

- `D_80114470` — a pair of 16-bit signed values read at offsets 0x00 and 0x02.
  The same block is read by the screen-setup code elsewhere and holds a pixel
  width and height.

## Arguments

Two pointers to 32-bit floating point outputs.

## Recovered behavior

The function converts the current render-target size into normalised scale
factors relative to the machine's nominal 320x240 display.

The stored width is divided by 320 and the stored height by 240. Both divisions
are performed in double precision — the 16-bit integers are widened to double,
divided by double constants, and only the quotients are narrowed to single
precision — so the result is correctly rounded rather than accumulating single
precision error. The horizontal factor is written through the first pointer and
the vertical factor through the second. Nothing is returned.

The double-precision arithmetic is not a stylistic choice recovered from the
instruction stream: it is what plain C produces when a 16-bit integer is divided
by an unsuffixed floating constant and the quotient is assigned to a single
precision variable.
