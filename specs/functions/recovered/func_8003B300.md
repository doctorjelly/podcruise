# func_8003B300

## Boundary

- USA VRAM range `0x8003B300`..`0x8003B323` (inclusive), ROM `0x3BF00`, size 36
  bytes. Matches the assignment.
- The body is a straight run of four stores; the last store occupies the delay
  slot of the return.

## Callers

One direct call site in the USA build.

## Callees

None. Leaf function.

## Globals and access widths

Four adjacent 32-bit variables written as full words:

| symbol | receives |
| --- | --- |
| `D_80114540` | argument 2 |
| `D_80114544` | argument 4 |
| `D_80114548` | argument 1 |
| `D_8011454C` | argument 3 |

They are only ever written here in the USA build; other code reads the region
through a pointer rather than by name.

## Recovered behavior

The function records a four-value clipping/viewport rectangle in a small block of
static state. The four arguments are stored so that arguments one and three land
in the second pair of words and arguments two and four land in the first pair,
i.e. the arguments arrive interleaved with respect to the storage layout. The
function performs no validation, clamping or ordering and returns nothing.

The store order the original compiler produced (first word, third word, second
word, fourth word of the block) follows directly from writing the four
assignments in the source order "argument 1, argument 3, argument 2, argument 4".
