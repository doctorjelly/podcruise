# func_80063E08

## Boundary

USA VRAM 0x80063E08..0x80063E4C (68 bytes), ROM 0x64A08. The body ends with the
return instruction and an empty delay slot. Both direct call sites (0x80063E9C
and 0x80063EAC, inside the same dispatcher) target 0x80063E08. Boundary as
assigned is correct.

## Callers

Two sites in one small dispatcher that selects between behaviours by a code in
a local; one passes the selector value one, the other passes two. Both forward
the record pointer they were given.

## Callees

`func_80015288`, the already-recovered three-component vector copy
(`output = source`).

## Globals and access widths

* `D_800A5100` — a table of three-float records; the second argument indexes it
  with a twelve-byte stride, which is exactly one three-component vector per
  entry. Read only, as a whole vector.

## Record fields used

* offset 0x50 — three consecutive floats, written (the copy destination).
* offset 0xA0 — 32-bit word, cleared to zero.

## Regional addresses

| Europe | 0x800692E8 | 0x69EE8 | 0x800AA400 | 0x80015718 |
| lrg_rev1 | 0x80063E08 | 0x64A08 | identical to USA | identical to USA |

The Japanese and European bodies were read independently; both keep the same
shift/subtract/shift index scaling and the same field offsets, differing only in
the two relocated symbols.

## Recovered behavior

Loads a preset orientation (or position) into a record and clears its progress
counter. The routine picks the entry of the shared preset table selected by the
index it is handed, copies that three-component vector into the record's vector
field at offset 0x50, and then zeroes the record's word at offset 0xA0. The
record pointer has to survive the copy call, so it is the only value spilled.
Nothing is returned.

## Status

Exact in USA, Japan, Europe and lrg_rev1 with the accepted ido53_o2 profile; no
per-unit flags needed.
