# func_80087FC0

## Boundary

- VRAM 0x80087FC0 .. 0x80088014 (exclusive), ROM 0x88BC0, size 84 bytes.
- The body is a leaf with no frame adjustment; it ends with the return
  instruction whose delay slot moves the result variable into the return
  register.
- Two padding words separate it from the preceding routine (func_80087E80)
  and three padding words separate it from the next (func_80088020), so the
  assigned boundary is confirmed on both sides. No branch from the preceding
  routine reaches into this label; the twenty direct call sites all target
  0x80087FC0.

## Callers and callees

- Twenty direct call sites, spread over the startup/allocation code.
- Leaf: calls nothing.
- Every observed call site passes zero in the first two argument slots, a
  region pointer in the third, a small element count in the fourth, and an
  element size in the fifth (on the stack: values 0x1C, 0x4C, 4, 1 observed).

## Globals and access widths

- None. All state is reached through the region pointer supplied by the
  caller.
- Region fields touched: a 32-bit base pointer at 0x00 (read), a 32-bit
  cursor pointer at 0x04 (read and written), and a 32-bit byte capacity at
  0x08 (read). Nothing at 0x0C is touched here.

## Arity and types

- Five arguments. The first two are never read, but the compiler still spills
  them into the caller-provided home slots at the very top of the body, which
  is the reliable signal that the arity really is five.
- The fourth and fifth arguments are combined with an unsigned multiply, so
  both are unsigned 32-bit quantities. Only the low word of the product is
  kept, so an overflowing request wraps.
- The comparison that guards the allocation is unsigned.
- The result is a pointer (null on failure).

All four bodies were read instruction by instruction and are word-identical;
the routine references no relocated symbol, so the same source verifies
against every version.

## Recovered behavior

A bump allocator that carves a block out of a caller-supplied region.

1. The requested byte count is the product of the element count and the
   element size, rounded up to the next multiple of sixteen.
2. The region's end address is its base plus its capacity. The request is
   granted only when the cursor advanced by the rounded size still lies at or
   before that end address; the comparison is unsigned.
3. When it is granted, the old cursor becomes the result and the cursor is
   advanced past the block. When it is refused nothing in the region changes.
4. The result is the old cursor on success and null on failure. The result
   variable is initialised to null before the test, so the failure path simply
   falls through.
5. The first two arguments are ignored entirely; all observed callers pass
   zero for both.

Two shapes mattered for byte equality. The advanced cursor is written twice in
the source — once as `cursor + size` inside the guard and once as
`result + size` in the assignment — which stops the compiler from sharing one
value and gives it an instruction to lift into the branch delay slot. Making
the region's base and cursor byte pointers rather than integers is what pins
the register assignment; an integer-typed version schedules the same
instructions into different registers.

## Status

Exact in usa, japan, europe and lrg_rev1.
