# func_8008126C

## Boundary
VRAM 0x8008126C-0x800812E8, ROM 0x81E6C, 124 bytes. The return's delay slot
holds the final double-precision store, so the store is part of the body.
Seven direct callers all target 0x8008126C. Boundary as assigned is correct.

## Callers / callees
Seven callers. Calls, in order: func_800811DC (no arguments, produces a 64-bit
value), func_8008AC48 and func_8008AB48 (each taking two 64-bit values and
producing one), and func_8008C738 (taking a 64-bit value, producing a
single-precision result).

## Globals and access widths
- D_80120BE0: 64-bit, written as two 32-bit halves through one computed base
  address, then read back for the first call argument.
- D_800ADC80: 32-bit float, read once.
- D_80120C08: 64-bit double, written once.

## Regional addresses
- jp 0x80081F0C (ROM 0x82B0C)
- eu 0x8008674C (ROM 0x8734C)

## Recovered behavior
Samples the system's free-running counter and records the sample in a global.
That recorded sample is then re-read and scaled twice by the 64-bit helpers:
first against the constant 0x40, then against 3000. The doubly scaled value is
converted to a single-precision quantity by a third helper, divided by a global
float scale factor, widened to double precision, and stored in a second global.
In effect the routine latches a timestamp and publishes a derived, unit-scaled
double alongside it.

## Status
behavior. The USA build is 120 of 124 bytes and differs only in how the address
of the double-precision destination is formed: the original materialises the
symbol address into a general register and stores at offset zero, while every
source shape tried folds the low half of the symbol into the store itself.
Writing the first global's assignment so that its value is re-read from the
global (rather than kept in a local) reproduced the original's base-register
form for that global exactly, which fixed the first half of the body; the same
trick has no second use to trigger it for the double. Eight shapes were tried
(local vs. re-read, array vs. scalar vs. struct-with-padding declarations,
address-of and char-pointer-offset spellings, volatile, -O1 and -O3).
