# func_80064A88

## Boundary

- USA VRAM range `0x80064A88` .. `0x80064AF3` inclusive (108 bytes, 27 words),
  USA ROM offset `0x65688`.
- Ends with `jr $ra` whose delay slot holds the float register move that
  produces the return value, so both the return and its delay slot are part of
  this body.
- Both conditional branches target labels inside the range; the second targets
  the final return. `0x80064AF4` is a separately called entry (func_80064AF4),
  so the end is confirmed from both sides.
- Eleven direct call sites all target `0x80064A88`.
- No boundary correction was required.

## Callers / callees

- Callers: 11 direct call sites. Every one of them supplies the argument as a
  float loaded straight out of a small table of constants immediately before
  the call, and several test the returned float against zero afterwards.
- Callees: none. This is a leaf.

## Globals and access widths

- `D_8011A240` — the base of a block of 32-bit floats. This function uses only
  the first element (offset `0x00`), reading and writing it as a 32-bit float.
  The original code materialises the block's base address into a register once
  and reaches the element through it, which is what an array subscript rather
  than a plain scalar produces.
- `D_80120BF8` — a single 32-bit float constant, read once. Given how it is
  used it acts as a per-frame step size.

## Recovered behavior

Advances a clamped normalised progress value and hands the caller the value it
settled on.

The caller supplies a rate. That rate is scaled by the global step size and the
product is added to the stored progress value, which is then written back. The
updated value is clamped into the closed range zero to one: if it now exceeds
one it is set to exactly one, and if it is below zero it is set to exactly
zero. The clamped value is returned.

Two details are load-bearing for reproducing the original code. First, the
comparison against one is written as a strict "greater than one" test and the
comparison against zero as a strict "less than zero" test, in that order.
Second, the stored value is re-read from memory after each write rather than
kept in a temporary, so the value returned is genuinely the value now in
memory; expressing this as repeated reads of the same subscript, not as a local
variable, is what produces the original instruction sequence.

Because both tests are strict, a value that lands exactly on a limit is left
alone, and a value that is not a number falls through both tests unchanged.

## Status

Exact. USA, Japan, Europe and lrg_rev1 all verified byte-identical.
