# func_80039A30

## Boundary

- USA VRAM range: 0x80039A30 .. 0x80039B6C inclusive (0x140 = 320 bytes, 80 instructions).
- USA ROM offset: 0x3A630.
- Ends with a return whose delay slot releases the eight-byte frame; the frame
  exists only to preserve one callee-saved register used to hold the loop limit.
- The first executed instruction is the load of the memory-size word, which sits
  before the frame adjustment; callers target that load, so it belongs to the
  function. Assigned size 320 was correct; no boundary correction.

## Callers and callees

- Two direct call sites in the USA build (the same site appears in two
  overlapping generated listings). Takes no arguments and returns nothing.
- Leaf function; no callees.

## Globals and access widths

- `D_80000318` — one 32-bit word, read only. It is the boot-time RAM size word
  the console leaves in low memory; the code compares it unsigned against
  0x800000, i.e. it distinguishes a 4 MB console from an expanded 8 MB console.
- `D_80114530` — three consecutive 32-bit words, each written twice. They are
  addresses, so an unsigned word array is the natural type.

## Recovered behavior

Carves three equally sized display buffers out of the very top of main memory
and records their addresses in the three-entry global table.

Everything is driven by whether the console has expanded memory. On an expanded
console the routine assumes a 640-pixel-wide, four-byte-per-pixel display and
reserves one extra scan line's worth of bytes as a guard band; on a stock
console it assumes 320 pixels wide, two bytes per pixel and no guard band. The
display height is fixed at 240 lines in both cases.

For each of the three buffers, counting from one, it takes the uncached address
of the end of physical memory and subtracts that many whole buffers, where one
whole buffer is the pixel area plus two guard scan lines. It stores that
address, then re-reads the slot and advances it by two guard scan lines, so the
recorded pointer names the first pixel rather than the start of the reserved
block. On a stock console the guard band is zero and the second step is a no-op
in effect but still executed.

Source-shape notes established by matching:

- Each of the four derived quantities (width, bytes per pixel, guard band, and
  the guard band again in the second statement) is written out as its own
  conditional expression rather than cached in a local; the original re-tests
  the memory size once per use, which is exactly what a macro spelled as a
  conditional expression produces.
- The condition is phrased in the "expanded console" direction, i.e. the test is
  greater-or-equal against 8 MB with the large values in the true arm. Writing
  it the other way round (less-than with the small values first) inverts the
  branch polarity of every one of the six conditional expressions and, for the
  guard band, turns a plain branch into a branch-likely plus an extra jump.
- The second statement really does re-read the table slot it has just written
  rather than reusing a local, which is the ordinary compound-assignment shape.
- The loop is an ordinary ascending count to three; the multiplier is the
  one-based buffer number, and the compiler shares the single increment between
  the multiplier and the loop variable.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
