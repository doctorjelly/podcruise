## Recovered behavior

Locates which segment of an ascending key array contains the object's current
position, and returns the index of that segment's lower key. It is the search
step that pairs with the inverse-lerp helper at 0x80005CAC: that helper is
handed exactly this index.

Three cases:

1. If the position is past the last key, the search saturates and returns the
   index of the final segment, that is two less than the entry count.
2. If the position is before the first key, it saturates the other way and
   returns zero.
3. Otherwise it starts at the final segment and walks backwards one segment at
   a time for as long as the position is still below the key at the current
   index, then returns where it stopped.

The walk is a backwards linear scan rather than a bisection, so it is cheapest
when the position is near the end of the array — consistent with a playback
cursor that usually advances only a little between queries. No bounds checking
is performed; an entry count below two would index before the array.

Source-shape note: the count, the position and the array pointer must be read
through the object expression at each use rather than copied into named locals,
or the compiler reuses the address it formed for the last-key test and folds
the segment lookup into a constant displacement off it, which the original does
not do.

## Status

Behavior recovered, not byte-exact. 97 of the 140 bytes match; the first
difference is at offset 0x61 and the compiled body is 144 bytes.

The whole divergence is one scheduling decision at the loop exit. The original
leaves the loop-guard branch in its plain form with an empty delay slot and
carries the result copy in the delay slot of the shared return. The rebuilt
form converts that guard into its branch-likely variant, duplicating the result
copy into the guard's delay slot and leaving the return's delay slot empty,
which costs one instruction. Every other instruction, register assignment and
operand order agrees.

Twenty source shapes were tried: index versus explicit pointer induction,
`while` / `for` / guarded `do`-`while`, negated and reversed comparisons,
locals versus direct object reads, declaration reordering, and single versus
duplicated exit returns. Direct object reads with an ordinary `while` loop gave
the best result and is also the clearest reading of the behavior, so that form
was kept. Two shapes (an explicit `>=` guard, and an `if`/`else` pair of
returns) reproduced the plain guard branch but regressed elsewhere to 152
bytes, which suggests the remaining gap is a delay-slot pass ordering effect
rather than a behavioral difference.
