# func_8001811C

## Boundary

- USA VRAM range 0x8001811C - 0x80018163 (inclusive), size 72 bytes, ROM 0x18D1C.
- Body ends with the return instruction plus an empty delay slot.
- The immediately preceding label, func_80018114, is an eight-byte one-line
  setter that returns before this address with its own store in the delay slot;
  it does not fall through and none of its instructions branch here. All four
  internal branches inside this body target addresses inside the body or the
  final return, so 0x8001811C is a genuine entry point.
- Direct calls in the USA build target exactly this address.
- No stack frame is created; the routine is a leaf.
- Boundary as assigned is correct.

## Callers

Seven direct call sites in the USA build. Every sampled site first obtains an
object pointer from a lookup routine, then passes that pointer, a small literal
selector (values 3 and 4 were both observed), and a 32-bit value that is either
a small negative literal or a field loaded out of a nearby structure.

## Callees

None. This is a leaf routine.

## Globals

None referenced. The routine writes only through the pointer it is given.

## Access widths

All four writes are 32-bit stores at fixed byte offsets 0x158, 0x15C, 0x160 and
0x164 from the object pointer. The selector is compared for equality against
32-bit literals.

## Recovered behavior

The routine sets one of four adjacent 32-bit fields of an object according to a
selector value. Selector 4 writes the field at offset 0x15C, selector 3 writes
the field at offset 0x164, selector 6 writes the field at offset 0x158, and
selector 5 writes the field at offset 0x160. All four selector tests are
performed unconditionally and in that order; the tests are independent rather
than mutually exclusive alternatives, but since the four constants are distinct
at most one store can occur. Any other selector value leaves the object
untouched. Nothing is read back and nothing is returned.

The mapping from selector to offset is deliberately not monotonic; the source
order 4, 3, 6, 5 is what the original build encodes and reordering it changes
the emitted code.

## Argument evidence

Argument one is an object address. Argument two is a 32-bit integer selector,
compared against literal constants. Argument three is a 32-bit value that is
stored verbatim; callers supply both a small negative constant and a value read
from another structure, so it is an ordinary 32-bit word rather than a float.

## Regional addresses

- Japan: VRAM 0x8001824C, ROM 0x18E4C, size 72. Body read independently; the
  same four comparisons against the same constants writing the same offsets in
  the same order.
- Europe: VRAM 0x800185AC, ROM 0x191AC, size 72. Body read independently;
  identical structure.
- lrg_rev1 shares the USA addresses.

## Conflict note

At the time of writing, `src/functions/func_80018114.c` (owned by another
worker) also contains a definition of `func_8001811C`. The orchestrator must
drop one of the two definitions before the host link will succeed. The two
recovered forms agree on behavior.

## Status

Exact. Byte-identical in USA, Japan, Europe and lrg_rev1 from a single source
file.
