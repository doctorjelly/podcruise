# func_80030B90

## Boundary
USA VRAM 0x80030B90-0x80030C08 (120 bytes, ROM 0x31790). Ends with a return
and an empty delay slot. One direct caller, func_80030EA8 at 0x80030EC0.
Boundary confirmed correct.

## Callers / callees
Caller: func_80030EA8. Callees: func_8002FAFC (no arguments, returns an
address), func_8002FAC4 (one address argument; its own body confirms a single
argument).

## Globals
D_80000318 read as an unsigned word; D_80114528 written twice as a word, the
second write reading the first back.

## Regional addresses
- jp 0x800315F0 (ROM 0x321F0)
- eu 0x80034150 (ROM 0x34D50)
- lrg_rev1 shares the USA addresses
Regional forms were not confirmed because USA is not yet exact.

## Behavior
Takes no arguments. It asks a helper for the current base address of a memory
region and publishes that raw address in the global slot. It then reads the
slot back, rounds the address up to the next 64-byte boundary, and stores the
rounded value over it, so the global ends up holding the aligned address while
the raw address stays in hand.

Next it inspects the system's memory-size word. Below eight megabytes it
selects a line length of 320 units; at eight megabytes or above it selects 640.

Finally it forms a second address from the raw base: it skips a 64-byte header
and then a full frame of the selected line length times 480 units, and passes
that address to the second helper.

## Status
Behavior recovered; not byte-exact. Correct length and correct instruction
sequence, differing only in register selection across seven instructions in
the memory-size comparison and the address computation. The original allocates
the loaded memory-size word and the 8 MB constant into argument registers,
which suggests the constant was a common subexpression in the original
translation unit; no source shape tried reproduced that allocation.
