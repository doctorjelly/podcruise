# func_800883F8

## Boundary

- USA VRAM range: 0x800883F8 .. 0x8008844F inclusive (0x58 = 88 bytes, 22 instructions).
- USA ROM offset: 0x88FF8.
- Terminates with a return whose delay slot copies the masked result into the
  return register.
- No frame is allocated; the routine is a leaf and keeps everything in
  registers.
- Assigned size 88 was correct; no boundary correction.

## Callers and callees

- One direct call site in the USA build, at 0x8009025C, inside the routine that
  fills in a queued audio-buffer descriptor. The caller passes a descriptor
  pointer and a count fetched from its own stack, and stores the result into
  the descriptor at offset 0x10.
- No callees (leaf function).

## Globals and access widths

- `D_800ADD80` — one 64-bit floating-point constant, read once as a double. It
  is the divisor that converts the multiplied quantity into the returned unit.
- The first argument is a pointer to a structure whose field at offset 0x44 is
  a signed 32-bit integer; only that field is touched.
- The second argument is a signed 32-bit integer: it arrives in an integer
  register and is converted to floating point by the callee, so it is a count
  and not a float.

## Recovered behavior

Converts a count of audio frames into a buffer size in bytes, rounded to a
whole number of sixteen-byte blocks.

Both the supplied count and the rate-like field at offset 0x44 of the given
descriptor are converted from integers to single precision and multiplied. That
single-precision product is widened to double precision, divided by the shared
double constant, and biased by one half so the following truncation rounds to
nearest rather than toward zero. The rounded value is narrowed back to single
precision, truncated to a signed integer, and finally cleared in its low four
bits so the returned size is a multiple of sixteen. The result is returned.

Three source-shape facts are pinned by the emitted code. The multiplication
happens in single precision before the division, so the two conversions feed a
single-precision multiply rather than a double one. The rounded quantity passes
through a single-precision variable before the integer conversion, which is
what produces the narrowing step between the addition and the truncation; a
direct double-to-integer conversion would omit it. The final rounding-down is a
bit mask against negative sixteen, not a divide-and-multiply pair, which would
have produced shift arithmetic instead.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
