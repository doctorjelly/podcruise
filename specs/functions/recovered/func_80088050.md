# func_80088050

## Boundary

- VRAM 0x80088050 .. 0x80088074 (exclusive), ROM 0x88C50, size 36 bytes.
- Leaf, no frame. The return instruction's delay slot carries the final store,
  so the last write really is part of this routine.
- func_80088020 ends immediately before and a distinct routine begins at
  0x80088074. Fifteen direct call sites all target 0x80088050. Boundary
  confirmed.

## Callers and callees

- Fifteen direct call sites. Leaf.
- Two arguments, both pointers to the same two-word chain record type: the
  record being inserted and the record it is inserted in front of.

## Globals and access widths

- None. Only chain records, all 32-bit accesses.
- Record layout: backward pointer at 0x00, forward pointer at 0x04.

## Regional/compiler note

The routine is the mirror image of func_80088020 and shares its record layout.

## Recovered behavior

Splices a record into a doubly linked chain immediately before an anchor
record.

1. The new record inherits the anchor's backward pointer and its forward
   pointer is set to the anchor.
2. If the anchor had a predecessor, that predecessor's forward pointer is
   redirected to the new record.
3. The anchor's backward pointer is finally set to the new record.

The anchor's backward pointer is read again for step two rather than reusing
the value captured in step one; that re-read is visible in the original and
must be written as a fresh field reference, not a local.

## Source-shape note

The two field writes in step one must be written backward pointer first,
forward pointer second. The compiler then swaps the two stores while
scheduling, producing the observed order and leaving one instruction between
the load and its use. Writing them in the observed order instead produces a
correctly sized but differently ordered body, and introducing a local for the
inherited pointer changes which registers are used.

## Status

Exact in usa, japan, europe and lrg_rev1.
