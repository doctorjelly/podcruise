# func_80093CD0 — invalidate an instruction-cache range

## Boundary

- USA VRAM `0x80093CD0` .. `0x80093D1F`; ROM `0x948D0`; size 80 bytes
  (20 instructions).
- Ends with `jr $ra` plus a `nop` delay slot at `0x80093D18`; the single direct
  caller targets `0x80093CD0`. **No boundary correction needed**, but see the
  note below.
- **Shared-tail note:** the third instruction pair branches *out of this body*
  to `func_80093D20`, the next function, rather than to a local label. The two
  are a hand-written pair — a bounded range walk and a whole-cache sweep — that
  share a return. This is exactly the kind of cross-label control flow that
  cannot survive being modelled as an independent C function.

## Callers

One direct call site, in `func_8008B580` (USA `main_8BDB0.s`), immediately after
a small structure copy. It passes base address `0x80000000` and length `0x190`,
i.e. it invalidates the freshly written low-memory exception vectors.

## Callees

None by `jal`. It transfers to `func_80093D20` by an ordinary branch when the
requested length reaches the whole-cache threshold.

## Globals and access widths

None. The function performs no data loads or stores; it issues cache-maintenance
operations against addresses derived from its two arguments.

## Regional addresses

| version    | VRAM         | ROM        | size |
|------------|--------------|------------|------|
| us         | `0x80093CD0` | `0x948D0`  | 80   |

| lrg_rev1   | `0x80093CD0` | `0x948D0`  | 80   |

All regional bodies are identical in shape, each branching to its own
version's neighbouring whole-cache routine.

## Recovered behavior

Discards any stale instruction-cache copies of a region of memory, so that code
just written through the data path will actually be executed rather than served
from the instruction cache.

It takes a start address and a byte length. A length that is zero or negative
is ignored and the routine returns at once. A length that reaches or exceeds
the full instruction-cache size (16 KiB) is not worth walking line by line, so
control is handed to the neighbouring routine that sweeps the entire cache. A
pointer range that wraps around the top of the address space is likewise
rejected.

Otherwise the start address is rounded down to the 32-byte cache-line boundary
that contains it, and the end address is stepped back by one line so the walk's
comparison covers the final line. Every 32-byte line from that rounded start up
to and including the line holding the last requested byte is then invalidated,
one line per pass.

## Status

**skipped** — not recoverable as C. The loop body is a cache-maintenance
instruction, which has no C expression, and the routine additionally branches
into a separate function, so it is not a self-contained compilation unit even
in principle. Inline assembly is forbidden by the project rules; this should be
carried as a handwritten assembly unit together with `func_80093D20`.
