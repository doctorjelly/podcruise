# func_800979F0

## Boundary

USA VRAM 0x800979F0..0x80097B7F (400 bytes, ROM 0x985F0). The body ends with the
return whose delay slot clears the result register. The function is a leaf: it
reserves a 0x10-byte frame for one spilled local and never saves a return
address. Four direct call sites target 0x800979F0. The instruction before the
label belongs to the previous function's epilogue, and the first instruction of
this function is a hardware-register load that the scheduler placed ahead of the
frame adjustment - callers still enter at 0x800979F0, so the assigned boundary
is correct.

## Callers

Four direct call sites, all in the cartridge/peripheral access layer near
0x80094918. They pass a device handle taken from a driver structure, a constant
device offset (0x05000510 in every observed site), and a data word.

## Callees

None.

## Globals and access widths

- `D_800A7BA0` - a two-entry array of pointers to device handles, indexed by the
  handle's channel byte. Read twice and written once per call, all 32-bit.
- The peripheral control block at physical 0xA4600010 onward is addressed as
  absolute constants, not as relocated symbols: the status word at 0xA4600010 is
  read repeatedly (32-bit), and the eight timing registers at 0xA4600014,
  0xA4600018, 0xA460001C, 0xA4600020 (channel 0) and 0xA4600024, 0xA4600028,
  0xA460002C, 0xA4600030 (channel 1) are written as 32-bit words from byte-wide
  handle fields.
- The final data store goes to the address formed by combining the handle's base
  address with the caller's offset and the uncached-segment constant 0xA0000000,
  which the assembler expands into a high-half load plus a bitwise or.

Handle layout used: link pointer at 0x00, kind byte at 0x04, latency at 0x05,
page size at 0x06, release duration at 0x07, pulse width at 0x08, channel at
0x09, base address (32-bit) at 0x0C.

address and the function's own address move.

## Recovered behaviour

Write one word to a device register on the parallel peripheral bus.

First wait until the bus reports that no transfer is in progress, by re-reading
the status word until its two low busy bits are clear.

Then, if the handle being used is not already the one the bus is programmed for
on this handle's channel, reprogram the four bus timing registers of that
channel - latency, page size, release duration and pulse width - but only for
those parameters whose value actually differs from the currently programmed
handle's, so an unchanged parameter costs no register write. Channel zero uses
the first bank of timing registers and any other channel uses the second bank.
Afterwards record this handle as the one now programmed for the channel.

Finally combine the handle's base address with the requested offset, force the
result into the uncached address window, store the caller's data word there, and
report success by returning zero.

## Status

Byte-identical to the original in all four builds, but only when the unit is
built at optimisation level one rather than the project default of two. The
proof used the accepted flag list with `-O2` replaced by `-O1`:
`-G 0 -O1 -mips2 -non_shared -Xcpluscomm -signed -Wab,-r4300_mul`.
At `-O2` the compiler fills branch delay slots, converts the comparisons to the
branch-likely forms and keeps the cached handle in a register; the original does
none of that, spilling the cached handle to the frame and re-reading it before
every comparison, which is the level-one shape. Two locals are declared with the
register storage class so that the polled status word and the cached channel
number stay in registers, which is what the original body does at that level.
