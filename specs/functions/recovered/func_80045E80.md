# func_80045E80

## Boundary

VRAM 0x80045E80 .. 0x80045F60 (exclusive), ROM 0x46A80, size 224 bytes (56
instructions). The body ends with the return jump and a stack-frame release in
its delay slot; the single direct call site targets 0x80045E80, and the
preceding function (func_80045DA0) returns before this label rather than
branching into it.

## Callers

One direct call site, at 0x800461C4, immediately after the call to
func_80045DA0 and with the same pointer argument. The result is not consumed.

## Callees

- `func_80018324(pointer, s32 kind)`, the same initialiser used by
  func_80045DA0, with a word-sized second argument.

## Globals

None; everything is reached through the pointer argument.

## Owner object fields used

- 0x0BB8 — pointer slot that receives the address of the header record.
- 0x104C — array of eighteen pointers (72 bytes).
- 0x1094 — eighteen records of 0x58 bytes, addressed as six rows of three.
- 0x16C4 — the header record, which lies inside the address range covered by
  the eighteen-record table. The two views therefore overlap, and the recovered
  source expresses that overlap as a union rather than pretending the region
  holds two disjoint members.

Within a record only the 32-bit count at 0x14 and the pointer at 0x18 are
written.

As with func_80045DA0 the regional entries are absent from the project's
cross-version table and were located by searching for the loop bounds, then
confirmed by reading the whole body at each candidate address.

## Recovered behavior

The same construction as func_80045DA0 but for an eighteen-entry collection.

The header record is initialised with one kind code, told that it owns eighteen
elements, pointed at the base of the pointer array, and published into the
owner's pointer slot.

Then, for six groups of three, each of the eighteen records is initialised with
a second kind code, has its count and pointer fields cleared, and has its
address written into the matching pointer-array entry. The records are indexed
as a two-dimensional table (six rows of three) and the pointer array with a
flattened row-times-three-plus-column index; that asymmetry is what produces
the separate stride and count registers seen in the original.

## Status

Exact in USA, Japan, Europe and lrg_rev1 under the standard IDO 5.3 -O2
profile. No per-unit compiler flags required.
