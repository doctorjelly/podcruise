# func_80006DE8

## Boundary

- VRAM 0x80006DE8 .. 0x80006E50 (exclusive), ROM 0x79E8, size 104 bytes.
- The body ends with the return instruction; its delay slot stores the third
  of the three float results.
- Assigned size 104 is correct. The internal label at 0x80006E04 is the
  one-instruction stall loop described below, not a function entry.

## Callers and callees

- One direct caller. No calls out (leaf).

## Globals and access widths

- None. Everything is reached through the pointer argument.

| offset | width | access |
| --- | --- | --- |
| 0x0F0 | 32-bit float | write |
| 0x0F4 | 32-bit float | write |
| 0x0F8 | 32-bit float | write |

## Arguments

Three: a record pointer, then two `f32` values. Because the first argument is
a pointer, both floats arrive in integer registers and are moved into the
floating-point file on entry, which is the normal calling-convention effect
and not a source-level cast.

The four bodies are word-for-word identical; there are no relocated symbols.

## Recovered behavior

Installs a validated animation range on a record.

1. If the upper bound is strictly less than the lower bound the routine hangs
   in an empty infinite loop. This is a hard consistency trap: the caller is
   expected never to invert the range, and no diagnostic text survives in the
   retail build.
2. Each bound is independently clamped up to zero, so a negative lower or
   upper bound becomes zero.
3. The clamped lower bound is written to offset 0x0F0, the clamped upper bound
   to 0x0F4, and their difference (upper minus lower) to 0x0F8.

Note that the clamps are applied after the ordering trap, so a range such as
(-5, -1) passes the trap and collapses to (0, 0) with a zero span.

## Status

Exact. Byte-identical in USA, Japan, Europe and lrg_rev1.
