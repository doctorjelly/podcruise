# func_80014C98 — append a pipeline-synchronisation command to the display list

## Boundary

- USA VRAM range: `0x80014C98` .. `0x80014CB8` inclusive, 36 bytes (9 instructions).
- ROM offset `0x15898`.
- Ends with a return whose delay slot holds the final word store into the
  reserved display-list slot, so the last observable write happens as the
  function returns.
- Confirmed as a real entry: both direct call sites target `0x80014C98`, the
  preceding function ends with its own return plus delay slot at `0x80014C94`,
  and no branch inside that function reaches past its return. The assigned
  boundary is correct.

## Callers and callees

- 2 direct call sites (both in the same display-list build routine, which
  immediately afterwards clears a global word).
- No callees; leaf function, no stack frame, no arguments, no return value.

## Globals and access widths

- `D_801217B0` — a 32-bit global holding the "next free display-list slot"
  pointer. Read once as a word and written back once as a word through an
  address materialised into a register and reused for both accesses.
- The reserved slot itself is written as two 32-bit words at offsets 0 and 4.

## Regional addresses

- Europe: `0x80015128`, ROM `0x015D28`, same 36 bytes; the global moves to
  `D_8012A450` (`0x8012A450`). Body confirmed instruction-for-instruction
  against the European disassembly.
- No Japanese address was supplied for this function in the assignment.

## Recovered behaviour

The routine reserves the next eight-byte entry of the current display list and
fills it with a fixed graphics-pipeline command.

It reads the global "next free entry" pointer, advances that global by one
eight-byte entry (post-increment: the old value is the entry that gets used),
then writes zero into the entry's second word and the constant `0xE7000000`
into its first word. The constant is the RDP pipeline-synchronisation opcode in
the high byte with an all-zero argument. Nothing is returned.

The post-increment shape matters for a byte match: writing the same behaviour
with an explicit "copy, then add one" pair of statements produces the same nine
instructions but a different temporary-register assignment.

## Status

Exact. USA verified byte-identical at the canonical address; Europe verified
byte-identical at its canonical address with the global remapped.
