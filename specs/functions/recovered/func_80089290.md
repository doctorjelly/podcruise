# func_80089290

## Boundary

USA VRAM 0x80089290 - 0x8008937B inclusive, ROM 0x89E90, 236 bytes (59
instructions). The return instruction sits at 0x80089374 with an empty delay
slot at 0x80089378. Two direct callers target 0x80089290. Every branch inside
the range lands inside the range. Boundary as assigned: correct.

## Callers and callees

Two direct callers; leaf function, no return value.

## Arguments

Four. The first is a pointer to a table header. The second is a signed byte
displacement applied to most stored pointers. The third is never read: its
register is dead on entry and is reused as scratch, which is what fixes the
arity at four rather than three. The fourth is a second, independent byte
displacement used for exactly one field.

## Globals and access widths

None; everything is reached through the header pointer.

Header layout:
* 0x03 unsigned byte "already relocated" flag;
* 0x0E signed 16-bit entry count;
* 0x10 onwards an inline array of 32-bit entry pointers.

Entry layout:
* 0x00, 0x04, 0x08 stored pointers (the one at 0x08 designates a surface
  record);
* 0x0E unsigned byte "already relocated" flag.

Surface layout:
* 0x00 stored pointer, relocated by the fourth argument;
* 0x08 unsigned byte kind selector;
* 0x09 unsigned byte "already relocated" flag;
* 0x0C stored pointer, relocated only when non-zero;
* 0x10 stored pointer.

## Regional addresses

* Japan: VRAM 0x80089F80, ROM 0x8AB80.
* Europe: VRAM 0x8008E7E0, ROM 0x8F3E0.
* lrg_rev1: shares the USA address.

Not probed regionally because the USA form is not byte-exact yet.

## Recovered behavior

This is a one-shot pointer-relocation pass over a loaded geometry table.

If the header's flag byte is already set the routine returns immediately;
otherwise it sets the flag and processes the header's entry array. For each of
the first N entries, where N is the header's signed 16-bit count and a count of
zero or less means no work at all:

* the stored entry pointer is biased by the first displacement and written back;
* if that entry's own flag byte is already set, the entry is skipped;
* otherwise the entry's flag is set and its three stored pointers at offsets
  0x00, 0x04 and 0x08 are each biased by the first displacement and written
  back. The relocated pointer from offset 0x08 designates a surface record;
* if the surface's flag byte is already set, the entry is finished;
* otherwise the surface's flag is set and its stored pointer at offset 0x00 is
  biased by the fourth argument's displacement rather than the first;
* then, on the surface's kind selector: kind 0 biases the pointer at offset
  0x10 unconditionally and the pointer at offset 0x0C only when it is non-zero;
  kind 1 biases only the pointer at offset 0x0C, and only when it is non-zero;
  any other kind touches neither.

The header count is re-read from memory on every iteration, so an entry that
rewrites it changes the number of remaining passes.

## Status

Behavior recovered; not byte-exact.

At the accepted ido53_o2 profile the recovered source compiles to 248 bytes
against the original's 236. Compiling the same source at -O3 produces exactly
236 bytes and an instruction-for-instruction correspondence except for two
register-allocation artefacts: the original keeps the fourth argument in its
incoming register and parks the surface pointer in a scratch register, whereas
the rebuild does the reverse and therefore also emits a home-slot store for the
unused third argument. Roughly twenty source shapes were tried (parameter vs
local cursors, local vs repeated array expressions, declaration order, block
scope, continue vs nested conditionals, switch vs if-chain, unsigned and
pointer and 64-bit spellings of the displacement arguments, an old-style
parameter list, and word-array rather than pointer-array entries); none moved
the residual difference. The remaining gap is purely which register holds the
surface pointer, not behavior.
