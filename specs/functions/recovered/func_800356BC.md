## Arguments

Three word-sized arguments. The second is never read. The compiler still
stores it into its caller-provided home slot at the very top of the body; this
is what IDO 5.3 at -O2 does with an unused register argument, and it is not a
local variable. That single store is the whole reason this function appears to
touch the stack despite having no frame.

## Recovered behavior

This is a small state machine that edits a pair of drawing-mode words in
response to a named feature being switched on or off. The first argument is a
four-character tag identifying the feature, the third argument says what to do,
and the pair `D_800A3DA0` / `D_800A3DA4` holds the current mode.

Three tags are recognised, and nothing at all happens for any other tag.

**Tag one** (the characters `ZBZB`). If the third argument is exactly one the
feature is being enabled:

- if the current mode word is the first well-known constant, replace the pair
  with the second constant pair;
- otherwise, if it is the third well-known constant, replace the pair with the
  fourth constant pair;
- otherwise leave the pair unchanged.

If the third argument is anything other than one the feature is being disabled
and the two substitutions run in reverse, mapping the second constant back to
the first and the fourth back to the third.

**Tag two** (the characters `AAEN`). Same shape, but a different pairing: when
enabling, the first constant becomes the third and the second becomes the
fourth; when disabling, the third becomes the first and the fourth becomes the
second.

**Tag three** (the characters `Full`). The third argument is not a flag here; it
is written verbatim into both mode words, overwriting whatever state the two
tag-driven machines had left behind.

The whole routine is a chain of equality tests: every comparison is against an
exact constant, so an unrecognised tag, an unrecognised current mode, or an
enable value other than one all fall through with no effect. Nothing is
returned.
