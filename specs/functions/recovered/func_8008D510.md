# func_8008D510

## Boundary

USA VRAM 0x8008D510..0x8008D554 (68 bytes), ROM 0x8E110. The body ends with the
return instruction and an empty delay slot. The single direct call site,
0x80088854, targets 0x8008D510, and the immediately following function
0x8008D554 is a sibling with the same shape. Boundary as assigned is correct.

## Callers

One site, 0x80088854, which passes the object just produced by an allocation
call as the only argument.

## Callees

`func_80095AA0`, the already-recovered four-argument handler-slot initialiser:
it clears the slot's first word, stores its second and third arguments as two
callback pointers, clears two adjacent halfwords, and stores its fourth
argument as a tag.

## Globals and access widths

None. Two function addresses are taken: `func_8008FA94` (a display-list
emitter that dispatches through a table entry) and `func_8008FA60` (a small
message handler that recognises the codes one and six). Neither is called here,
only referenced.

## Record fields used

* offsets 0x00..0x13 — written indirectly, by the initialiser callee.
* offset 0x14 — 32-bit word, cleared to zero.
* offset 0x18 — 32-bit word, set to one.

## Recovered behavior

Constructs one particular kind of interface element on top of a freshly
allocated object. The routine installs the element's two behaviour callbacks —
the drawing routine and the message handler — together with the type tag three,
by handing them to the shared slot initialiser. It then finishes the object's
own two extra fields that the shared initialiser does not know about: the word
at offset 0x14 is cleared and the word at offset 0x18 is set to one, giving the
element a zeroed state value and an enabled/visible flag. The object pointer has
to survive the initialiser call, so it is the only value spilled. Nothing is
returned.

## Status

Exact in USA, Japan, Europe and lrg_rev1 with the accepted ido53_o2 profile; no
per-unit flags needed.
