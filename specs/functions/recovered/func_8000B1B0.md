# func_8000B1B0

## Boundary correction

The assigned boundary (88 bytes, `0x8000B1B0` .. `0x8000B207`) is **wrong**.

The heuristic labelling splits this routine in two at `0x8000B208`, but:

- the conditional branch at `0x8000B1F8` jumps *past* the return at
  `0x8000B200`/`0x8000B204` and lands on `0x8000B208`, i.e. the routine branches
  over its own early return into the supposed second function;
- the inventory records zero direct calls to `0x8000B208` and one incoming
  cross-branch, which is exactly that branch;
- `0x8000B208` has no prologue and its code consumes a constant that was set up
  in the delay slot back at `0x8000B1FC`, so it cannot be entered independently.

The real routine therefore runs `0x8000B1B0` .. `0x8000B253`, ROM `0xBDB0` ..
`0xBE53`, size **164 bytes** — the assigned 88 bytes plus the 76 bytes wrongly
labelled `func_8000B208`. The corrected size is what verifies byte-identical.

## Boundary

- USA VRAM range `0x8000B1B0` .. `0x8000B253`, ROM `0xBDB0` .. `0xBE53`, 164
  bytes.
- Two return points: an early return at `0x8000B200` whose delay slot at
  `0x8000B204` performs the selector store, and the final return at
  `0x8000B24C` whose delay slot at `0x8000B250` is empty.
- Nothing branches into the entry from the preceding routine, and every call
  site targets `0x8000B1B0`.

## Callers

Two distinct direct call sites: `0x8000B944` and `0x80031300` (a third recorded
entry is the second address repeated in an overlapping generated section file).

## Callees

None; leaf routine, no stack frame. It writes the incoming selector to the
caller-provided argument home slot but never reads it back.

## Globals and access widths

- `D_8009B790` — 32-bit pointer slot, base of the array of 124-byte records.
- `D_8009B794` — 32-bit pointer slot, receives the address of the newly selected
  record.
- `D_8009B798` — 32-bit signed record selector; `-1` means "nothing selected".
- `D_8009B79C` — 32-bit word, cleared to zero when a record is selected.
- Record field touched: the 32-bit flag word at record offset `0x00`; bit 0 is
  cleared on the outgoing record and set on the incoming one.

The routine multiplies the selector by the 124-byte record stride at run time
rather than folding it into a shift sequence, because the stride constant is
shared by all three index computations in the routine.

## Recovered behaviour

This is a "make this record the current one" routine driven by a signed 16-bit
selector, where `-1` is the sentinel for "none".

1. If a record is currently selected (the stored selector is not the sentinel),
   the routine clears bit 0 of that record's flag word, deselecting it.
2. The stored selector is replaced by the incoming selector.
3. If the incoming selector is the sentinel, the routine stops there: nothing is
   selected and the cached record pointer and auxiliary word are left untouched.
4. Otherwise the routine caches the address of the newly selected record in the
   pointer global, sets bit 0 of that record's flag word, and clears the
   auxiliary word to zero.

Step 4 re-reads the stored selector rather than reusing the incoming argument,
so the record whose flag bit is set is by definition the one just recorded.

Nothing is returned and the selector is not range checked; only the sentinel is
treated specially.

## Status

Exact at the corrected 164-byte boundary. USA, Japan, Europe and lrg_rev1 all
verify byte-identical from `src/functions/func_8000B1B0.c`. The orchestrator
should retire the spurious `func_8000B208` label, which this unit now covers.
