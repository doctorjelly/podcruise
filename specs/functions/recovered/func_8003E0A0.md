# func_8003E0A0

## Boundary

USA VRAM 0x8003E0A0 - 0x8003E18B inclusive, ROM 0x3ECA0, 236 bytes (59
instructions). The return instruction is at 0x8003E184 with an empty delay
slot at 0x8003E188. Eleven direct callers target 0x8003E0A0. The two argument
transfer instructions at the very top are the function's own prologue, not a
stray tail of the previous body. Boundary as assigned: correct.

## Callers and callees

Eleven direct call sites; the routine is a leaf and returns nothing.

## Arguments

Three: a pointer, then two single-precision values. The two floating-point
arguments arrive in integer registers because the first argument is a pointer,
and the body moves them into the floating-point unit immediately, which fixes
their width at 32 bits.

## Globals and access widths

None. All state is reached through the argument pointer and through one further
pointer stored inside the referenced object at byte offset 0x8.

Object layout used (relative to the argument pointer):
* 0x00 word flag field, read and written as 32 bits;
* 0x04 signed 16-bit coordinate;
* 0x06 signed 16-bit coordinate;
* 0x08 pointer to a limits record.

Limits record layout:
* 0x04 signed 16-bit span;
* 0x06 signed 16-bit span.

## Regional addresses

* Japan: VRAM 0x8003EA20, ROM 0x3F620.
* Europe: VRAM 0x800429E0, ROM 0x435E0.
* lrg_rev1: shares the USA address 0x8003E0A0 / ROM 0x3ECA0.

All three regional bodies were disassembled independently; their 59 instruction
words are byte-identical to the USA body.

## Recovered behavior

If the argument pointer is null the routine does nothing. Otherwise it sets bit
15 of the object's leading flag word, then fetches the limits record pointer at
offset 0x8; if that pointer is null it stops there, leaving the flag set.

With a limits record present it advances two scrolling coordinates, each of
which is a signed 16-bit value that must stay inside the half-open range
[0, span) for its axis:

* The first coordinate is replaced by the truncated-toward-zero integer value
  of its own current value plus the first floating-point argument multiplied by
  the axis span. If the result now exceeds the span it has the span subtracted
  once; if it is then negative it has the span added once.
* The second coordinate is treated identically using the second floating-point
  argument and the second axis span.

Each coordinate is written back to the object before the wrap tests read it
again, so the tests operate on the stored 16-bit value rather than on a wider
intermediate.

## Status

Exact on USA, Japan, Europe and lrg_rev1 with the accepted ido53_o2 profile.
