# func_800704A8 (USA)

## Facts

- Address: `0x800704A8`; ROM offset `0x710A8`; verified span is 700 bytes
  through `0x80070763`. The return at `0x8007075C` has the frame restoration
  at `0x80070760` in its delay slot.
- The USA caller set includes `func_80070E98`, `func_800718DC`,
  `func_8007CD50`, `func_8006FEE8`, and `func_8007134C`. Direct callees are
  `func_8003B184`, `func_80016F0C`, `func_800174B8`, `func_80015268`, and
  `func_80015288`.
- The routine receives an object pointer and floating-point offset. It builds
  a matrix from object offset `0xAC`, extracts six placement values into
  offsets `0x08`..`0x1C`, and derives the object transform at `0x20` from
  that placement.
- It clears the object state words at `0x60`, `0x64`, `0xEC`, `0xF8`,
  `0x100`, `0x114`, and initializes the documented halfwords/floats and
  vectors at offsets `0x10C`..`0x268`. If offset is negative, `0xE8` receives
  the prior value at `0xE0`.
- Cross-version map equivalents are JP `0x80071018` (ROM `0x71C18`) and EU
  `0x80075988` (ROM `0x76588`); both are marked
  `unique_match` in `analysis/cross_version_functions.csv`.

## Inference

The routine is an object/framebuffer-state reset or initializer: it consumes
placement from `func_8003B184`, resets flags and counters, establishes default
vectors/scalars, and leaves the object ready for subsequent runtime updates.

## Status

Behavior-only recovery. IDO53 produces the same 700-byte span but does not
match exactly; the first difference is `0x25A`. The remaining differences are
localized to the final floating-point constant and register allocation (21
byte differences across eight instruction words).
