## Recovered behavior

The function stages a save-memory write request into the shared serial command
buffer. It takes a byte-sized block number and a pointer to eight bytes of
payload.

1. The buffer's trailing control word (offset 0x3C) is set to 1, which is the
   flag the transfer engine polls to start the transaction.
2. A twelve-byte command packet is built on the stack: a transmit length of 10,
   a receive length of 1, a command code of 5, the caller's block number, and
   then the caller's eight payload bytes copied one at a time in ascending
   order.
3. The first four bytes of the buffer, one per attached port, are cleared to
   zero so that the request is addressed to the first port only.
4. The finished packet is copied as a single object assignment into the buffer
   immediately after those four bytes, and the byte following the packet is set
   to 0xFE, the end-of-command marker.

The packet is assembled in a local and copied as a whole rather than written
field by field; that whole-object assignment is what produces the unaligned
block copy at the end. The block number parameter is byte sized, which is why it
is spilled into its incoming argument slot even though the spill is never read
back.
