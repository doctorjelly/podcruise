# func_8008A6B4

## Boundary

USA: VRAM 0x8008A6B4-0x8008A70B inclusive, 88 bytes, ROM 0x8B2B4.
The body closes with a return whose delay slot is a no-op. The preceding
routine (func_8008A690) returns before this entry, and the 220 direct callers
all target 0x8008A6B4, so the assigned boundary is correct. The single
internal branch jumps forward to the epilogue inside the function.

## Callers

220 direct call sites spread across the whole program - by far the most used
routine in this assignment. Callers pass a writable character buffer, a
format string, and a variable number of further arguments, and most of them
ignore the returned count.

## Callees

- func_80093180 - the formatting engine. It takes an output callback, an
  opaque state value handed to that callback, the format string, and the
  address of the first variable argument. It returns the number of characters
  produced, or a negative value on failure.
- func_8008A690 - referenced only by address, never called from here. It is
  the output callback that appends a run of characters to the buffer and
  returns the advanced buffer position.

## Recovered behaviour

This is the "format into a caller-supplied buffer" entry point.

1. Because the routine accepts a variable argument list, every incoming
   argument register is written to its home slot on entry; the address just
   past the format string's home slot is the start of the variable arguments.
2. It runs the formatting engine with the buffer-appending callback, the
   buffer as the callback's state, the format string, and that variable
   argument address.
3. If the engine reports a non-negative character count, the routine writes a
   terminating zero byte at that offset in the buffer. A negative count is
   left alone, so a failed conversion does not scribble on the buffer.
4. It returns the engine's count unchanged.

## Status

Exact in USA, Japan, Europe and lrg_rev1.
