## Recovered behavior

A byte fill in the shape of the standard library's memory-set primitive.

The three arguments are a destination address, a fill value, and a count. A
walking cursor starts at the destination. While the count is still non-zero the
count is decremented, the low byte of the fill value is written at the cursor,
and the cursor advances one byte. When the count reaches zero the loop stops and
the original destination address is returned unchanged.

The count is treated as unsigned, and the test is made before the decrement, so
a count of zero writes nothing and returns immediately. The fill value is
consumed only through its lowest byte; the upper bits are ignored rather than
masked. There is no alignment special case and no word-at-a-time fast path -
every byte is stored individually - so this is the plain, portable form of the
routine rather than an optimised one.
