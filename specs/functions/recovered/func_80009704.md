# func_80009704

## Boundary

USA VRAM 0x80009704..0x80009744 (64 bytes), ROM 0xA304. The body ends with the
return instruction whose delay slot performs the last global store, so the final
store is part of this function. All four direct call sites land on 0x80009704;
no branch from the preceding function reaches into this range. Boundary as
assigned is correct.

## Callers

Eleven direct call sites in the USA build (four distinct ones after the
duplicated overlay segments are collapsed), all in the menu/user-interface
region around 0x800272B8, 0x800536E8, 0x800543F8 and 0x8005440C. Every site
supplies four register arguments and two further arguments in the caller's
outgoing stack area, which fixes the arity at six.

## Callees

`func_800092EC`, which itself consumes only three arguments.

## Globals and access widths

* `D_8009ADE8` — 32-bit word, written whole.
* `D_8009ADEC` — 32-bit word, written whole.
* `D_8009ADF0` — 32-bit word, written whole.

All three are plain integer words: they are written with word stores here and
elsewhere in the module are set to -1, so they are treated as signed 32-bit.

## Recovered behavior

A six-argument entry point that starts a sub-activity and then records three
pieces of context for whoever polls it later. It first hands the first three
arguments to `func_800092EC`, which performs the actual work of locating and
starting the activity. Once that returns, the remaining three arguments are
published into module-scope state: the fourth argument into the first of the
three shared words, the fifth into the second, and the sixth into the third.
Nothing is returned, and nothing is read back.

The fourth argument is the only one that has to survive the call, so it is the
only one saved across it; the fifth and sixth already live in the caller's
argument area and are simply picked up afterwards.

## Status

Exact in USA, Japan, Europe and lrg_rev1 with the accepted ido53_o2 profile; no
per-unit flags needed.
