## Callees

## Globals and access widths

None. The function only touches memory reachable through its three pointer
parameters, all in 32-bit floating point units.

## Parameters

1. Pointer to a block of single-precision floats; only the three consecutive
   floats starting at byte offset 0x24 (element index 9) are read and written.
   The layout is consistent with a four-row by three-column matrix whose last
   row is a translation.
2. Pointer to a three-by-three block of single-precision floats stored row by
   row; it is read column-wise.
3. Pointer to three consecutive single-precision floats, read as a vector.

## Recovered behavior

For each of the three components in turn, the routine accumulates four terms
into the corresponding component of the destination triple (the floats at
element indices 9, 10 and 11 of the first argument):

- minus the first component of the vector, times the matrix entry in row 0 and
  the current column;
- minus the second component of the vector, times the entry in row 1 and the
  current column;
- minus the third component of the vector, times the entry in row 2 and the
  current column;
- plus the component of the vector corresponding to the current column.

Each of the four terms is accumulated as a separate read-modify-write of the
destination element rather than being summed in registers first; that is
observable in the compiled form and is reproduced by writing four separate
compound-assignment statements. In effect the destination translation is
adjusted by the vector minus the vector transformed through the three-by-three
matrix, which is what recentring a transform about a new pivot point looks like.

The loop counter runs over exactly three iterations and is materialised in a
register rather than unrolled. Nothing is returned.
