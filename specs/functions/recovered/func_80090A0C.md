# func_80090A0C

## Boundary

- USA VRAM range: 0x80090A0C .. 0x80090AA0 inclusive (0x98 = 152 bytes, 38 instructions).
- USA ROM offset: 0x9160C.
- Terminates with a return whose delay slot releases the stack frame.
- The assigned size of 152 was correct; no boundary correction was needed.

## Callers and callees

- One direct call site in the USA build (func_80090880), which passes a saved
  integer and the address of a four-byte stack object, then immediately reads
  bytes 2 and 3 of that object.
- No callees; leaf function.

## Globals and access widths

- `D_8014D720` — the same byte-addressed buffer written by func_8009094C. Read
  here as a six-byte record at a caller-chosen offset. Declared
  `extern u8 D_8014D720[]`.

## Recovered behaviour

The function decodes one six-byte record out of the shared buffer into a small
output structure supplied by the caller.

1. A cursor starts at the beginning of the buffer and is advanced by one byte
   per iteration of a counted loop whose trip count is the first parameter.
   The loop has no other effect; a count of zero or less leaves the cursor at
   the start of the buffer.
2. The six bytes at the cursor are copied into a local record. Because the
   record type is byte aligned while the local copy sits on the aligned stack,
   the copy reads bytewise and writes word-aligned.
3. The top two bits of record byte 1 are extracted and shifted down by four,
   and the result is stored into the fourth byte of the output structure. The
   value is therefore one of 0, 4, 8 or 12.
4. Only when that stored value is zero are the remaining fields filled in: the
   halfword at the start of the output takes record byte 4 as its high half and
   record byte 3 as its low half, and the third byte of the output takes record
   byte 5. Otherwise those fields are left untouched.

Two source-shape facts were needed for the byte-exact result:

- the locals must be declared in the order cursor, record, loop counter, which
  is what places the record at the stack offset the original uses;
- the extracted field is written to the output structure and then the *stored*
  field is tested rather than a local temporary. The compiler forwards the
  value it just stored but still applies the byte-width truncation of the
  field, which is exactly the extra masking step the original performs.

## Status

Exact. Verified byte-identical against USA, Japan, Europe and lrg_rev1.
