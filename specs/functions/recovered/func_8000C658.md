# func_8000C658

## Boundary

- USA VRAM range `0x8000C658` .. `0x8000C6C7` (last instruction word begins at
  `0x8000C6C4`), ROM `0xD258` .. `0xD2C7`, size 112 bytes.
- Ends with the return at `0x8000C6C0` and its delay slot at `0x8000C6C4`, which
  performs the final store.
- One internal forward branch that stays inside the range; nothing branches in
  from outside, and the single caller targets the entry.

## Callers

One direct call site: `0x8000DF40`.

## Callees

None; leaf routine, no stack frame.

## Globals and access widths

Identical to `func_8000C5F0`:

- `D_8009B7DC` — 32-bit word, live copy of the current slot's value.
- `D_8009B7F4` — array of 32-bit words, per-slot save area indexed by slot.
- `D_8009B800` — 32-bit signed current slot number.
- `D_800D5718` — array of 32-bit words, push-down stack of slot numbers.
- `D_800D578C` — 32-bit signed stack depth; compared as a signed quantity.

## Recovered behaviour

This is the "pop" half of the pair implemented by `func_8000C5F0`. It takes no
arguments and:

1. saves the live value back into the save-area entry belonging to the currently
   active slot;
2. decreases the stack depth by one, but only if the depth is still positive, so
   an over-pop clamps at index zero instead of walking off the front of the
   stack;
3. reads the slot number recorded at the resulting depth and makes it the
   current slot;
4. loads that slot's saved value into the live copy.

Because the depth is clamped rather than allowed to go negative, popping an
already-empty stack repeatedly simply reselects whatever slot is stored at
index zero. Nothing is returned.

## Status

Exact. USA, Japan, Europe and lrg_rev1 all verify byte-identical.
