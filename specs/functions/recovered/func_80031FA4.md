## Recovered behaviour

This is the per-tick advance of a table-driven texture (or palette) animation.

It first subtracts the global elapsed-time value from the record's accumulator.
The subtraction is performed in double precision - the accumulator is widened,
the global double is subtracted, and the result is narrowed back to single
precision before being stored - which is the natural result of a single-
precision field being decremented by a double-precision variable.

It then counts how many whole frames have elapsed: while the accumulator is
negative, it adds the frame period back and increments a step count. A zero or
negative frame period would hang here, so the record is assumed to hold a
positive period.

If the destination table pointer is null, or if no whole frame elapsed, the
routine returns without touching anything else.

Otherwise, for each of the animated slots in turn:

1. The slot's frame cursor is advanced by the number of elapsed frames and
   reduced modulo the record's frame count, so it wraps within the animation.
   The reduction is a signed remainder of a value built from an unsigned byte
   cursor and a signed step count, and the wrapped result is stored back as a
   byte.
2. The 16-bit entry selected by the slot's new frame cursor is copied out of
   the source table into the destination table at the slot's destination index.

Both the record pointer and the record's field values are re-read from memory
between the individual accesses, because the byte and 16-bit stores may alias
them; that re-reading is behaviour of the original code and is reproduced by
naming the global directly at every use rather than caching it in a local.

## Notes on shape

- The remainder is taken with the signed division operator, and the compiler's
  automatic divide-by-zero and overflow traps appear inline around it.
- The zero the accumulator is compared against is a single-precision zero, so
  the comparison is written against `0.0f`.
- The two early-exit guards are one conjunction in the source, not two nested
  statements; the loop's own entry test accounts for the third guard.
