# func_8000C724

## Boundary

- USA VRAM range `0x8000C724`-`0x8000C777` inclusive, ROM `0xD324`, size 88
  bytes (22 instructions).
- Terminates with a return followed by an empty delay slot; the preceding
  function `func_8000C6C8` ends at `0x8000C720`, so the assigned entry point is
  a true boundary.
- Leaf function: no frame is allocated.

## Callers

One direct call site in the USA build, reached from a jump-table dispatch. That
site passes the address of a global word, a floating-point value, the constant
`1.0`, a lower limit of `0`, and an upper limit of `6`.

## Callees and globals

None of its own. The single caller supplies a pointer to global data.

## Parameters

1. pointer to a signed 32-bit integer (read-modify-write target)
2. single-precision float
3. single-precision float
4. signed 32-bit integer, lower limit
5. signed 32-bit integer, upper limit (passed on the stack)

Returns nothing.

## Regional addresses

| Version | VRAM | ROM | Size |
| --- | --- | --- | --- |
| USA | 0x8000C724 | 0xD324 | 88 |
| Japan | 0x8000C724 | 0x00D324 | 88 |
| Europe | 0x8000C724 | 0x00D324 | 88 |

Both regional bodies were read independently and are identical to the USA body;
nothing in this function relocates.

## Recovered behavior

The integer counterpart of `func_8000C6C8`. It advances a stored integer by a
fractional increment and confines the result to a closed integer interval.

1. The stored integer is converted to floating point, the product of the second
   and third arguments is added, and the sum is truncated toward zero back to
   an integer.
2. That truncated result is written through the pointer.
3. If the result is below the lower limit, the lower limit is written instead
   and becomes the working value.
4. If the working value is above the upper limit, the upper limit is written.

Unlike the floating-point variant, the working value is carried in a local
temporary rather than re-read from memory between the steps, so the second
comparison sees the value the first step decided on. The final store is the one
that determines the stored result. Both comparisons are strict.

## Status

Exact. USA, Japan, and Europe all verify byte-identical.
