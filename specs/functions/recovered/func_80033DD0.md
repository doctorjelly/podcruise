## Globals and access widths

- `D_800A3CC0` - a single 32-bit signed counter. Its address is formed once and
  then used for one read and up to two writes, which is why the compiled form
  materialises the address rather than folding it into each access.
- `D_800E0C50` - the base of an array. The returned address is the base plus the
  counter scaled by 32, so the array elements are 32 bytes wide. The function
  never reads or writes through this base itself; it only hands the address out.

## Recovered behavior

A round-robin allocator handing out slots from a fixed pool of 256 records,
each 32 bytes long.

Each call advances a persistent counter by one. If the advanced counter has
reached the pool size of 256 the counter is reset to zero instead, so the index
cycles through 0..255 forever. The function then returns the address of the pool
entry selected by the counter.

Note that the incremented value is written back before the range test, and the
reset value is written back again on the wrapping call; the observable result is
simply that the stored counter always ends up equal to the index that was
returned. The comparison is signed, and the pool is never cleared or otherwise
touched here - callers get a raw slot address and are responsible for filling
it. Slots are reused after 256 calls with no in-use tracking, which makes this a
recycling ring buffer rather than a real allocator.

An immediately adjacent function does the same thing for a second, larger pool.
