# func_8003D370 — emit a fixed graphics-mode preamble into the display list

## Boundary

- USA VRAM `0x8003D370`..`0x8003D444` (exclusive), ROM `0x3DF70`, size 212 bytes.
- Frameless leaf: the body ends with the return instruction and an empty delay
  slot.
- All three direct call sites target `0x8003D370`, and the preceding function's
  branches stay inside their own body, so the boundary is correct.

## Callers and callees

- Three call sites, in `func_8000A53C`, `func_8003E9D8` and `func_8003EA30`.
- No callees.

## Parameters

None; the function takes no arguments and returns nothing.

## Globals

- `D_801217B0` — a pointer to the current write position of the graphics
  command buffer. It is re-read before every command, advanced by eight bytes,
  and written straight back, so each command consumes one eight-byte slot.
- `D_800A4960` — a word of option flags, read as a full word twice: once for
  bit 0 and once for bit 2. The second read genuinely re-loads the word, which
  is why the value cannot simply be cached in the source.

## Recovered behavior

The routine appends a fixed run of graphics commands to the display list. Each
command is one eight-byte slot: the routine reads the current buffer position,
advances the stored position past the slot, and fills the slot's command word
and payload word.

Three commands are always emitted: a texture-state command whose payload sets
both scale fields to their half-scale value, a colour-combiner command carrying
a fixed combiner recipe, and a lower-render-mode command that selects the
default depth source with a zero payload.

Two further commands are conditional on the option word. If bit 0 is set, a
lower-render-mode command is emitted that rewrites the whole render-mode field
with a fixed blend recipe. The option word is then read again, and if bit 2 is
set a final lower-render-mode command disables the alpha-compare stage.

## Status

Behavior recovered, not byte-exact. The compiled body is the same length and,
after thirteen source-shape experiments, is instruction-for-instruction
identical to the original including the instruction schedule; the only remaining
difference is the register assignment for two long-lived temporaries. The
original keeps the command-buffer pointer's address in the register two slots
lower than the compiler chooses here, and holds the option word in the first
return register rather than an argument register. Every ordering variant
(command word first or payload first per command, block-scoped versus
function-scoped slot pointers, post-increment versus explicit add, an explicit
local for the option word, extern declaration order, `-O1`, `-O3` and IDO 7.1)
was tried; the block-scoped, command-word-first form kept here is the one whose
schedule matches exactly.

## Source-layout finding

IDO's instruction scheduler is sensitive to source line grouping in this
function. Writing each emitted command's three statements on one source line, as
a macro expansion would produce, reproduces the original instruction order
exactly; spreading the same statements over separate lines changes which of the
two word stores is emitted first and moves the constant materialisation. This is
worth trying on any other display-list emitter that comes out one or two
instructions out of order.
