# func_80093890

## Boundary

- USA VRAM range: 0x80093890 .. 0x800938E0 inclusive (0x54 = 84 bytes, 21 instructions).
- USA ROM offset: 0x94490.
- Terminates with a return whose delay slot performs the store into the
  caller-supplied output word, so that store is part of the function.
- The assigned size of 84 was correct; no boundary correction was needed.

## Callers and callees

- Two direct call sites in the USA build.
- No callees; leaf function. It does keep an eight-byte stack frame that it
  never writes to, which is a consequence of the optimisation level (see below).

## Globals and access widths

- `D_80000308` — 32-bit word, read once. Holds the base address that is combined
  with the caller's device offset; the usual operating-system ROM base.
- The peripheral status word at physical address 0xA4600010 is read as a
  volatile 32-bit word. In the recovered source this is written as a literal
  address rather than as a named symbol: a named external produces a single
  hoisted address computation shared by both reads, whereas the original
  materialises the address separately for each read. The literal form is what
  reproduces the original.

## Regional addresses

The body is instruction-for-instruction identical in every version, and the only
relocated symbol (`D_80000308`) sits at the same address in all of them, so one
object matches everywhere.

| version   | VRAM       | ROM     |
|-----------|------------|---------|
| us        | 0x80093890 | 0x94490 |
| jp        | 0x80094580 | 0x95180 |
| eu        | 0x80098DE0 | 0x999E0 |
| lrg_rev1  | 0x80093890 | 0x94490 |

## Recovered behaviour

A raw programmed-I/O read from the cartridge bus.

1. The peripheral status word is sampled. While either of its two low bits is
   set — the bus is busy with an I/O or DMA transfer — it is sampled again.
   The loop is a plain busy-wait with no timeout.
2. Once the bus is idle, the caller's device offset is combined with the stored
   ROM base and forced into the uncached, unmapped address window, and the
   32-bit word at that address is read.
3. The word is stored through the second parameter and the function returns
   zero, which the callers treat as success.

Two compilation facts were needed for the byte-exact result:

- this translation unit was built at optimisation level 1, not 2. That is what
  produces the unused eight-byte frame, the unshared address computations and
  the unfilled branch delay slots. The recovered unit therefore carries a flags
  override, which this project already supports per unit.
- the status value is held in a `register`-qualified local. Without it the
  level-1 build spills the value to the stack on every iteration; with it the
  value stays in a register exactly as the original does.

## Status

Exact, using the unit flag override
`-G 0 -O1 -mips2 -non_shared -Xcpluscomm -signed -Wab,-r4300_mul`.
Verified byte-identical against USA, Japan, Europe and lrg_rev1.
