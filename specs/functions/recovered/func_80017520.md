# func_80017520

## Boundary

- USA VRAM range 0x80017520 - 0x8001757F (inclusive), size 96 bytes, ROM 0x18120.
- Body ends with the return instruction plus a filled delay slot; the delay slot
  performs the final store of the constant one.
- The preceding function (func_800174B8) tears down a 0x20-byte frame and
  returns immediately before this label with a bare delay slot, and none of its
  branches target this address, so 0x80017520 is a genuine entry point.
- Direct calls in the USA build target exactly this address.
- No stack frame is created.
- Boundary as assigned is correct.

## Callers

Twenty-six direct call sites in the USA build. The sampled sites hand it a
stack-local 64-byte scratch area and three consecutive 32-bit words loaded out
of a caller structure, and immediately afterwards feed that scratch area into
the project's 4x4 matrix concatenation routine. That surrounding use confirms
the destination is a matrix in this island's established layout.

## Callees

None. This is a leaf routine.

## Globals

None referenced.

## Recovered behavior

The routine fills a 4x4 single-precision matrix, laid out as sixteen
consecutive floats in row-major order with translation in the last row, with a
pure axis-aligned scaling transform. The first diagonal entry receives argument
two, the second diagonal entry receives argument three, the third diagonal
entry receives argument four, and the fourth diagonal entry is set to one.
Every one of the twelve off-diagonal entries is set to zero, including the
whole translation row. The destination is written unconditionally; nothing is
read back and nothing is returned.

## Argument evidence

Argument one is the destination address. Arguments two, three and four arrive
in the integer argument registers and are transferred into floating point
registers before being stored as 32-bit floats, so all three are `f32`. The
constant one appears as an immediate loaded into a register rather than from a
literal pool, which is the usual form for 1.0f in this compiler.
