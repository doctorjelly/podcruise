# func_80033E40 — latch the current transform and eye point into the debug globals

## Boundary

- USA VRAM range 0x80033E40 .. 0x80033EEB inclusive, 172 bytes (0xAC).
- The preceding label func_80033E08 is a genuine separate function ending in its
  own return; this function starts cleanly with a load from the second argument
  and ends with the return jump whose delay slot performs the final store.
- Boundary as assigned is correct; no correction needed.

## Callers

One call site (VRAM 0x800869C0 in the USA build). Both arguments are addresses
of stack temporaries in the caller: the first points at a 64-byte block that was
filled a few instructions earlier, the second at a 12-byte block adjacent to it.

## Callees

None. The function is a leaf.

## Globals and access widths

- `D_800A3FDC` — three consecutive 32-bit floats, all written.
- `D_80112E20` — sixteen consecutive 32-bit floats, all written.

Both destinations are addressed from a single materialised base with constant
displacements, so each is one object rather than a set of neighbours.

## Recovered behaviour

The function snapshots two pieces of camera-like state into globals so that
later code can use them without threading them through call arguments.

It first copies the three floats the second argument points at into a
three-element global — a position or direction triple. It then copies the
sixteen floats the first argument points at into a sixteen-element global, in
ascending order, which is a four-by-four transform stored row-major.

Both copies are straight element-by-element assignments with no arithmetic, no
bounds checks and no conditional paths. The compiled code interleaves the
opening stores of the triple with the setup of the second destination address,
which is scheduling only: the triple is fully written before the matrix copy
begins in program order, and the two destinations do not overlap.

The function returns nothing.

## Status

Exact. Byte-identical in usa, japan, europe and lrg_rev1.
