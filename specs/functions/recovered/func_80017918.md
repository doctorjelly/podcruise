# func_80017918 — scale the three basis rows of a 4x4 matrix

## Boundary

- USA VRAM `0x80017918`..`0x800179EC` (exclusive), ROM `0x18518`, size 212 bytes.
- The body ends with the return instruction and a store of the final matrix
  element in its delay slot; the last written element is the one at byte offset
  0x3C of the destination. No stack frame is created and no register is saved,
  so this is a leaf.
- Direct callers jump to `0x80017918` itself, and no branch inside the previous
  function reaches into this range, so the assigned boundary is correct.

## Parameters

The first parameter is a pointer (destination matrix). Parameters two, three and
four are single-precision floats delivered in the integer argument registers, as
the O32 rules require once the first parameter is not floating point; the fourth
is spilled into its caller-provided home slot and re-read from there at each use.
The fifth parameter arrives on the stack and is the source-matrix pointer.

Recovered signature: `void func_80017918(f32 dest[4][4], f32 x, f32 y, f32 z,
f32 source[4][4])`.

## Recovered behavior

The routine writes a scaled copy of a four-by-four single-precision matrix.
Every element of the first row of the source is multiplied by the second
parameter, every element of the second row by the third parameter, and every
element of the third row by the fourth parameter; the results are stored into
the matching positions of the destination. The fourth row is copied across
unchanged. In the usual interpretation of a row-major transform this scales the
three basis vectors of a transform independently while leaving the translation
row alone. Source and destination are written element by element in ascending
order, so overlapping buffers behave like a forward copy.
