## Recovered behavior

Draws a fresh 32-bit value from the generator func_80082BE0, converts it to a
float and scales it by 1/2147483648 so that the result lies in the range that a
signed 32-bit value spans, roughly -1 to +1. Doubling that and truncating
towards zero therefore yields 0 for a non-negative draw and 0 or -1 for a
negative draw; in practice the useful cases are 0 and -1. That whole number is
then doubled and reduced by one, and the result is returned as a float.

Read end to end, the function returns a small odd integer as a float: -1 for a
non-negative draw and -1 or -3 for a negative one. The obvious intent is a
coin-flip sign, which holds whenever the generator only produces non-negative
values in the lower half of the range plus the top half interpreted as negative.

## Source shape notes

The doubling step is the load-bearing detail. Writing it as a multiplication by
the double literal 2.0 makes the compiler strength-reduce it to a
double-precision addition, which is twelve bytes short of the original. Writing
it as a multiplication by the *integer* literal 2 against an explicitly
double-typed left operand keeps a real double multiply against an inline 2.0,
which is what the original contains. Multiplying by the integer 2 without the
double cast instead gives a single-precision multiply, which is eight bytes
short.

## Status

Exact on us, jp, eu and lrg_rev1.
