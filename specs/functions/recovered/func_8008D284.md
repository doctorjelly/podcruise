## How control reaches it

Three ways, and two of them are not calls.

- By unconditional jump from func_8008CB00, at 0x8008CFF4, 0x8008D00C and
  0x8008D03C, and from func_8008D12C at 0x8008D224. These transfer control and
  do not expect it back.
- By call, twice, from 0x8008BA4C and from 0x80095A6C — startup and thread
  teardown, respectively. The return address those two leave behind is dead: the
  routine cannot return, so those call sites are calls only in encoding.

Four blocks inside the body have no incoming branch and are reached solely by
falling through the floating-point restore sequence.

## Callees

func_8008D274, called once at the very top.

## State read and written

Reads: the ready list head at D_800A7BB8, the global permitted-interrupt mask at
D_800A7B50, the halfword table at D_800ADF90, and the whole saved context of the
thread it selects.

Writes: the running-thread pointer at D_800A7BC0, the selected thread's run
state halfword, the peripheral interrupt mask register D_A430000C, the processor
status register, the exception program counter, the multiply result pair, the
floating-point control word, every general-purpose register except the two
kernel-reserved ones, and all sixteen saved floating-point registers.

The halfword table at D_800ADF90 is indexed by the thread's saved peripheral
mask after that mask has been narrowed against the global permitted set, and is
read at halfword width with a scaled index. It converts a compact per-source bit
set into the enable/disable bit pattern the hardware register actually wants.

## Recovered behavior

Chooses the next thread to run and resumes it. This is the single point at which
the operating-system layer gives the processor back, and every path out of the
exception handler and out of the voluntary yield ends here.

It removes the first thread from the ready list — which the two routines that
maintain that list keep sorted by priority, so the first is the highest — records
it as the running thread and marks its state as running.

It then rebuilds the machine from that thread's saved context. The status word is
restored with its interrupt-enable bits narrowed to the intersection of what the
thread saved and what the global permitted mask currently allows, so a thread
cannot resume with permission that has since been withdrawn. The multiply result
pair, every general register including the stack, frame and global pointers and
the return address, and the exception program counter are all reloaded. If the
thread is flagged as a floating-point user, its floating-point control word and
all sixteen saved floating-point registers are reloaded too; otherwise that whole
block is skipped, which is the entire point of the flag.

The last thing it restores is the peripheral interrupt mask. The thread's saved
mask is a compact bit set, one bit per interrupt source; it is narrowed against
the high half of the global permitted mask and then used to index a table that
turns it into the paired set/clear bit pattern the hardware register expects.
That store is followed by a deliberate delay before the processor is restarted,
so the write has taken effect before any interrupt can be recognised.

The routine then returns from exception: the processor restores the program
counter from the saved exception program counter, drops out of exception level,
and continues executing the resumed thread. That single instruction is what makes
the resumption atomic — the status word and the program counter are put back
together, with no window in which an interrupt could be taken with one restored
and not the other.

The separate two-instruction entry after it is the landing pad for a thread whose
entry function returns: it destroys the current thread, which in turn ends up
back here to pick someone else.

## Why this cannot come from C

The decisive instruction is the return from exception at 0x8008D3FC. It is a
privileged coprocessor-0 instruction with no C spelling whatever: it is not a
return, it does not use the return-address register, and its effect — restoring
the program counter from a coprocessor-0 register and clearing exception level
in the same cycle — is not expressible as any C statement. The accepted compiler
has no inline assembly; it parses an `asm(...)` construct as a call to an
undeclared function named `asm`, so there is no source text that reaches the
instruction at all.

The body is disqualified twice more, independently. It writes the coprocessor-0
status register at 0x8008D2D0 and the exception program counter at 0x8008D35C.
And it uses both kernel-reserved registers as its main working pair across 75 of
its 95 instructions — the selected thread's context pointer lives in one of them
for the whole restore, precisely because every other register is being
overwritten with the resumed thread's values. That is a register allocation no
compiler will produce and no compiler could produce, since it requires knowing
that no exception can be taken during the sequence.

The structural fact behind all of this: for its last few instructions the
routine has no live registers of its own and no stack, because it has already
restored the resumed thread's stack pointer. There is nothing left for a
compiler-generated epilogue to run on.

## Note on translation unit

This body is part of the same original assembly translation unit as
func_8008CB00, func_8008D044 and func_8008D12C; the argument is set out in full
in `func_8008D044.md`. The facts specific to this function are that it begins at
the exact byte after func_8008D274 ends, at an address that is not sixteen-byte
aligned; that it is entered by one-way jump from two of the others, a contract
separately compiled units cannot agree on; and that the two-instruction entry
that follows it is the last code before the alignment padding that closes the
unit at 0x8008D410.
