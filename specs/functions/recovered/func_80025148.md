# func_80025148

## Verified facts

- The canonical USA body begins at VRAM `0x80025148`, ROM `0x25D48`, and is
  `0x14FC` (5,372) bytes. Its `jr ra` is at `0x8002663C`; the delay slot at
  `0x80026640` restores the `0xE8`-byte stack frame. `func_80026644` starts
  immediately afterward.
- Its only direct recovered caller is `func_8004A880`, which dispatches to it
  for menu mode 13.
- Three computed switches were checked against the local USA ROM. The seven
  words at ROM `0xAA918` select the option-rendering cases at `0x800253FC`,
  `0x800254A8`, `0x800256D8`, `0x80025750`, `0x800257F0`, `0x800258A8`, and
  `0x80025958`. The tables at ROM `0xAA944` and `0xAA960` select the seven
  increment and decrement cases beginning at `0x80026354` and `0x8002647C`.
  All three indirect jumps have a `nop` delay slot.
- The canonical body has 91 static calls. IDO merges four pairs of mutually
  exclusive calls in the recovered expression form, but the resulting 87
  sites retain the same reachable helper operations and ordering on each
  branch.
- JP `func_80025884` spans `0x1640` bytes through `0x80026EC3`. It uses the
  same `0xE8` stack frame and ends with `jr ra` plus a stack-restore delay slot.
  EU `func_80026BAC` spans `0x210C` bytes through `0x80028CB7`; its localized
  variant uses a `0xF0` stack frame and has the corresponding terminal pair.
  These variants were used only as structural and relocation evidence.

## Behavioral specification

Initialize the pre-race settings screen when it is entered, including its
selection, fade state, and list of enabled option kinds. Draw each visible row
according to its option kind: vehicle side, race format and lap values,
difficulty, race count, AI level, upgrade mode, or track choice. Advance the
layout for the taller upgrade row and format the current value beside each
label.

Update the screen fade, vehicle preview, text panel, upgrade indicators, and
three associated sprites. Once the screen is fully visible, read the single
menu input word. Confirm stores the chosen race count and advances to the next
screen; cancel returns to the previous screen. Vertical input wraps the active
row, while horizontal input changes the selected value through two seven-way
switches. Finish by wrapping all bounded option values to their valid ranges.

## Inferences and recovery notes

- The routine is a pre-race menu renderer/controller. This follows from its
  option-list construction, formatted labels, sprite placement, navigation
  sounds, and its mode-13 caller; it is not an authored symbol name.
- Field and global names remain address based because their full semantics are
  not established. Local type names describe only the offsets used here.
- The input loop starts at `D_800A4BA4` and terminates at the immediately
  following address `D_800A4BA8`, so this build processes exactly one word.
  Later reads are intentionally not all folded into the first snapshot because
  the canonical body reloads the word after helper calls.
- The two `func_8002D048` calls use its old-style declaration and pass
  `0x437F0000` as an integer so the float bit pattern remains in `a3` while the
  canonical ignored seventh word is retained. Passing a C `float` through an
  unprototyped call would promote it to a `double` and change the ABI.
- A mechanical `m2c` draft was used only to expose the large control-flow
  graph after supplying the three ignored jump tables. The boundary, delay
  slots, callers, helper contracts, table targets, state reloads, and behavior
  were checked independently against the USA assembly and recovered callees.

## Status

**Behavior-recovered C, not byte-matching.** IDO 5.3 emits a `0x136C`-byte
function after the final state-reload corrections versus canonical `0x14FC`,
and its first differing instruction byte is offset `0x2`. IDO 7.1 emits
`0x132C` bytes and also first differs at `0x2`. The USA split must continue
assembling the original body.
