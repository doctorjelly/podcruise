# func_80093C30 — guarded single-word read from a serial-bus device address

## Boundary

* USA VRAM `0x80093C30`–`0x80093C7F`, ROM `0x94830`, 80 bytes.
* Frame is 0x18 bytes; both parameters live in their caller-provided home slots
  across the call. Ends with the standard return sequence and an empty delay
  slot. Two internal labels, both this function's own arms.
* Two direct callers target this entry. Boundary as assigned is correct.

## Callers

Two direct call sites in USA, adjacent to each other in the routine at
`0x8008B5xx`. Both pass the literal device address `0x1FC007FC` (the status
word at the end of the serial peripheral's buffer) and the address of a stack
local as the destination.

## Callees

* `func_80097950` — busy test for the same serial peripheral. It reads the
  peripheral's status register, returns 1 when either of the low two status
  bits is set, and 0 otherwise. It takes no arguments.

## Globals

None by name. The routine reaches one hardware word through a computed
uncached address; no data symbol is referenced.

## Access widths

* Both parameters are 32-bit: a device address and a pointer to a 32-bit
  destination.
* The device word is read as a 32-bit volatile load, and stored as a 32-bit
  word through the destination pointer.
* The result is a 32-bit status code.

## Recovered behavior

The routine performs one uncached programmed-I/O read on behalf of the caller,
but only when the peripheral is idle. It first asks the busy test whether a
transfer is in flight; if so it fails immediately with -1 and touches nothing.
Otherwise it converts the supplied physical device address into its uncached
kernel-segment alias by setting the top three address bits, loads the 32-bit
word found there, writes it through the caller's destination pointer, and
reports success with 0.

## Status

Byte-identical in USA, Japan, Europe and lrg_rev1 under IDO 5.3 with the
accepted flags but -O1 in place of -O2; see the result JSON for the exact flag
list. Under the accepted -O2 profile the body is four bytes short (76 instead
of 80) because -O2 hoists the first parameter reload into the guard branch's
delay slot; the original leaves that slot empty. This is an optimisation-level
property of the translation unit rather than a source-shape question — the
neighbouring routines in this unit show the same -O1 tells (parameters re-read
from their home slots, no cross-branch scheduling).
