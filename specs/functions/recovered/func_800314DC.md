# func_800314DC

## Boundary — corrected

- Assigned range: 0x800314DC, size 108. **Wrong.**
- Actual range: VRAM 0x800314DC .. 0x80031560 (exclusive), ROM 0x320DC,
  size 132 bytes.
- The label scan cut the function at its first return. Two branches inside the
  body jump *past* that return, to 0x80031548 and to 0x80031550, and both of
  those follow-on labels have zero direct callers. They are the two alternate
  arms of the closing three-way selection, not functions. The real body ends at
  0x8003155C with a return whose delay slot is empty; the next genuine entry is
  func_80031560, which has a proper prologue and is the target of real calls.
- The same truncation is present in the Japan, Europe and lrg_rev1 label scans;
  the corrected size 132 was confirmed against all four ROMs.

## Callers and callees

- Two direct call sites (four counting the duplicated split files). No calls
  out (leaf).
- Call sites supply the index in the first slot, load the second argument with
  an unsigned 16-bit load, and pass two full words for the remaining two
  arguments.

## Arguments

Four: a 32-bit index, an unsigned 16-bit value, and two 32-bit flags. The
16-bit argument is spilled to its caller-provided home slot on entry and then
masked to 16 bits, which is the ordinary code shape for a `u16` parameter and
not evidence of a stack local.

## Globals and access widths

- `D_800DB8A0` — array of 28-byte records; the index argument selects one.

| offset | width | access |
| --- | --- | --- |
| 0x04 | unsigned 16-bit | read once, written once |
| 0x06 | unsigned 16-bit | read once, conditionally written |
| 0x08 | signed 16-bit | written once |
| 0x16 | signed 16-bit | written once |

The differing signedness of the two written 16-bit fields at 0x08/0x16 versus
the unsigned pair at 0x04/0x06 is load bearing: see the compiler note.

## Recovered behavior

Publishes a new value into one record of the table and marks how it should be
consumed.

1. The record is selected by multiplying the index by the 28-byte record size.
2. A "restart" marker (0x8000) is stored into the record's 16-bit field at
   0x06 unless all three of the following are true: the field already holds a
   non-zero marker, the record's current value at 0x04 already equals the new
   value, and the third argument is non-zero. In other words the marker is
   refreshed whenever the record was idle, whenever the value actually changes,
   or whenever the caller asks for the inactive mode.
3. The new value is then stored unconditionally into the record's current
   value field at 0x04 and into its companion field at 0x16.
4. The record's mode field at 0x08 is set from the two flag arguments: minus
   one when the third argument is zero, one when the third argument is non-zero
   but the fourth is zero, and two when both are non-zero.

## Compiler note

Two source-shape details were needed for byte equality.

- The closing selection must be written as a nested pair of tests on the third
  then the fourth argument, with the "two" case as the innermost fall-through;
  a flat if / else-if chain starting from the zero case lays the three arms out
  in the wrong order.
- The field at 0x16 must be declared signed while the field at 0x04 is
  unsigned. Both receive the same unsigned 16-bit argument, but the type
  mismatch stops the optimiser from sharing one register between the two
  stores, and it emits the extra pair of register copies that the original
  contains. With both fields the same type the result is two instructions
  short.

## Status

Exact at the corrected size 132. Byte-identical in USA, Japan, Europe and
lrg_rev1.
