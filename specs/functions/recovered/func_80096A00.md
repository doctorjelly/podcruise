# func_80096A00 — summarise a table of eight-byte records into entries and a bitmask

## Boundary

- USA VRAM `0x80096A00`..`0x80096AD0` (exclusive), ROM `0x97600`, size 208 bytes.
- The prologue is the two-instruction load of the count byte followed by the
  stack adjustment; the count load sits *before* the frame adjustment but is
  part of the function, because the single direct caller targets `0x80096A00`.
- The body ends with the return instruction whose delay slot performs the final
  byte store through the first parameter.

## Callers and callees

- One call site, in `func_80096790`, which passes pointers to two of its own
  stack locals.
- No callees. Leaf function, 0x18 bytes of frame, nothing saved.

## Parameters

Two pointers. The first receives a single byte on exit. The second points at an
array of four-byte entries which is walked forwards, one entry per iteration.

Recovered signature: `void func_80096A00(u8 *flags, PcEntry *entry)` where
`PcEntry` is `{ u16, u8, u8 }`.

## Globals

- `D_80149CB1` — unsigned byte, re-read on every loop test, used as a signed
  iteration count.
- `D_8014D720` — base of an array of eight-byte records whose alignment is one
  byte (the copy out of it is performed with unaligned word loads). Fields at
  record offsets 2, 4, 5 and 6 are read as single bytes.

## Locals

Four locals live in the frame rather than in registers, in this order from the
low end of the frame: an unsigned byte accumulator, a signed word index, an
eight-byte copy of the current record, and the record pointer. Their order in
the frame is the reverse of their declaration order in the source.

## Compiler note (important for the shared configuration)

This translation unit only reproduces the original bytes when it is compiled at
`-O1`. At `-O2` the same source is correct but 172 bytes, because the index,
accumulator and record pointer are register-allocated and the count global's
address is hoisted; the original keeps all three in the frame and rebuilds the
count global's address on every iteration. Adding a per-unit `flags` override
(the mechanism `tools/verify_c_matches.py` already supports) with `-O1` in place
of `-O2` makes it exact under the accepted `ido53_o2` profile.

## Recovered behavior

The routine clears an eight-bit accumulator and walks the record table from its
first element, once for each of the first N records where N is the current value
of the count byte, re-read at every iteration.

For each record it takes a private copy of the whole eight-byte record, then
derives a two-bit code from the record byte at offset 2: the top two bits of
that byte, shifted down by four, so the stored code is 0, 4, 8 or 12. That code
is written into the last byte of the current output entry.

The code is then read back out of the entry and, only when it is zero, three
more things happen: the first halfword of the entry receives the record bytes at
offsets 4 and 5 combined little-endian style (offset 5 forms the high byte), the
third byte of the entry receives the record byte at offset 6, and the bit whose
position equals the current iteration index is set in the accumulator.

After each record the output entry pointer advances by one entry and the record
pointer by one record. When the loop ends the accumulator is stored through the
first parameter, so the caller learns which of the first N records qualified.

## Status

Exact at `-O1`. USA, Japan, Europe and lrg_rev1 all verified byte-identical from
one source file.
