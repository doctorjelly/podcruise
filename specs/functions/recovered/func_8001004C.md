# func_8001004C — decode a packed bank-and-offset value into a linear address

## Boundary

- USA VRAM range `0x8001004C` .. `0x8001007F` inclusive; size 52 bytes
  (13 instructions).
- The body ends with the standard return instruction whose delay slot holds the
  final addition producing the result, so both instructions belong to this
  function.
- `func_80010040` returns before this label and all five direct call sites
  target `0x8001004C`, so the assigned boundary is correct.

## Callers

Five direct call sites in the USA build: `0x800103A4`, `0x800103B4`,
`0x80010864`, `0x80010D00`, `0x80011300`. One argument, one returned word.

Two call sites load the argument from a word in memory, one loads it as an
unsigned halfword, and two reach the call with the argument already in place.
Every call site immediately compares the returned word against another signed
integer, so the result is used as a signed quantity.

## Callees

None; leaf function, no stack frame.

## Globals and access widths

| symbol | role | width |
| --- | --- | --- |
| `D_8009B888` | eight entries of two words each: a shift count followed by a base value | two 32-bit loads per lookup |

The bank index is at most seven and the entry stride is eight bytes, so the
table occupies `0x8009B888` .. `0x8009B8C7`.

Regional data symbol (USA / Japan / Europe): `D_8009B888` / `D_8009C578` /

located and confirmed by reading the Europe body at `0x800104AC`, which is the
same thirteen-instruction shape with the Europe data address.

## Recovered behaviour

The argument is a packed value split into two fields:

- bits 13 to 15 select one of eight table entries (a "bank");
- bits 2 to 12 hold an element count; bits 0 and 1 are ignored entirely.

The routine reads the selected entry's shift count and base value, scales the
element count left by that shift count, adds it to the base value, and returns
the sum. The effect is to turn a compact bank-plus-index token into a flat
address or offset, where each bank may have a different element size (expressed
as a power-of-two shift) and a different starting point.

Both field extractions use signed arithmetic shifts, so the argument is a signed
integer in the original source; because the masks clear the sign bit before the
shift, the signedness has no effect on the values produced.

## Status

Behaviour-recovered, not byte-exact. The compiled form agrees with the original
in every opcode, every operand order and the complete instruction schedule; 51
of the 52 bytes are identical. The one difference, at byte offset `0x16`, is the
scratch register the compiler colours the table-entry address with: the original
uses the second argument register, the recovered source causes the second return
register to be chosen instead.

Twelve source shapes were tried to move that colouring (expression form with and
without a named pointer, a two-word array instead of a struct, a two-dimensional
array, separate index/shift/scaled locals in both declaration orders, pointer
arithmetic instead of subscripting, the `register` storage class, a second
declared parameter, and the 7.1 compiler profile). The controlled results show
the compiler assigns the second return register to whichever eligible local is
defined first and the second argument register to the next one, and no shape
that keeps the instruction count at thirteen leaves an earlier eligible local to
absorb the first register. The behaviour above is certain; only the register
colouring is unresolved.
