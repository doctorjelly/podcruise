# func_80007E80

## Verified facts

- The canonical USA body spans VRAM `0x80007E80` through `0x80007F5B`, ROM
  `0x8A80`, for 220 bytes. The final `jr ra` restores the 40-byte frame in its
  delay slot; the following function begins at `0x80007F5C`.
- Recovered caller `func_8002FA00` passes 1. The routine saves that argument but
  does not otherwise read it.
- It calls `func_80007A80` and `func_80007A44` for each occupied entry, then may
  call `func_80008F28` repeatedly.
- It reads and clears the 23 words at `D_8009A32C` and the eight words at
  `D_8009A388`. It also reads and writes `D_800B05B0`.
- Both array loops increment their cursor in branch-likely delay slots. The
  return delay slot restores the stack pointer, confirming the 220-byte
  boundary.
- The LRG body is byte-identical. Japan and Europe retain the same size,
  branches, delay slots, and call sequence; only five and six address-building
  words differ, respectively, consistent with relocated globals.

## Behavior

Walk both slot tables. For every nonzero slot, run the two release helpers,
clear the slot, and remember that at least one resource was released. If any
slot was cleared, reset the frame counter and repeatedly run the drain helper
until that counter reaches five.

## Status

Byte-matching C in canonical USA. Exact linked IDO 5.3 `-O2` comparison
reproduces all 220 bytes. The behavior-neutral `released * 0` expression is
always zero but preserves the flag's compiler lifetime and selects the ROM's
saved-register allocation. No Japan or Europe byte match is claimed.
