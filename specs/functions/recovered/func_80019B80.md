# func_80019B80

## Boundary
- USA VRAM `0x80019B80` .. `0x80019BB4` (exclusive), ROM `0x1A780`, size 52 bytes.
- Standard leaf-of-one-call frame: the body reserves 0x18 bytes of stack, saves the
  return address, performs one call, restores and returns. The final return is
  followed by an empty delay slot.
- Verified as a real entry point: the function immediately before it ends with its
  own return two words earlier, and every direct call site targets `0x80019B80`.
  No branch from the preceding function reaches into this range.

## Callers
Three call sites, all inside the same dispatch routine reached through the jump
table at `jtbl_800AB0D8`; the caller supplies one object pointer and ignores any
result.

## Callees
- `func_8004A6A4(object, flag, mode)` — takes a pointer plus two integer values,
  both of which it homes to its own frame.

## Globals
None referenced directly.

## Structure fields touched
- offset `0x68` of the incoming object, read as a 32-bit word.

## Recovered behaviour
The routine forwards its single object argument to the shared handler, adding two
extra values. The first extra value is a boolean derived from the word at offset
`0x68` of the object: one when that word is set, zero when it is clear. The second
extra value is always one. Nothing else is read or written, and the handler's
result is discarded.

The source shape that reproduces the original code initialises the boolean to one
and clears it only when the object word is zero; writing the same test in the
opposite order (clear first, set in the taken branch) produces a longer body with
an extra unconditional branch, and writing it as a plain `!= 0` comparison
produces an unsigned set-on-less-than instead of a branch.

## Status
Exact on USA, JP, EU and lrg_rev1.
