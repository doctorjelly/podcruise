# func_80064AF4

## Boundary

- USA VRAM range `0x80064AF4` .. `0x80064B43` inclusive (80 bytes, 20 words),
  USA ROM offset `0x656F4`.
- Ends with `jr $ra` and an empty delay slot. Both conditional branches inside
  the body target that same final return, which is why the two tests read as
  nested rather than sequential.
- `0x80064B44` begins a separate body that starts by re-materialising the same
  global base into a different register, so the end is confirmed.
- The single direct call site targets `0x80064AF4`.
- No boundary correction was required.

## Callers / callees

- Callers: 1 direct call site, made with no arguments set up, immediately after
  a per-frame update call and before the caller inspects a mode field.
- Callees: none. This is a leaf.

## Globals and access widths

- `D_8011A240` — the same block of 32-bit floats used by `func_80064A88`. This
  function uses only the element at byte offset `0x38`, which is index 14 of a
  float array. It is read and written as a 32-bit float, and the base address
  is materialised into a register once and reused, as for an array subscript.
- `D_80120BF8` — the same single 32-bit float step constant, read once and only
  on the path where the countdown is actually running.

Each regional body was read independently before probing. All three are the
same instruction shape as the USA body, differing only in the two relocated
data addresses.

## Recovered behavior

Takes no arguments, returns nothing, and runs one tick of a floating point
countdown timer.

If the stored timer value is strictly greater than zero, the global step size
is subtracted from it and the result written back. The new value is then
re-read and, if it has gone strictly below zero, it is replaced with exactly
zero so the timer parks at zero instead of drifting negative. If the timer was
not above zero to begin with, nothing at all is written and the step constant
is not even loaded.

The value tested at entry and the value used as the minuend are the same read;
only the result of the subtraction is re-read from memory for the second test.
That mixture of one cached read and one re-read is what the original bytes
show, and follows naturally from writing the update as a compound subtraction
on the array element followed by a fresh test of that element.

## Status

Exact. USA, Japan, Europe and lrg_rev1 all verified byte-identical.
