# func_80093C20 — exchange the floating-point control/status word

## Boundary

- USA VRAM `0x80093C20` .. `0x80093C2F`; ROM `0x94820`; size 16 bytes.
- Ends with `jr $ra` plus a `nop` delay slot; the single direct caller targets
  `0x80093C20`. **No boundary correction needed.**
- Both of the first two instructions are floating-point control-register
  transfers, which no compiler emits.

## Callers

One direct call site, in `func_8008B580` (USA `main_8BDB0.s`), during start-up.
The argument is the literal `0x01000800`, which is the usual N64 boot setting
for this register: flush-denormals-to-zero enabled together with a single
enabled exception. The returned previous value is discarded at that site.

## Callees

None.

## Globals and access widths

None; no ordinary memory is touched.

## Recovered behavior

An atomic swap of the floating-point unit's control and status word: the
existing word — rounding mode, enabled exception mask, sticky exception flags
and the flush-to-zero control — is captured as the return value, and the word
supplied by the caller is installed in its place. Callers use it both to
program the FPU mode at start-up and to save/restore that mode around code with
different rounding or exception requirements.

## Status

**skipped** — not recoverable as C. Reading and writing the FPU control
register are privileged coprocessor transfers with no C spelling, and inline
assembly is forbidden by the project rules. Carry it as a handwritten assembly
unit.
