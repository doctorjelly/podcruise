# func_80089CC0

## Boundary

- USA VRAM range: 0x80089CC0 .. 0x80089D84 inclusive (0xC8 = 200 bytes, 50 instructions).
- USA ROM offset: 0x8A8C0.
- Ends with a return whose delay slot releases the 0x18-byte frame; two padding
  words follow before the next function, confirming the end of the body.
- One direct call site; the entry is the target of that call. No branch from the
  preceding function reaches into this range. Assigned size 200 was correct.

## Callers and callees

- Called from exactly one place (a routine at 0x80089BB4 that first calls a
  helper, then dispatches on a byte flag).
- Leaf function: no calls out. Takes no arguments and returns nothing.

## Globals and access widths

- `D_80149C70` — a 16-word block of 32-bit integers at the start of a shared
  buffer. Word indices 0..14 are cleared; word index 15 receives 1. The same
  address is also treated as an array of 8-byte records (see behavior).
  A neighbouring routine at 0x80089AC0 clears the same block with an explicit
  `index < 15` word loop, which fixes both the element width and the count.
- `D_80149CB1` — unsigned byte, read once before the fill loop and re-read on
  every pass; it is the number of records to write.
- The 8-byte record has four byte fields, then a 16-bit field at offset 4
  (written with a halfword store, so it is genuinely 16 bits wide), then two
  more byte fields. The two trailing byte fields hold the value -1 as a signed
  quantity, while the leading byte field holds 255; the compiler materialises
  the two constants differently, which pins the signedness of each field.

## Regional addresses

Body is instruction-for-instruction identical in all four versions; only the two
global addresses move.

| version  | VRAM       | ROM     | buffer      | count byte  |
|----------|------------|---------|-------------|-------------|
| us       | 0x80089CC0 | 0x8A8C0 | D_80149C70  | D_80149CB1  |
| jp       | 0x8008A9B0 | 0x8B5B0 | D_8014CEE0  | D_8014CF21  |
| eu       | 0x8008F210 | 0x8FE10 | D_80152910  | D_80152951  |
| lrg_rev1 | 0x80089CC0 | 0x8A8C0 | D_80149C70  | D_80149CB1  |

In every version the buffer's count byte sits at buffer + 0x41 and the word
written with 1 sits at buffer + 0x3C, so the layout is unchanged regionally.

## Recovered behavior

Rebuilds the shared record list from scratch.

First it clears the fifteen leading words of the buffer to zero and sets the
sixteenth word to one. Then it builds a template record in a local: a leading
tag byte of 255, then 1, then 4, then 1, a 16-bit field of 0xFFFF, and two
trailing signed bytes of -1. That template is copied into consecutive 8-byte
slots at the start of the buffer, once per entry, where the entry count is the
shared count byte; because the count byte is re-read on every pass, a change to
it during the loop would be observed. Finally the first byte of the slot just
past the last written record is set to 254, terminating the list.

Shape notes that were needed for byte equality: the clearing pass must be
written as an ordinary indexed loop over word 0..14 rather than as a pointer
walk (the pointer walk lets the compiler consume the buffer's base register, and
it then has to rematerialise the address for the following word store); the
record copy must be a whole-record assignment rather than field-by-field stores;
and the loop bound must be the shared count byte itself, not a cached local copy,
otherwise the compiler unrolls the fill loop.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
