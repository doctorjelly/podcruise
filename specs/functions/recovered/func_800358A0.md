# func_800358A0

## Boundary

- USA VRAM range: `0x800358A0` .. `0x8003594B` inclusive.
- Size: 172 bytes (43 instructions).
- Ends with a shared return whose delay slot holds the move of the result into
  the return register. A second return sits inside the body, also with a
  computation in its delay slot.

**Boundary correction.** The assignment file gave `size: 184`. The heuristic
label covers only the first 92 bytes and branches forward past its own return
into `func_800358FC`, which in turn falls into `func_8003592C`; neither of those
labels is the target of any call, and both are interior branch targets. The real
extent is `0x800358A0` to `0x8003594B`, 172 bytes; the next real function starts
at `0x8003594C` with a genuine stack-frame prologue.

The corrected body uses a third global, `D_800A3D60`, that the assignment's
truncated view did not list.

## Recovered behavior

The routine takes a set of drawing flags, filters it against three global
capability switches, and returns the adjusted set. The argument is never
written back anywhere; only the return value carries the result.

1. Read the capability word `D_800D697C` once.
   - If its bit 0x40 is set, clear bit 0x00010000 from the flag set.
   - If its bit 0x20 is set, clear bit 0x00020000 from the flag set.
2. If `D_800A4744` is zero, clear both bit 0x400 and bit 0x200 and return
   immediately. This is the "feature completely unavailable" path.
3. Otherwise, if `D_800A3D60` is zero, return the flag set unchanged.
4. Otherwise exchange bits 0x200 and 0x400, but only when exactly one of them is
   set:
   - if 0x200 is set and 0x400 is clear, set 0x400 and clear 0x200;
   - if 0x400 is set and 0x200 is clear, set 0x200 and clear 0x400;
   - if both or neither are set, leave the pair alone.
5. Return the resulting flag set.

The second half of step 4 re-tests bit 0x200 even though the enclosing branch
already established it is clear. That redundant test is present in the original
code and is reproduced by the recovered source, which is why the two halves are
written as mirror images of each other rather than collapsed.

## Status

Behavior recovered, not byte-exact. 172 bytes expected, 176 produced; first
difference at offset 0x64.

Everything up to offset 0x60 is byte-identical, including all three global
reads, both capability filters, the early clear-and-return path, the register
choices in the bit-exchange block, and the interior return. The residual
difference is confined to the shared return tail. The original places the
result-move into the delay slot of the final return, so the two conditional
branches that jump to that tail cannot use branch-likely forms and take empty
delay slots. The recovered source instead yields a result-move standing ahead of
the final return, which lets the compiler convert those two branches to
branch-likely forms with a duplicated move; that costs one extra instruction.

Eight source-shape experiments were tried against this tail: nested versus
short-circuit conditions, explicit interior returns versus fall-through
assignment, an explicit temporary for the exchanged value, inverting the
`D_800A3D60` test into an early return, an explicit return at the end of the
enclosing block, and an if/else pair of returns. Two of them (an explicit return
closing the `D_800A3D60` block, with or without a trailing else) reproduce the
wanted two-instruction tail exactly but then split the `D_800A3D60`-is-zero path
into a second return block, which costs more. The version kept here is the
smallest and clearest of the set. The remaining gap is a single
delay-slot-scheduling choice, not a behavioral difference.
