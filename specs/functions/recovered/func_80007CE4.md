# func_80007CE4 — resolve a packed handle to its owning record pointer

## Boundary

- **Boundary correction.** The assignment gave `0x80007CE4` with size 24. That is
  wrong: the first conditional branch in the body jumps to `0x80007CFC`, and the
  block at `0x80007CFC` in turn branches to `0x80007D30`. Both of those addresses
  carry heuristic `func_` labels but neither has a single direct call site
  anywhere in the image, and the block at `0x80007D30` consumes a scaled index
  that is only ever computed inside the block at `0x80007CFC`. They are internal
  arms of one function.
- Corrected USA VRAM range: `0x80007CE4` .. `0x80007D43` (inclusive), 96 bytes.
- ROM offset `0x88E4`, translation unit `main_7BE4.s`.
- Three separate return sites. The first two return in a delay slot that holds
  the value-producing load; the last has an empty delay slot.
- The preceding function ends with its own return at `0x80007CDC`, so
  `0x80007CE4` is a genuine entry.

## Callers

Two direct call sites, both in `main_7BE4.s`: the routine at `0x80007F5C`, which
passes its own first argument straight through, and the routine at `0x80007FC0`.
One integer argument, one integer/pointer result.

## Handle layout

The packing routine at `0x80009118` builds these handles by ORing a value into
bits 24-31, another into bits 16-23, and setting bit 15 as a marker. This routine
is the matching unpacker: bit 15 is the "is a real handle" marker, bits 24-31 are
a small kind selector, and bits 16-23 are an index.

## Recovered behaviour

The routine takes one packed handle word and returns the record it designates.

If the handle does not have bit 15 set it is not a packed handle at all, and the
routine returns the single fallback record pointer held in `D_800AFA54`.

Otherwise it extracts the kind selector, the byte occupying bits 24-31. Kinds 0
and 1 share one pool: for those the routine takes the index byte from bits 16-23
and returns that entry of the `D_8009A32C` word table. Every other kind has one
record per kind rather than a pool, so the routine returns the entry of the
`D_8009A388` word table selected by the kind value itself.

The kind selector is taken as the arithmetic shift of the signed handle followed
by a mask to a byte, so a handle with the sign bit set still yields a value in
0..255. The index byte is extracted the same way.

## Status

Exact, with the boundary corrected from 24 bytes to 96. Byte-identical in USA,
Japan, Europe and lrg_rev1.
