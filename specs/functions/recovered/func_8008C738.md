## Recovered behavior

Converts a 64-bit integer argument to a single-precision floating point result.
This is one of a family of four adjacent conversion helpers (the other three
convert 64-bit signed to double, 64-bit signed to single, and 64-bit unsigned to
double); they are compiler support routines, emitted by the code generator
rather than called from game logic.

The 64-bit argument arrives as two 32-bit halves in the argument registers. The
routine reassembles them into a single 64-bit quantity by writing both halves to
the caller-provided argument home area and reading the pair back as one 64-bit
load, converts that quantity to single precision treating it as signed, and then,
when the quantity's top bit was set, adds 2^32 to the result before returning it.
The correction constant is 2^32 rather than 2^64; the sibling unsigned-to-double
helper applies the same 2^32 correction, so this is a property of the original
runtime and not a reading error. The routine touches only the caller's argument
home slots and adjusts no frame.

## Access widths

Two 32-bit stores into the argument home area, one 64-bit load back out of it,
one signed 64-bit to single-precision conversion, and one single-precision add.

## Status

Behavior recovered; not matchable with this toolchain.

The recovered C expresses exactly the observed computation, and the host gate
accepts it. It cannot be verified byte-for-byte here for a toolchain reason:
the body uses 64-bit integer and 64-bit-to-float instructions, which the accepted
`-mips2` profile cannot emit. Compiled under the accepted profile the same source
becomes a call to the very helper this function *is*, leaving an undefined
`__ll_to_f` reference, so the probe cannot even link. The local IDO 5.3 and 7.1
both refuse `-mips3` outright ("implies -64bit, which is not supported"), and the
`-mips3 -32` combination either drops the 64-bit move to the float unit at `-O2`
or aborts inside the scheduler with an internal assertion. Reproducing this
routine needs a MIPS III code generator that this toolchain does not provide, so
it should stay an assembly unit.
