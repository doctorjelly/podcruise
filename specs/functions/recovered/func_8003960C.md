# func_8003960C — copy one 1008-byte global block over another

## Boundary

- USA VRAM range `0x8003960C` .. `0x8003964B` inclusive, **64 bytes**, ROM
  `0x3A20C`, translation unit `main_18B28.s`. The assignment listed 128, twice
  the true length.
- The body is a five-instruction preamble, a nine-instruction loop, and a return
  whose delay slot is empty. The single backward branch targets an address
  inside the body; nothing branches out of it.
- Six direct call sites target `0x8003960C`, and the preceding function ends
  with its own return at `0x80039608`, so the entry and the extent are both
  confirmed.

## Callers

Six direct call sites, from the routines at `0x8003964C`, `0x80039828` and
`0x800398C0` — all immediate neighbours, which is consistent with this being a
small housekeeping helper local to the same source file. No site sets up
arguments and none uses a return value: the signature is `void (void)`.

## Callees

The two blocks are adjacent: `D_80113A70` is exactly `D_80113680 + 0x3F0`, and

nothing in this function constrains the internal layout further.

## Recovered behaviour

The routine copies the whole of one 1008-byte global block into another,
overwriting the destination completely. It reads and writes nothing else and
returns no value — a snapshot or restore of a fixed block of state.

The emitted loop moves three words per pass and walks a source cursor to a
precomputed stop address. That is the original compiler's inline expansion of a
single whole-object assignment between two objects of this size, not evidence of
a 12-byte record: writing the copy as an element loop over 12-byte records, or
as nested loops, produces visibly different and longer code. Recovering it as
one structure assignment reproduces the register choices and the instruction
order exactly.

## Status

Exact. Byte-identical in USA, Japan, Europe and lrg_rev1, at 64 bytes.
