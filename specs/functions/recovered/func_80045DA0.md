# func_80045DA0

## Boundary

VRAM 0x80045DA0 .. 0x80045E80 (exclusive), ROM 0x469A0, size 224 bytes (56
instructions). The body ends with the return jump and a stack-frame release in
its delay slot. The single direct call site targets 0x80045DA0 exactly, and the
label immediately following (0x80045E80) is itself a separate function with its
own caller, so the boundary is correct.

## Callers

One direct call site, at 0x800461BC, which passes a single pointer and ignores
the result. The very next instruction pair calls func_80045E80 with the same
pointer, so the two routines initialise two different tables of the same owner
object.

## Callees

- `func_80018324(pointer, s32 kind)`. The second argument is stored to the
  callee's offset 0 as a full 32-bit word and compared against a 32-bit
  constant, so it is a word-sized parameter, not a narrow one.

## Globals

None. Everything the routine touches is reached through the pointer argument.

## Owner object fields used

- 0x0BC4 — pointer slot that receives the address of the header record.
- 0x16E0 — array of twelve pointers (48 bytes).
- 0x1710 — twelve records of 0x58 bytes, addressed as six rows of two.
- 0x1B30 — one further record of the same 0x58-byte shape (the header).

Within a record only two fields are written here: a 32-bit count at 0x14 and a
pointer at 0x18.

The Japanese and European entries are not listed in the project's cross-version
table (the shared prologue makes the first thirty-two instructions ambiguous).
They were located by searching for the two distinctive loop bounds, then the
whole body was read at the candidate address and confirmed identical in shape.

## Recovered behavior

The routine builds a twelve-entry collection inside the owner object.

First it initialises the header record with one kind code, records twelve as
its element count, points it at the base of the pointer array, and publishes
the header's address into the owner's pointer slot.

Then, for six groups of two, it initialises each of the twelve records with a
second kind code, clears that record's count and pointer fields, and stores the
record's address into the matching pointer-array entry. The records are laid
out as a two-dimensional table (six rows of two) while the pointer array is
addressed with a flattened index built from the row and column; that
combination is what produces the two independent loop counters in the original.

## Status

Exact in USA, Japan, Europe and lrg_rev1 under the standard IDO 5.3 -O2
profile. No per-unit compiler flags required.
