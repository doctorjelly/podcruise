# func_80089C34

## Boundary

- USA VRAM `0x80089C34` .. `0x80089CBF`, ROM `0x8A834`, 140 bytes (35 instructions).
- Frame of 16 bytes; terminates with `jr $ra` whose delay slot releases the frame.
- The two internal labels are the loop head and the if-skip target, both inside the
  range; all seven direct callers `jal` the entry address.
- Boundary as assigned: correct.

## Callers / callees

- 7 direct call sites (4 distinct callers).
- No callees (leaf) - the eight-byte record copy is expanded inline rather than
  through a library call.

## Recovered behavior

Converts a global table of eight-byte source records into a caller-supplied array
of six-byte output records, one output per source record, for as many records as
the global count byte currently reports. The count is re-read every iteration
because the loop writes through a caller pointer that could alias it.

For each record the routine takes a private copy of the whole eight-byte source
record - the source table is only two-byte aligned, so the copy is done with
unaligned word loads into an aligned stack temporary, and the individual fields are
then read back out of that temporary.

The top two bits of the byte at offset 2 of the record form a small classification
code (the masked bits are shifted down by four, giving 0, 4, 8 or 12). That code is
always stored into the unsigned byte at offset 4 of the output record. Only when the
code is zero - that is, when neither of the top two bits is set - are the remaining
fields copied: the source halfword at offset 4 becomes the output halfword at
offset 0, and the two signed bytes at offsets 6 and 7 become the output signed bytes
at offsets 2 and 3. Records with a non-zero code leave the rest of their output
record untouched.

Both pointers advance every iteration regardless of the branch.

## Notes on shape

Three source-shape details were needed for byte equality, all of them consistent
with documented IDO behaviour:

- the classification code is written into the output field and then that field is
  read back for the zero test, rather than being tested through a named local; the
  compiler forwards the stored register and only masks it for the comparison;
- the source cursor is an explicit pointer variable initialised before the loop,
  which is why the table address is materialised unconditionally ahead of the
  loop guard;
- the local declaration order (counter, record copy, source cursor) fixes where the
  eight-byte temporary lands in the frame.

## Status

`exact` in usa, japan, europe and lrg_rev1.
