# func_800945C0

## Verified facts

- The USA body spans VRAM `0x800945C0` through `0x800947E3`, ROM `0x951C0`,
  548 bytes. The return is at `0x800947DC`; its delay slot is `nop`.
- Callers pass a device-channel handle, transfer direction, device offset,
  DRAM address, and byte count. The fifth argument is read from incoming stack
  offset `0x10`.
- The handle supplies four byte-wide timing values at offsets `0x05` through
  `0x08`, a channel at `0x09`, and a base address at `0x0C`.
- The routine reads and updates `D_800A7BA0`, calls only `func_80088360`, and
  accesses the peripheral-interface registers at `0xA4600000` through
  `0xA4600030`.
- Japan (`0x800952B0`, ROM `0x95EB0`) and Europe (`0x80099B10`, ROM
  `0x9A710`) retain the same 548-byte extent and matching entry/return shape,
  with relocated code and handle-table addresses.

## Behavior

Wait until the peripheral interface is idle. If this handle is not the one
currently programmed for its channel, update only the timing registers whose
byte values differ and cache the new handle. Publish the physical DRAM address
and the masked device address, then start the requested transfer by writing
`size - 1` to the direction-specific length register. Reject directions other
than zero or one with `-1`; otherwise return zero.

## Status

Exact in the canonical USA build. IDO 5.3 `-O1` emits all 548 bytes
identically. The explicit `switch` is significant: an equivalent if/else is
four bytes short and does not reproduce the original branch layout.
