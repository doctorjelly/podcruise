# func_80095820

## Boundary

- USA VRAM 0x80095820..0x800958D4, ROM 0x96420, size 180 bytes (0xB4).
- Ends with the return instruction plus its delay slot popping the 0x18-byte
  frame; the next function starts at the callee it invokes.
- Nine direct call sites target 0x80095820, so the assigned boundary is correct.

## Callers

Nine direct call sites, all in the same translation unit, none of which uses a
result. Several of them write a status word to a global immediately before the
call.

## Callees

- func_800958D4() - no arguments, no result used.

## Globals and access widths

- D_8014D7D4: pointer-sized global holding the base of a record array whose
  elements are 0x14 bytes; the second element's final 32-bit word is read twice.
- D_800A7B50: 32-bit word, read-modify-written once with a bit-set.
- Memory-mapped words at 0xA4600010 (peripheral status/control) and 0xA5000510
  (the peripheral-bus register this routine programs) are accessed as volatile
  32-bit locations.

## Recovered behavior

The routine pokes one command word at the external peripheral device twice,
first with a high control bit forced on and then with the plain value, waiting
for the bus to go idle before each write.

1. Take the second record of the array the global points at; its last word is
   the command value to program.
2. Spin until the peripheral status register reports neither transfer bit set.
3. Write the command value with the top control bit (bit 28) set.
4. Spin again until the status register is idle, then write the command value
   unmodified. The second read of the command word is a fresh read, not the
   value cached from step 3.
5. Call the follow-up helper, acknowledge the peripheral interrupt by writing
   the clear bit to the status register, and finally set three flag bits in the
   32-bit status global.

## Compiler notes

Both spin loops are the ordinary "read once, then re-read while busy" shape;
the hardware locations are plain volatile pointer dereferences built from the
constant addresses.

## Status

Exact in USA, Japan, Europe and lrg_rev1 under the accepted ido53_o2 profile;
no per-unit compiler flags needed.
