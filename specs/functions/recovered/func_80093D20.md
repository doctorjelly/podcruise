# func_80093D20 — whole-cache arm of func_80093CD0, not a function

## Verdict

Not a separate entity. `0x80093D20` is the whole-cache arm of
`func_80093CD0`, the instruction-cache range invalidation routine. It is a
label only because the neighbour branches to it across the neighbour's own
return. The specification belongs with `func_80093CD0`, which already carries
it; this file records the classification.

## Boundary

- USA VRAM `0x80093D20` .. `0x80093D43` inclusive, ROM `0x94920`, 36 bytes,
  nine instructions. The extent ends with the return instruction and an empty
  delay slot; padding words follow.
- The extent is right and the classification is wrong: this is an arm, not an
  entry point.

## Why this is an arm and not a function

1. **No caller.** No call instruction in the USA image targets `0x80093D20`.
   The only in-bound edge is one conditional branch inside `func_80093CD0`,
   taken when the requested length is not smaller than the whole instruction
   cache.
2. **It depends on the neighbour's register state.** The cache-size constant
   that bounds the sweep is materialised by `func_80093CD0` before the branch
   and merely survives into this range. Nothing here produces it.
3. **No parameters; it returns on the neighbour's behalf** through the link
   register supplied by the neighbour's caller.
4. **Three exits, one call.** Early-out, bounded walk, and this sweep are the
   three ways `func_80093CD0` finishes a single invocation.

The one structural difference from the two data-cache pairs is the geometry:
this arm steps thirty-two bytes at a time rather than sixteen, and its parent's
threshold is twice as large, because the instruction cache is twice the size of
the data cache and has twice the line length.

## Callers

None. One in-bound branch edge from `func_80093CD0` at `0x80093CE0`.

None.

Read independently in all four versions; word-for-word identical, each

## Recovered behavior of the arm

Reached when the caller of the parent routine asked to invalidate an
instruction-cache range at least as large as the cache itself. Instead of
walking the requested range, this arm starts at the base of the cached view of
memory and visits every instruction-cache line in turn, thirty-two bytes apart,
discarding each one, stopping after the last line the cache holds. It then
returns to the parent's caller.

The operation used here only discards; unlike the data-cache arms there is
nothing to write back, because the instruction cache is never written by the
processor.

## Status

Skipped, permanently, and it should not be on the decompilation queue.

The loop body is the processor's cache maintenance operation, which the
accepted compiler cannot emit from C, and inline assembly is forbidden by the
project rules. Beyond that, the range is not a compilation unit at all: it has
no entry, no parameters and no prologue, and it reads a register established
inside a different labelled range.

Recommendation for the orchestrator: drop `func_80093D20` from the queue and
carry `0x80093CD0` .. `0x80093D43` as one hand-written assembly unit of 116
bytes (80 + 36). The `externs` list on the `func_80093CD0` result, which
currently names `func_80093D20`, becomes unnecessary once the two are one unit.
