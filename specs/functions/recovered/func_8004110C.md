# func_8004110C

## Boundary

- USA VRAM `0x8004110C` - `0x80041210`, ROM `0x41D0C`, 264 bytes
  (66 instructions). Ends with the return whose delay slot holds the final
  float store. Boundary as assigned; no correction.
- Leaf function: no frame, no calls.

## Callers / callees

- 6 direct call sites; no callees; no globals.

## Parameters

- Argument 1: pointer to a large object (at least 0x2A4 bytes).
- Argument 2: a 32-bit value stored into the object at +0x7C.

## Recovered behaviour

The routine snapshots two blocks of sixteen 32-bit floats inside one object and
records a 32-bit value.

1. The sixteen floats at +0x20 through +0x5C are copied to +0x224 through
   +0x260.
2. The sixteen floats at +0x108 through +0x144 are copied to +0x264 through
   +0x2A0.
3. The second argument is stored as a 32-bit word at +0x7C.

Both blocks are copied element by element in ascending order; every access is
made through the single object pointer with constant offsets, which is what
lets the compiler batch six loads and then six stores at a time using six
floating-point temporaries.

## Regional addresses

- Japan: VRAM `0x80041914`, ROM `0x042514`.
- Europe: VRAM `0x80045AAC`, ROM `0x0466AC`.
- lrg_rev1 shares the USA address.

## Status

Behaviour recovered; not byte-identical. The recovered C compiles to exactly
264 bytes with exactly the same instructions, the same six-at-a-time batching,
the same floating-point register assigned to every element, and the word store
in the same position. The only difference is the order in which the loads and
stores are emitted inside each batch: the original issues the two elements that
reuse the just-freed registers before the elements that take fresh registers,
while the straightforward source yields ascending order. Loop forms (flat or
nested), structure assignment and two-dimensional subscripts were all ruled out
by measurement: loops stay loops, and structure assignment is expanded with
integer registers.
