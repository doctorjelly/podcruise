# func_80073C58

## Boundary

- USA VRAM range: 0x80073C58 .. 0x80073CCF inclusive (0x78 = 120 bytes,
  30 instructions).
- USA ROM offset: 0x74858.
- Ends with a return whose delay slot moves the working value into the float
  return register, so that move is part of the function.
- The stack pointer is never adjusted; every stack reference is to a
  caller-provided argument home slot, so there is no frame and no local
  storage.
- Assigned size 120 was correct; no boundary correction.

## Callers and callees

- One direct call site in the USA build. It writes two floats into the fifth
  and sixth outgoing argument slots on the stack immediately before the call,
  and loads the third and fourth arguments as raw words into the third and
  fourth integer argument registers.
- No callees (leaf function).

## Arguments and return

Six 32-bit float arguments. The first two arrive in the two float argument
registers; the third and fourth arrive in the third and fourth integer
argument registers and are moved to float registers through their home slots
(the standard O32 handling of float arguments in slots three and four); the
fifth and sixth are read straight out of the outgoing argument area at offsets
0x10 and 0x14. Returns a 32-bit float.

## Globals and access widths

None. The function is pure: it touches no memory other than its own argument
home slots.

## Regional addresses

The body is instruction-for-instruction identical in every version, and there
are no relocations at all, so the 120 bytes are literally the same in every
ROM.

| version  | VRAM       | ROM     |
|----------|------------|---------|
| us       | 0x80073C58 | 0x74858 |
| jp       | 0x80074888 | 0x75488 |
| eu       | 0x80079138 | 0x79D38 |
| lrg_rev1 | 0x80073C58 | 0x74858 |

## Recovered behavior

Constrains a candidate value to a window and then to a hard range, returning
the constrained result. Reading the six arguments as (value, centre, low,
high, forward slack, backward slack):

1. The value is capped so it never exceeds the centre plus the forward slack.
2. The value is then raised so it never falls below the centre minus the
   backward slack.
3. The value is raised again so it never falls below the low limit.
4. Finally it is capped so it never exceeds the high limit.

The four steps are applied strictly in that order, which matters: the window
around the centre is applied first and the absolute limits win over it, so a
window that lies entirely outside the limits is pulled back inside. Each of the
first three tests is emitted as a conditional-move-style compare with the
following comparison hoisted into the branch delay slot, which is what the
compiler produces for four ordinary `if (a < b) x = b;` statements written back
to back over the parameter itself; keeping a separate local for the running
value instead adds a redundant move.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
