# `func_80016A20` USA stack-layout audit

The current C body is 468/468 bytes but differs from the canonical USA ROM
in 20 words, first byte `0x03`. Every differing word is a stack/frame
immediate. The ROM uses a `0xC8` frame with the pivot work area at `sp+0xB4`,
the three-float vector at `sp+0xA8`, and the basis array beginning at
`sp+0x68`. Current C uses a `0xD0` frame; its aggregate addresses are eight
bytes higher.

The recovered callees `func_80016260` and `func_800167E4` use exactly three
`s32` pivot indices. Replacing the caller's 20-byte opaque work struct with
`s32 work[3]` (12 bytes) and the corresponding pointer prototypes fixes the
frame size and reduces the mismatch to 16 words. All 16 are still aggregate
stack offsets exactly `+8` relative to the ROM; the first is at byte `0x0B`.
An equivalent 12-byte struct produces the same result.

All six aggregate declaration orders were tested with both the original
20-byte struct and the typed 12-byte array. The former kept 20 differences;
the latter kept 16. Two scalar-block placements did not match. An unused
eight-byte local before the typed work area restored the old `0xD0` frame
and 20 differences. No variant was exact; all source experiments were
reverted and the parent reran the original 468/468, 20-word comparison.

Do not repeat local-order or simple padding sweeps without new evidence for
why the original compiler placed the aggregate group eight bytes below the
same-sized C frame.
