# func_800894D0

## Verified facts

- The true USA body spans VRAM `0x800894D0` through `0x8008956B`, ROM
  `0x8A0D0`, 156 bytes. `func_80089548` is the signed-index loop tail reached
  by a backward branch, not a separate function.
- Success returns at `0x80089540` and exhaustion returns at `0x80089564`; both
  `jr ra` delay slots are `nop`. The word at `0x8008956C` is alignment padding.
- `func_80007FC8` is the sole direct caller. It supplies the global table
  pointer and one item pointer. There are no callees or global references in
  this routine itself.
- The table holds a slot pointer at `0x40` and signed count at `0x44`. Each
  48-byte slot uses fields `0x1C`, `0x20`, `0x24`, `0x28`, `0x2C`, `0x2E`, and
  `0x2F`; the item contributes its unsigned byte at `0x0D`.
- Japan maps to `0x8008A1C0` / ROM `0x8ADC0`; Europe maps to `0x8008EA20` / ROM
  `0x8F620`. Their next mapped entries have the same 160-byte spacing,
  including the final padding word.

## Behavior

Scan the table's 48-byte records using a signed 16-bit index. On the first
record with no owner, attach the supplied item, select state five, initialize
its scalar and flag fields, derive a 16-bit angle-like value from the item's
byte, and return the record index. Return minus one when every record is busy
or the table count is nonpositive.

## Status

Behavior recovered, not byte-matching. A linked IDO 5.3 `-O2` comparison emits
the correct 156-byte size and the same control-flow and store layout, but the
first difference is byte `0x1`: the original assigns the count, slot pointer,
and index to `a2`, `v0`, and `v1`, while the isolated source assigns them to
`v0`, `v1`, and `a2`. Three evidence-driven source forms retained that broad
register-coloring difference, so no exact claim is made.
