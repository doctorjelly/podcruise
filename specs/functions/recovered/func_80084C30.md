# func_80084C30

## Boundary

- USA VRAM `0x80084C30` .. `0x80084CC0` inclusive, ROM `0x85830`, size 148 bytes
  (37 instructions).
- Terminates with `jr $ra` whose delay slot performs the last field store.
- The preceding function returns at `0x80084C24` and is followed by one padding
  word; the single call site reaches `0x80084C30` with a direct `jal`. The
  assigned boundary is correct.

## Callers

One direct call site, at `0x80084E30`, which loads the argument with a signed
half-word load - independent confirmation that the parameter is a signed 16-bit
value.

## Callees

None; no frame is set up. The argument is written to its caller-provided home
slot, which is what the compiler does for a sub-word parameter, and the value is
then sign-extended from 16 bits before being compared.

The descriptor pointer is re-read from `D_801488C0` before every single field
store, so each store in the source is written through the global rather than
through a cached local.

Field offsets written: `0x08`, `0x0C`, `0x10`, `0x18`, `0x28`, `0x2C`, `0x30`.

### The two symbols at `0x800980C0`

The address `0x800980C0` is materialised twice, once for a subtraction and once
for a field store, and the compiler did *not* share the two computations even
though they are in the same straight-line region and the value is loop
invariant. That only happens when the two uses name different C objects, so the
original source refers to two distinct symbols that happen to resolve to the
same address: the end of the blob beginning at `func_80097FF0` coincides with
the start of the blob at `0x800980C0`.

The recovered source therefore declares a second symbol, `D_800980C0_2`, which
the orchestrator must bind to `0x800980C0` (and to the corresponding regional
address). Declaring only one symbol and using it twice compiles to 140 bytes
instead of 148 because the address computation is shared.

## Interface

One signed 16-bit value selecting a mode. Nothing is returned.

## Recovered behavior

The routine fills in the fixed parts of a task descriptor held behind a global
pointer, in preparation for handing that task to the coprocessor.

It records the address of the bootstrap blob and the blob's length, the latter
computed as the distance between the blob's end symbol and its start. It then
copies three pointer-sized values that other code has parked in globals into the
descriptor's buffer and payload fields.

Only when the mode selector equals 5 does it additionally install the main
program blob and its data blob into the descriptor; for every other mode those
two fields keep whatever they already held. The payload pointer field is written
last, unconditionally.

## Status

Exact in all four versions. Two experiments: the first assumed a single symbol at
`0x800980C0` and came out 8 bytes short, the second split it in two.
