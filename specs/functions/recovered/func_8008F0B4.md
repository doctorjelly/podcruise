# func_8008F0B4

## Boundary

USA VRAM 0x8008F0B4-0x8008F348 inclusive, ROM 0x8FCB4, 664 bytes, 166
instructions. The assigned label-scan size is correct.

Checks performed:

* the body ends with a return instruction whose delay slot is empty, and no
  branch inside the body targets anything past that return;
* all four direct calls target 0x8008F0B4, the address of the frame setup;
* the preceding routine (0x8008EEE4, 464 bytes) ends with its own complete
  return sequence immediately before this label, so nothing falls through into
  it;
* no executed instruction precedes the frame adjustment.

Frame is 0x20 bytes: 0x14 bytes of outgoing-argument space (the widest call
made from here passes five arguments), padding, and one slot for the return
address. No callee-saved register is saved or restored.

## Why this looked like hand-written assembly, and why it is not

Every input arrives in an unusual register: the object pointer, the two cursor
pointers, the sample count and a pass-through selector in callee-saved
registers, and the command-list pointer in a *scratch* register that all four
call sites load immediately before the call and hold live across it. Three more
callee-saved registers are written without ever being saved.

That is ordinary compiler output from a translation unit built one optimisation
level above the rest of the ROM. At that level the compiler allocates registers
across every function of a unit at once, so a file-local routine whose call
sites are all visible takes its arguments wherever the allocator wanted them,
clobbers callee-saved registers its caller will reload anyway, and is emitted
with no symbol at all. The sibling routine at 0x8008E420 was proved to be
exactly this, and this body is the clearest instance: no hand-written helper
needs an argument in a caller-saved scratch register that the caller keeps
live, and no ordinary caller could supply one.

Compiling the recovered source that way reproduces the frame, the length, the
register assignment of all six inputs, and 160 of the 166 instructions.

The specific choice of registers is itself explained by the unit: the routine
avoids the three lowest callee-saved registers for anything that has to survive
a call, because the file-local routine at 0x8008EEE4 that it calls twice
destroys exactly those three and takes its own pointer argument in the middle
one. Reproducing the assignment therefore needs both routines and a caller in
one unit.

## Callers

Four direct calls, all inside the 1352-byte routine that begins at 0x8008F3FC
(0x8008F604, 0x8008F7FC, 0x8008F85C, 0x8008F8E4). Every site sets up the same
six values from its own frame immediately before the call and stores the
returned pointer back into the same frame slot it took the incoming pointer
from, so the result is always consumed.

## Callees

* an indirect call through a routine pointer read at offset 0x4 of the object
  reached through the voice's field 0x00, taking five arguments (that object,
  the input cursor, the sample count, the pass-through selector, and the
  current end of the command list) and returning a command-list pointer;
* the file-local routine at 0x8008EEE4, called twice, taking an integer, two
  doubles and a pointer it writes a 16-bit value through, and returning a
  16-bit result;
* func_80088360, called once on each path, converting a stored address to a
  physical address.

## Globals and access widths

D_800A7D80, a table of signed 16-bit values, read twice: once at a supplied
index and once at the mirror position 127 minus that index. The second access
is expressed by the compiler as an offset from the address of element 127,
which is why the generated listing shows a second symbol at D_800A7D80 + 0xFE.

The voice object is read and written as follows: field 0x00 a pointer, 0x14 a
32-bit address, 0x18 through 0x2E signed 16-bit values (0x24 and 0x2A are also
read as unsigned when packed into a command word), 0x30 a 32-bit running
total, 0x34 a 32-bit value passed on, 0x38 a 32-bit flag that is tested and
cleared, and 0x48 a 32-bit state word that is only tested.

Both cursors are single signed 16-bit values behind pointers; the first is read
once and increased, the second is read three times and never written.

## Regional addresses

* Japan 0x8008FDA4, ROM 0x909A4
* Europe 0x80094604, ROM 0x95204
* lrg_rev1 0x8008F0B4, ROM 0x8FCB4

All three bodies were read independently and compared with the USA body over
the full 664 bytes. lrg_rev1 is byte-identical. Japan and Europe differ in
exactly eight words, all of them relocations: the two halves of the table
address, the two calls to the routine at 0x8008EEE4, and the two calls to
func_80088360. Every other instruction, including all displacements and branch
offsets, is identical, so the three regions were built from the same source.

## Recovered behaviour

The routine appends a short burst of eight-byte command words to a growing
audio command list for one voice, and returns the position just past the last
word it wrote.

It does nothing unless the voice's state word holds the single value this
routine handles and the requested sample count is non-zero; when either fails
it returns the command list unchanged.

Otherwise it first asks the voice's source object, through the routine that
object carries, to stage the samples. That request is given the source object,
the input cursor, the sample count, a selector passed straight through from the
caller, and the current end of the command list; it hands back the position
from which this routine continues writing.

Two commands then describe the buffers for the step that follows. The first
selects the current input position as the source, a fixed distance above the
second cursor as the destination, and a length of twice the sample count. The
second selects three further fixed distances above the same cursor.

If the voice's "levels are stale" flag is set, the flag is cleared and both
output levels are recomputed. An index carried by the voice selects an entry of
the shared table for one channel and the mirror entry for the other; each entry
is multiplied by the voice's overall level and the product scaled down by
fifteen bits. Each new level, paired with the level currently in effect for
that channel, is then handed to the helper routine, which stores a fractional
per-sample step into the voice and returns the whole part of that step, which
is stored as well.

When the levels were recomputed, five level commands follow: one for each of
the two levels currently in effect, one for each of the two newly computed
levels carrying its whole and fractional step, and one more carrying a further
pair of values the voice holds. The burst then ends with a mixing command
marked to restart, carrying the physical address of the voice's working block.
When the levels were not recomputed, only that mixing command is appended, with
the plain marker and the same address.

Finally the input cursor is advanced by twice the sample count, the voice's
running total is increased by the sample count, and the new end of the command
list is returned.

## Status

Behaviour recovered and reviewed; not byte-exact.

Built with the original compiler at the optimisation level this unit needs, the
recovered source produces a body of exactly the right length (664 bytes) with
the identical frame, the identical register assignment for all six inputs and
for every long-lived value, and the identical sequence of operations. 135 of
the 166 instructions are byte-identical and 160 of 166 are identical apart from
which of the four rotating scratch registers a temporary landed in.

Exactly six instructions are in a different order, in three places, and all
three are the compiler choosing a different instruction to fill a slot:

* the third level command computes its first word before it copies the running
  command pointer; the recovered source copies the pointer first (two
  instructions exchanged). This alone rotates the scratch-register choice for
  the remaining 50 instructions, which is where most of the 53 differing bytes
  come from;
* on each of the two paths that end in the address conversion, the original
  puts the pointer advance in the call's delay slot and loads the call's
  argument before the call, while the recovered source does the opposite (two
  instructions exchanged on each path).

Over forty source shapes were tried against these three sites - pointer
increment idioms, separate versus shared command-pointer variables, statement
order, the position of the pointer advance, unsigned-cast versus mask forms,
u32 versus struct command pointers, a merged tail with a flag variable, an
inlined helper taking the pointer last, and both parameter orders - and none
moved them. Four source shapes found earlier did move the equivalent problems
and are in the delivered source: the two early exits share one condition and
one return; the object pointer is read into a local before the test; the call
that stages the samples takes the command list as a fifth argument, which is
what puts it in a scratch register and gives the frame its size; and every
sixteen-bit field packed into the high half of a command word is masked before
it is shifted, which is the shape the original's macro must have had.
