# func_80034DA8

## Boundary

- USA VRAM range: 0x80034DA8 .. 0x80034E1F inclusive (0x78 = 120 bytes, 30 words).
- ROM offset 0x359A8. Entry is a `glabel` immediately after the end of
  func_800349C4; no instruction of the preceding function branches past its own
  return into this range.
- The body terminates with a return whose delay slot is the last of the three
  packet stores, so the final store is executed before control leaves.
- The assignment's size (120) was confirmed correct; no boundary correction.

## Callers

Three direct call sites, in two functions:

- func_800374C4 at 0x800375A4 and 0x8003790C
- func_80038388 at 0x80038474

## Callees

None. The function is a leaf.

## Globals and access widths

| symbol | width | direction |
| --- | --- | --- |
| D_800A3FF8 | 32-bit word | written (cleared to zero) |
| D_80112C90 | 32-bit pointer variable | read and written, three times each |
| D_801134D0 | 32-bit word | read once |
| D_801134D4 | 32-bit word | read once |

D_80112C90 holds a write cursor into a graphics command buffer. The generated
code takes the address of this global into a register once and reuses it, which
is what a single variable referenced repeatedly produces.

## Recovered behavior

The function clears the flag word D_800A3FF8 and then appends three eight-byte
command packets to the buffer that D_80112C90 points at, advancing the cursor by
one packet each time.

1. The first packet pairs the constant command word 0xDA380003 with the pointer
   value currently stored in D_801134D0.
2. The second pairs the constant 0xDC38000E with the value in D_801134D4.
3. The third pairs the constant 0xDB0C0000 with the constant 0x00010000.

Each packet is written after the cursor has already been advanced, so the cursor
in memory always names the next free slot even between the two word stores of a
packet. Nothing is returned.

## Source shape notes

Byte equality required each packet to be emitted inside its own brace-enclosed
block whose local pointer is initialised from a post-increment of the global
cursor; a single function-scope pointer variable reused three times produces the
same behaviour but a different register assignment. The three statements of the
last block additionally had to sit on one source line: spreading them across
three lines changes which of the two final stores IDO puts in the return delay
slot, and nothing else.

## Status

Exact on us, jp, eu and lrg_rev1.
