# func_80005B44

## Boundary

- USA VRAM range: 0x80005B44 .. 0x80005B74 inclusive (0x34 = 52 bytes,
  13 instructions), followed by two padding words that align the next function.
- USA ROM offset: 0x6744.
- Contains three separate returns; the last one's delay slot is empty.
- **Boundary corrected.** The assignment file gave size 20. The generated
  disassembly splits this function into three labels (0x80005B44, 0x80005B58,
  0x80005B70) because the splitter starts a new label after every return, but
  the two later labels have zero direct call sites and are only reached by
  branches from inside the first block. The true function is all 52 bytes.

## Recovered behavior

A small selector-driven getter. It matches the argument against two known
selector values: selector 3 returns the first stored word, selector 5 returns
the second. Any other selector yields -1, and that failure value is prepared
unconditionally on the way to the second test rather than only on the failing
path.

## Status

Already recovered. This function was already implemented, byte-exact, by
another worker's file `src/functions/func_80005B1C.c` (which defines the
matching setter `func_80005B1C` alongside it) and is already registered in
`config/c_matching.json` under unit id `func_80005B1C` with size 52.

Verified independently here rather than duplicated: USA, Japan and Europe all
compile byte-identical at 52 bytes from that existing source. No new file was
created, because a second definition of the symbol would break the host link
and the brief forbids editing another worker's source.
