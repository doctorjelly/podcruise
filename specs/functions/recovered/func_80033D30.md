# func_80033D30 — install the second menu page's descriptor and layout constants

## Boundary

- USA VRAM range 0x80033D30 .. 0x80033DC3 inclusive, 148 bytes (0x94).
- Starts immediately after the previous function's return; ends with the return
  jump whose delay slot performs the last float store. Nothing branches into the
  range from outside.
- Boundary as assigned is correct; no correction needed.

## Callers

One call site (VRAM 0x80033D64 in the USA build). It is the sibling of
func_80033C70: the same caller tests bit 0x800 of the same flag word and calls
this function when that bit is set.

## Callees

None. The function is a leaf and takes no arguments.

## Globals and access widths

- `D_800A31E0` — same descriptor table as func_80033C70, written as 32-bit
  words at byte offsets 0x47C, 0x480, 0x484, 0x48C, 0x490 and 0x4A8.
- `D_800A5CA0` — same layout table, written as 32-bit floats at byte offsets
  0x978, 0x97C, 0x980, 0x984, 0x988 and 0x98C.
- `D_800AA650`, `D_800AA654` — only their addresses are taken.
- `D_800AAAB4`, `D_800AAAB8`, `D_800AAABC`, `D_800AAAC0`, `D_800AAAC4`,
  `D_800AAAC8` — each read once as a 32-bit float.

`void func_80033D30(void)`

Japanese symbol correspondence: D_800A31E0 -> D_800A5F50,
D_800A5CA0 -> D_800A8AF4, D_800AA650 -> D_800AD6F8, D_800AA654 -> D_800AD700
(the two payload objects are eight bytes apart in japan rather than four),
D_800AAAB4..D_800AAAC8 -> D_800ADB64..D_800ADB78 in the same order.

The European build again has no corresponding function of this shape; its
counterpart begins at VRAM 0x8003737C and is 272 bytes because it chooses the
payload addresses from a language-selection word. Europe is excluded.

## Recovered behaviour

The function is the exact structural twin of func_80033C70, applied to a second
entry of the same two tables.

It writes three consecutive small identifiers — 0x11D, 0x11C and 0x11F — into
the descriptor table, then the addresses of two static payload objects into the
next pair of slots but one, then a fourth identifier 0x121 at a slot further on.
The identifiers are exactly two higher than the ones the first page installs and
occupy offsets exactly 0x2D8 bytes further into the same table, which is what
identifies the table as an array of fixed-size page descriptors.

It then copies six tuned single-precision constants into the layout table. Three
of them go to one run of slots and the other three go to a run that starts three
slots earlier; the compiled order writes the later run first, which is simply
the order the assignments appear in and has no observable consequence because
every destination is distinct.

There is no conditional logic, no read-back and no return value.

## Status

Exact. Byte-identical in usa, japan and lrg_rev1. Europe deliberately excluded
(structurally different function).
