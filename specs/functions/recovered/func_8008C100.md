# func_8008C100 — scan a run of eight-byte records for the first hit

## Boundary
- USA VRAM 0x8008C100 .. 0x8008C18B (140 bytes, ROM 0x8CD00).
- Ends with the return instruction plus an empty delay slot; the frame of 32
  bytes is released immediately before it.
- Boundary confirmed: the single direct call site targets 0x8008C100, the
  preceding function ends before it, and the frame adjustment is the first
  executed instruction. Not corrected.

## Callers
One direct call site, inside the wrapper at 0x80039340. That wrapper validates
that its byte count is a multiple of eight and that both the starting index and
the index one past the end fit in the permitted range, then calls this function
with a fixed table pointer, the starting index reduced to a single byte, its
own first argument, and the byte count. The wrapper keeps the returned value
and hands it back to its own caller, so the result is meaningful.

## Callees
- `func_80094C80(table, index, record)` — three arguments; treats the second
  as a byte-wide index. Returns zero on success and a non-zero status
  otherwise.

## Globals and access widths
None.

## Arguments
1. a pointer to the table/handle the per-record routine works on;
2. an unsigned byte index of the first record (read back from its home slot
   with a byte load and incremented with a byte store, so it is genuinely
   byte-wide);
3. a pointer to the first eight-byte record;
4. a signed byte count, tested against zero with a signed comparison.

## Regional addresses
| version | entry | rom | callee |
|---|---|---|---|
| us | 0x8008C100 | 0x8CD00 | func_80094C80 |
| jp | 0x8008CDF0 | 0x8D9F0 | func_80095970 |
| eu | 0x80091650 | 0x92250 | func_8009A1D0 |
| lrg_rev1 | 0x8008C100 | 0x8CD00 | func_80094C80 |

All three regional bodies were read independently and match the USA shape
instruction for instruction apart from the relocated callee address.

## Recovered behavior
A status value is set to zero. While the remaining byte count is positive, the
per-record routine is called on the current record with the current byte index.
If it reports a non-zero status the loop stops immediately and that status is
returned. Otherwise the remaining count is reduced by eight, the byte index is
advanced by one, the record pointer is advanced by eight bytes, and the loop
repeats. If the count was not positive on entry, or the loop ran to completion
without a failure, zero is returned.

## Status
Exact under IDO 5.3 with the accepted flag list but `-O2` replaced by `-O1`.
Every local is spilled to the frame and re-read in each basic block, the byte
index round-trips through memory on every iteration, and no callee-saved
register is used — the established `-O1` fingerprint for this area of the ROM
(the same profile that `func_8008C900` needed). Under `-O2` the behaviour is
identical and the size is right, but the compiler promotes the four live values
into callee-saved registers and the body diverges from offset 0x3.
Verified byte-identical in us, jp, eu and lrg_rev1 under the `-O1` profile.
