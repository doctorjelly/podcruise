# func_8006E6F8

## Verified facts

- The canonical USA body begins at VRAM `0x8006E6F8`, ROM `0x6F2F8`, and is
  `0x1310` (4,880) bytes. Its `jr ra` is at `0x8006FA00`; the delay slot at
  `0x8006FA04` is a `nop`.
- The only direct recovered caller is `func_8006FB00`. It invokes this routine
  for an active object whose mode flags select the control path. The object
  contains control flags at `0x60/0x64`, output values at `0x18C/0x1F0`,
  controller state at `0x1E70`, and timing fields at `0x2F4/0x2F9`.
- The one computed switch accepts controller modes `0..8`. The nine words read
  from the local USA ROM at `0xAE348` send modes `0..7` to `0x8006E7D4` and
  mode 8 to `0x8006E9B0`. Every target and the `jr` delay slot were checked.
- The body makes 19 static calls. Both compiler candidates retain the exact
  canonical target order: input-state update, collision helpers, event
  delivery, one effect helper, one random draw, three voice alternatives,
  two common updates, a later random draw, request update, sound, and three
  directional-state alternatives.
- JP `func_8006F268` at ROM `0x6FE68` and EU `func_80073BD8` at ROM `0x747D8`
  are also exactly `0x1310` bytes. Both have the same first eight instruction
  words and the same final stack restore, `jr ra`, and `nop` delay slot as USA.
  They were used only as structural confirmation.

## Behavioral specification

Translate the current controller packet into an object's acceleration,
steering, braking, and transient control flags. Clear stale controller bits,
read the selected input bank, account for the alternate handedness mode, and
detect held, released, repeated, and paired inputs. A debug input mode combines
two controller banks into the same logical values.

Pass those values through the already recovered charge and collision helpers.
Collision state can suppress a pending action, bias steering, and alter
acceleration. Repeated input may create an effect and choose one of three voice
patterns. Two small tagged messages notify object listeners about snap and
button events, while common helpers update collision channels before the final
control calculation.

For an actively racing object, update latched flags, calculate acceleration,
fade the braking amount, select a directional target, and curve the steering
input around its dead zone. Apply the high- and low-axis attenuation factors,
enforce the minimum acceleration required by the charge state, and finish with
the output scale set to one.

## Inferences and recovery notes

- Local names such as `primaryActive`, `brakeActive`, and `steering` describe
  observed use, not authored game symbols. Address-based function and field
  names remain unchanged where semantics are not established.
- `func_8006E42C` receives only the object and controller index. The live
  `a2/a3` values at its call are not arguments; its recovered body proves the
  two-argument contract.
- The call to `func_8006E034` occurs once. A mechanical control-flow draft
  duplicated it, but the USA body has one `jal` at `0x8006EFEC`.
- At `0x8006F5D0` and `0x8006F73C`, the ROM constructs `0.5f` and `0.0f` and
  compares them. The recovered behavior simplifies the resulting always-false
  tests while preserving the selected branches.
- A local `m2c` run was used only to expose the large control-flow graph after
  supplying the ignored jump table. Types, helper contracts, input states,
  delay slots, call count, and retained behavior were checked independently
  against the USA assembly and recovered neighboring functions.
