# func_80073834

## Boundary

USA VRAM 0x80073834 - 0x800738D3 inclusive (160 bytes, 40 instructions), ROM
0x74434. The body ends with a return whose delay slot is empty. The single
direct call site targets 0x80073834, and the caller guards the call on the same
pointer field the routine tests first. All internal branches land inside the
range. Boundary as assigned is correct.

## Callers

One direct call site, at 0x80073834's caller 0x8007AD9C, which passes the
object it is updating as the only argument. That caller checks the object's
pointer at offset 0x344 for null before calling, so the routine's own null
check is redundant at that site but is still present in the code.

## Recovered behavior

The routine advances up to five per-object timers by a common increment,
skipping any timer whose descriptor flag is clear.

The increment is the float at offset 0x250, read exactly once at entry and held
for the whole routine.

If the descriptor pointer at offset 0x344 is null the routine returns without
touching anything.

Otherwise it works through five consecutive descriptor flags, at descriptor
offsets 0x04, 0x08, 0x0C, 0x10 and 0x14, pairing them in order with the object
floats at offsets 0x3C8, 0x408, 0x448, 0x488 and 0x4C8. For each pair, if the
flag is non-zero the corresponding float has the increment added to it;
otherwise that float is left untouched. The five tests are independent - a
cleared flag skips only its own timer.

One detail matters for reproducing the original: the descriptor pointer is
re-read from offset 0x344 after every timer that is actually advanced. That is
a natural consequence of writing each flag test as a fresh dereference of the
object's pointer field, because the float store may alias the pointer field as
far as the compiler can tell. Caching the descriptor pointer in a local would
remove those reloads.

## Status

Exact on USA, Japan, Europe and lrg_rev1.
