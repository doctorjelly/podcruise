# func_8000AB24 — object colour setter

## Boundary

- USA VRAM range: `0x8000AB24` .. `0x8000ABD3` (inclusive), **size 176 bytes**,
  44 instructions, ROM `0xB724`.
- The body has three separate return points. The last one is at
  `0x8000ABCC`; its delay slot is a `nop`. The two earlier return points end
  the first and second conditional blocks and each carry a byte store in the
  delay slot.
- **Boundary corrected.** The assignment listed the function as 88 bytes
  (`0x8000AB24` .. `0x8000AB7B`). The heuristic labels `func_8000AB7C`
  (0x28 bytes) and `func_8000ABA4` (0x30 bytes) are *not* functions: neither
  has a single direct call site anywhere in the USA image, and each is the
  fall-through/branch target of the conditional test immediately preceding it
  inside `func_8000AB24`. The three fragments form one if/else-if chain with a
  common argument set-up prologue that is only executed once. The corrected
  extent runs to `0x8000ABD4`, where the next real function
  (`func_8000ABD4`, 13 direct callers) begins. 176 = 88 + 40 + 48.

## Callers

291 direct call sites in the USA image. Sampled sites confirm five arguments:
four in the argument registers and a fifth pushed into the caller's outgoing
argument area at offset 0x10, so the function has arity 5. Observed argument
one values include the sentinel constants used by the two special cases below.

## Callees

None. This is a leaf function; it makes no calls and allocates no stack frame
(it writes only to the caller-provided argument home slots).

## Globals and access widths

| symbol | access | note |
|---|---|---|
| `D_8009B77C` | four byte stores at +0, +1, +2, +3 | 4-byte colour record |
| `D_8009B780` | four byte stores at +0, +1, +2, +3 | 4-byte colour record, adjacent to the above |
| `D_800D2190` | element stride 32 bytes; four byte stores at element offsets +0x18..+0x1B | table of 32-byte object slots |

The fifth argument is re-read from its incoming stack home slot as a single
unsigned byte (the low byte of the word) separately in each of the three
blocks.

addresses.

## Recovered behaviour

The routine assigns a four-component colour (three colour channels plus a
fourth trailing component) to one of three destinations, chosen by a signed
16-bit selector supplied as the first argument. The four colour components are
unsigned 8-bit values; the first three arrive in the ordinary argument
positions and the fourth arrives on the stack.

- Selector value -103 writes the four components into the standalone 4-byte
  record `D_8009B77C`.
- Selector value -104 writes them into the adjacent standalone 4-byte record
  `D_8009B780`.
- Any non-negative selector treats it as an index into the 32-byte-per-entry
  object table `D_800D2190` and writes the four components into the four
  consecutive bytes starting at offset 0x18 of that entry.
- Any other negative selector (i.e. negative but neither sentinel) does
  nothing at all and the routine returns without touching memory.

The three cases are mutually exclusive and evaluated in that order. Nothing is
returned.

## Status

Exact. Byte-identical against USA, Japan, Europe and lrg_rev1 at 176 bytes,
first attempt, no experiments needed.
