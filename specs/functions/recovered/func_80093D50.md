# func_80093D50

## Boundary

USA VRAM 0x80093D50-0x80093DA8, ROM 0x94950, size 88 bytes (22 instructions).
The body ends with a return whose delay slot is empty. The single direct call
site targets 0x80093D50, and no branch from the preceding function reaches into
this range, so the assigned boundary is correct.

## Callers / callees

One caller (inside the early hardware bring-up path at 0x8008B700). No callees;
this is a leaf.

## Globals

None. The routine only touches processor control registers.

## Regional addresses

- Japan: 0x80094A40, ROM 0x095640, same 88-byte body.
- Europe: 0x800992A0, ROM 0x099EA0, same 88-byte body.
- lrg_rev1: shares the USA addresses.

## Recovered behaviour

The routine installs one fixed entry in the processor's address-translation
table so that a high, otherwise unmapped virtual window is redirected onto the
first physical page. It saves the current translation-context register, selects
a fixed table slot, clears the page-size register, programs the virtual page,
programs the two physical half-page descriptors (the first pointing at physical
zero with cached, valid, dirty attributes, the second merely valid), writes the
indexed entry, waits out the hazard with padding instructions, and finally
restores the translation-context register it saved on entry.

## Status

skipped. Every instruction in the body is a privileged coprocessor-0 transfer
or the indexed table-write instruction; the local disassembly even marks the
whole function as handwritten. There is no C spelling of these operations, and
the project rules forbid inline assembly, so no source was produced. The
function should be kept as an assembly translation unit.
