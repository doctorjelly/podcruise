## Arguments and return value

The function returns an eight-byte structure of two 32-bit signed integers by
value. Under this ABI that is implemented with a hidden buffer pointer in the
first argument register, so the visible source signature is two 32-bit signed
integers (a numerator and a denominator) and the structure return. The hidden
pointer is also handed back as the integer return value, which is the standard
convention rather than anything the source states.

The compiler emits the usual pair of division guards around the divide: a trap
when the denominator is zero, and a trap for the single overflowing case where
the most negative numerator is divided by minus one. Both are automatic and
have no counterpart in the source.

## Recovered behavior

Divides one signed integer by another and reports quotient and remainder
together, using the flooring-style convention rather than the machine's native
truncation.

1. The quotient is computed with an ordinary signed division, which on this
   architecture truncates toward zero.
2. The remainder is then derived arithmetically as the numerator minus the
   product of the denominator and that quotient, rather than by reading the
   hardware remainder.
3. A correction step runs only when the quotient came out negative and the
   derived remainder came out strictly positive. In that case the quotient is
   incremented by one and the denominator is subtracted from the remainder.

The effect of step three is to move a negative-quotient result from
truncate-toward-zero to round-toward-negative-infinity, so that the remainder
always ends up with the same sign as the denominator (or zero). For the sole
caller, which always divides by ten, this makes the digit extraction behave
consistently for negative inputs.

The quotient is placed in the first word of the returned pair and the remainder
in the second.
