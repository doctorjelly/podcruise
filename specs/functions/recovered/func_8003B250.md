# func_8003B250

## Boundary

- USA VRAM range `0x8003B250`..`0x8003B2F3` (inclusive), ROM `0x3BE50`, size 164
  bytes. Matches the assignment.
- The body ends with a return whose delay slot is empty; every early exit is a
  forward branch to that single return. Three alignment padding words follow the
  function before the next entry point.

## Callers

Five direct call sites in the USA build.

## Callees

None. Leaf function.

## Globals

None. All data comes from the first argument.

## Arguments and data shape

- Argument 1 is a pointer to the same object record used by `func_8003A568`: a
  descriptor-table pointer at offset 0x00 and a four-entry 32-bit selection array
  beginning at offset 0x10.
- The descriptor table has a 16-bit flag at offset 0x00 and, at offset 0x0C, a
  pointer to an array of 84-byte records. Each record has a 16-bit "has
  successor" flag at offset 0x00 and a 16-bit successor index at offset 0x04.
- Argument 2 is a 32-bit record index.

## Recovered behavior

The function fills the object's four selection slots with a chain of successor
records, starting from the supplied index.

All four slots are first set to the supplied index, so an object with no chain
keeps the same record at every level. The record named by the supplied index is
then examined: if it advertises a successor, that successor's index replaces the
value in the second slot.

At that point the descriptor table's own 16-bit flag is consulted. A non-zero
flag stops the walk after one step, leaving the third and fourth slots at the
original index. A zero flag lets the walk continue: the record now named by the
second slot is examined the same way, and if it advertises a successor that
successor's index is written into the third slot; then the record named by the
third slot is examined, and if it advertises a successor that successor's index
is written into the fourth slot.

The walk therefore stops as soon as a record has no successor, and each stored
slot always holds a valid record index.

Note on source shape: the walk reads its current position back out of the
selection slot it just wrote rather than keeping it in a temporary. Keeping it in
a temporary produces behaviorally identical but 12-byte-shorter code, so the
slot-based form is the one that reproduces the original.
