# func_800091B0

## Boundary

- USA VRAM range `0x800091B0` .. `0x80009277` inclusive, 200 bytes (0xC8).
- Ends with a return whose delay slot is empty, following the 0x20-byte frame
  release. All three arms of the body converge on that epilogue.
- The single call site targets `0x800091B0`; the assigned boundary is correct.

## Callers

- One caller, which loads all four arguments from its own stack immediately
  before the call and ignores the result, so the routine returns nothing.

## Callees

- `func_80007F5C(s32)` — returns a single-precision level for the supplied
  source handle.

## Globals and access widths

- `D_8009AD10` — array of single-precision values, indexed by the first argument
  and written as a 32-bit float.
- `D_8009AD30` — array of single-precision values, indexed by the second
  argument and written as a 32-bit float.
- `D_8009AD8C` — array of signed 32-bit words, indexed by the second argument.
- `D_8009ADFC` — array of single-precision values, read at the fourth argument's
  index.

## Regional addresses

Entry and ROM offset are identical in every version (`0x800091B0` / `0x9DB0`),
as is the callee `func_80007F5C` at `0x80007F5C`. Only the data moves:

| symbol       | jp           | eu           | lrg_rev1     |
| ------------ | ------------ | ------------ | ------------ |
| `D_8009AD10` | `D_8009BA00` | `D_800A0260` | `D_8009AD10` |
| `D_8009AD30` | `D_8009BA20` | `D_800A0280` | `D_8009AD30` |
| `D_8009AD8C` | `D_8009BA7C` | `D_800A02DC` | `D_8009AD8C` |
| `D_8009ADFC` | `D_8009BAEC` | `D_800A034C` | `D_8009ADFC` |

## Recovered behaviour

The routine first asks `func_80007F5C` for the current level of the source named
by the third argument. It then records a derived value in one of two global
tables, selected by the first argument, which behaves as a small kind code.

For kinds zero and one the level plus one is stored into the second table at the
slot given by the second argument, and the kind itself is recorded alongside it
in the parallel slot table. These two kinds therefore share a single arm.

For kind two the routine ignores the level entirely: it reads a preset value
from a third table at the index given by the fourth argument, adds a quarter to
it, and stores the result into the first table at the slot numbered by the kind.

For every other kind the level plus one is stored into the first table, again at
the slot numbered by the kind.

The dispatch is a genuine multi-way selection on the kind code, with the
"every other kind" arm as the fall-through default; the two-kind arm is written
after the kind-two arm in the source, which is what fixes the order of the
generated blocks.

## Status

Byte-exact against the USA, Japan, Europe and lrg_rev1 ROMs. No per-unit
compiler flags were needed.
