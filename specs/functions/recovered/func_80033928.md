# func_80033928

## Boundary

- USA VRAM range: 0x80033928 .. 0x8003398B inclusive (0x64 = 100 bytes, 25 words).
- ROM offset 0x34528.
- The body ends with a return whose delay slot restores the stack pointer.
- The assignment's size (100) was confirmed correct; no boundary correction.
  Both interior labels (the early-out and the shared epilogue) are branch
  targets of this body, not separate functions, and every direct call site
  targets 0x80033928 itself.

## Callers

Seven direct call sites, in func_80060DE4, func_80062274 and func_80063084.

## Callees

func_80006EB4, called once per iteration with a 32-bit value and a float.

## Globals and access widths

None. The function touches only its two parameters and the memory the first one
points at, which it reads as consecutive 32-bit words.

## Parameters

1. Pointer to a zero-terminated table of 32-bit handles. May be null.
2. A single-precision float, forwarded unchanged to every call. It arrives in an
   integer register (it is the second argument and the first is a pointer) and
   is kept in a callee-saved float register across the loop.

same as the USA body, including the callee address, which did not move in
either regional build.

## Recovered behavior

Given a table of handles and one float amount: if the table pointer is null the
function does nothing. Otherwise it walks the table from the front, and for each
entry that is non-zero it invokes func_80006EB4 with that entry and the float
amount. The walk stops at the first zero entry, so the table is
zero-terminated and an empty table causes no calls at all. Nothing is returned.

## Source shape notes

A plain `while (*entry != 0)` over a separate cursor local (never reusing the
parameter as the cursor) reproduces the rotated loop the compiler emitted, with
the pre-loop test loading the first entry and the loop tail loading the next one
before advancing.

## Status

Exact on us, jp, eu and lrg_rev1.
