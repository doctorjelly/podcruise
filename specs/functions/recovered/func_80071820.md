# func_80071820

## Boundary

USA VRAM 0x80071820 - 0x800718DB inclusive (188 bytes, 47 instructions), ROM
0x72420. The body ends with a return whose delay slot is empty. All five direct
call sites target 0x80071820. Every internal branch lands inside the range, and
the last of them lands on the return itself. Boundary as assigned is correct.

## Callers

Five direct call sites. Three of them compute the second argument as a value
reduced modulo six, which confirms that the index selects one of six slots. All
five compute the third argument as a single-precision value and move it into
the third integer argument register, which is the standard way a float in
argument slot three is passed.

## Callees

None. This is a leaf.

## Globals and access widths

- `D_800A52D4` - a single 32-bit word, read once and tested against zero.

## Parameters and return

Three arguments: a pointer to an object, a signed 32-bit slot index, and a
32-bit float amount. No return value.

## Object fields touched

| offset | width | use |
| --- | --- | --- |
| 0x060 | 32-bit word | status flags, read and written |
| 0x064 | 32-bit word | second flag word, read only |
| 0x0A0 | float | per-object scale factor, read only |
| 0x270 + 4*index | float | running maximum, read and written |
| 0x288 + 4*index | float | accumulator, read and written |
| 0x2A0 + 4*index | 32-bit word | per-slot flags, read and written |
| 0x2C4 | float | total, read and written |

The three indexed groups are six entries each and sit back to back, so they are
best modelled as three parallel arrays of six.

## Recovered behavior

The routine adds a scaled amount into one of six per-object accumulators, clamps
it, tracks its peak, marks the slot, and adds the raw amount to a running total.

Four guards run first, and any one of them abandons the whole routine:

1. the module-level word `D_800A52D4` must be zero;
2. bit 0x4000 of the object's status word at offset 0x60 must be clear;
3. bit 0x2000 of the same status word must be clear;
4. bit 0x02000000 of the second flag word at offset 0x64 must be clear.

The second and third guards are separate tests of the same loaded word, not a
single combined mask. The fourth is a single-bit test that the compiler turns
into a shift-and-sign-test.

Once past the guards, the routine clears bit 0x00800000 of the status word at
offset 0x60 and stores it back.

It then adds `amount * object[0xA0]` into the accumulator for the selected
slot. If the accumulator now exceeds 1.0 it is set to exactly 1.0. Note the
comparison against 1.0 re-reads the accumulator from memory rather than reusing
the freshly computed sum, and the peak comparison that follows re-reads it
again - the original source expresses each of these as a fresh subscript of the
array, which is what produces the reload.

Bit 0x1 is then set in the slot's own flag word at offset 0x2A0.

Finally, if the slot's stored peak at offset 0x270 is below the (possibly
clamped) accumulator, the peak is raised to it; and the unscaled amount is
added to the object-wide total at offset 0x2C4.

The clamp is written as "greater than 1.0", and the peak test as "peak is less
than accumulator"; the operand orders in the emitted comparisons follow from
that reading.

## Status

Exact on USA, Japan, Europe and lrg_rev1.
