# func_80032F2C

## Boundary

- USA VRAM `0x80032F2C` .. `0x80033007`, ROM `0x33B2C`, size 220 bytes (55
  instructions). Terminates with the return instruction at `0x80033000`; the
  delay slot at `0x80033004` carries the frame release.
- Boundary confirmed: label/endlabel bracket the range, all nine direct call
  sites target `0x80032F2C`, and the two internal loops branch only within the
  range. Not corrected.

## Callers

Nine direct call sites. Two of them make the argument shape unambiguous: one
computes the second argument as a base address plus a multiple of 60 bytes,
confirming the record size; another passes the addresses of two seven-byte
stack buffers as the third and fourth arguments.

## Callees

- `func_800321F0` (`0x800321F0`) — dispatches on its second argument through a
  seven-entry jump table, compares its third argument against small integers,
  and spills its fourth argument to memory before reloading it as a
  single-precision float.

## Globals and access widths

None. All memory traffic goes through the four pointer arguments.

## Recovered behavior

The routine installs a settings record and then applies seven per-channel
adjustments to it.

It begins by overwriting the destination record with the source record
wholesale — a 60-byte object copied as a unit, which the compiler expands into
a three-word-per-pass move loop rather than a field-by-field assignment.

It then walks the seven channels in order. For each channel it reads a mode
selector from the third argument's byte array and an intensity from the fourth
argument's byte array. The intensity is an unsigned byte on a 0..255 scale and
is normalised into a 0..1 fraction by dividing it, as an unsigned quantity, by
255. Channel index, mode selector and normalised intensity are handed to
`func_800321F0` together with the destination record, which applies the change
in place.

Nothing is returned.

Matching details. The intensity must be converted through an explicitly
unsigned integer type: the original contains the compiler's unsigned-to-float
correction branch, which a plain signed byte-to-float conversion does not
produce. The mode selector must be read into its own local *before* the
normalised intensity is computed — that ordering is what assigns the two byte
pointers to their callee-saved registers in the original order — while the
normalised intensity must still be computed as a local statement ahead of the
call, otherwise the two argument-register moves are hoisted above the
floating-point work.

## Status

Exact in USA, Japan, Europe and lrg_rev1.
