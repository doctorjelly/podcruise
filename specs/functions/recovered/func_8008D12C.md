# func_8008D12C

## Boundary

- USA VRAM range: 0x8008D12C .. 0x8008D22B inclusive, 256 bytes (64
  instructions), USA ROM 0x8DD2C.
- Assigned size 256 was correct; **no boundary correction.**
- The body does not end in a return. It ends at 0x8008D224 with an
  unconditional jump to func_8008D284, whose delay slot at 0x8008D228 is a
  no-operation. Control never comes back, so there is no epilogue.
- Confirmation method: I resolved every branch displacement in the enclosing
  listing to an absolute target. The body has two forward branches, both
  internal, and no branch from outside lands in it. All six call sites target
  0x8008D12C exactly. The preceding function, func_8008D044, ends at
  0x8008D0F7, and the block between that and this entry belongs to
  func_8008CB00 (see `func_8008D044.md`); nothing from it falls through into
  this entry, because its last instruction is an unconditional branch.

## How control reaches it

By call, six times, from six different regions of the image: 0x80087EE0,
0x8008BA8C, 0x8008C06C, 0x8008C810, 0x8008C994 and 0x80097D98. It is a genuine
exported routine with one argument, unlike its private neighbour
func_8008D044. Every caller sets the running thread's state field immediately
before or in the delay slot of the call, and every caller regains control only
because some later scheduling decision resumes the thread — the call itself does
not return.

## Callees

- func_8008D22C, called once, only when the argument is non-null.
- func_8008D284, entered by unconditional jump and never returned from.

## State read and written

Takes one argument: a pointer to a list head cell, or null. Four of the six
callers pass the address of the global ready list at D_800A7BB8; one passes a
list head four bytes into a message-queue record; one passes a value loaded from
its own stack frame.

Reads: the running-thread pointer at D_800A7BC0, the processor status register,
the global permitted-interrupt mask at D_800A7B50, and the peripheral interrupt
mask register D_A430000C.

Writes, all into the running thread's saved context: the status word, the
program counter, the peripheral interrupt mask, the callee-saved general
registers, the global and stack pointers, the frame pointer, the return
address, and — only when the thread is marked as a floating-point user — the
floating-point control word and the six callee-saved floating-point registers.
The caller-saved registers are deliberately not written.

## Recovered behavior

Suspends the calling thread and hands the processor to whichever thread should
run next, optionally parking the caller on a wait list on the way out.

This is a voluntary yield, so it can be much cheaper than the involuntary save
that func_8008CB00 performs. It saves only what the calling convention says must
survive a call: the callee-saved general registers, the stack and frame
pointers, the global pointer, and the return address, which it also records as
the resume point. The caller-saved registers are not saved at all, because from
the suspended thread's point of view this looks exactly like an ordinary call
that eventually returns. Floating-point state is saved on the same principle —
only the callee-saved half, and only if the thread is flagged as having used
floating point.

Before saving, it records the current processor status with the exception-level
bit forced on, so that the resume path treats the thread as if it had been
interrupted. It then rewrites two masks in the saved state so the thread will
come back with no more permission than it is entitled to: the processor
interrupt-enable bits are narrowed to the intersection of what the thread had
and what the global permitted mask allows, and the peripheral interrupt mask is
narrowed the same way against the high half of that global mask. The peripheral
mask is captured from the live hardware register rather than from memory.

Finally, if the caller supplied a list head, the thread is inserted into that
list in priority order — the callers use this to move themselves onto a message
queue's wait list or back onto the ready list, having already set their own
state field to say which. If the argument is null the thread is simply dropped:
nothing holds a reference to it and it will not run again until something else
requeues it. Either way the routine jumps into func_8008D284 to select and
resume a thread, and does not return.

## Why this cannot come from C

The decisive instruction is at 0x8008D134: a coprocessor-0 read of the status
register. There is no C construct that reads a coprocessor-0 register, and the
accepted compiler has no inline assembly — it parses an `asm(...)` construct as
a call to an undeclared function named `asm`. No source text reaches the
instruction.

The body is disqualified a second, independent way. It uses both
kernel-reserved registers, k0 and k1, as ordinary working registers across 21
instructions, including holding the saved status word and the peripheral mask in
them. No compiler allocates those registers, because an exception taken at any
point would destroy them; using them here is safe only because the code knows
exactly what state the machine is in.

Two structural facts confirm it. The routine saves precisely the callee-saved
register set and no more, into fixed offsets of a record laid out by
func_8008CB00 and func_8008D284 — a hand-partitioned split of the register file
that a compiler has no way to express. And it terminates by jumping into another
routine that never returns, so it has no epilogue and no return value; a C
function that never returns still emits a frame teardown or at minimum a tail
call the compiler chose, not a jump the author chose.

## Note on translation unit

This body is part of the same original assembly translation unit as
func_8008CB00, func_8008D044 and func_8008D284; the argument is set out in full
in `func_8008D044.md`. The two specific facts that bear on this function are
that it begins at the exact byte after func_8008CB00's out-of-line arm ends,
at an address that is not sixteen-byte aligned, and that it ends by jumping into
func_8008D284's entry with the never-return contract that only makes sense if
both were written together.
