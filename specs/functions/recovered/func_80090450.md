# func_80090450

## Verified facts

- The USA body occupies VRAM `0x80090450` through `0x800904FF`, ROM
  `0x91050`, for 176 bytes. Its `jr $ra` is at `0x800904F8`; the delay slot is
  `nop`.
- `func_80088BFC` calls it at two sites. It calls `func_80088500` to obtain a
  node and `func_80088450` on the alternate path. A callback is loaded through
  the target object at offsets `0x0C` and `0x08`. It references no globals.
- Japan and Europe use the same normalized body at `0x80091140` and
  `0x800959A0`. Those regional compiler comparisons identify this translation
  unit's optimization level as IDO 5.3 `-O3` rather than the project default
  `-O2`.

## Behavior

Read the target pointer held by the second argument. If no target is attached,
return without changing the holder. When the target's word at `0xD8` is zero,
pass the owner and target to `func_80088450`. Otherwise allocate an event node;
if allocation succeeds, initialize it from the owner and target, then dispatch
it through the target's callback with command three. After either completed
path, clear the holder's target pointer. Allocation failure leaves that pointer
unchanged.

## Status

Independently expressed C. Exact for the canonical USA body with IDO 5.3
`-O3`; the linked 176-byte compiler comparison is byte-identical. Japan,
Europe, and the later USA revision are also exact under their symbol maps.
