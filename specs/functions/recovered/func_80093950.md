# func_80093950 — whole-cache arm of func_80093900, not a function

## Verdict

Not a separate entity. `0x80093950` is the "the caller asked for at least a
whole cache's worth" arm of `func_80093900`. It carries a label only because
the neighbour reaches it with an ordinary conditional branch that happens to
cross the neighbour's return, and the label scanner promotes any such target to
a function. The specification for this code belongs with `func_80093900`, whose
existing write-up already covers it; this file records the classification.

## Boundary

- USA VRAM `0x80093950` .. `0x80093973` inclusive, ROM `0x94550`, 36 bytes,
  nine instructions. The extent is correct on its own terms: the range closes
  with the return instruction and an empty delay slot, and padding words follow
  before the next content.
- The classification is what is wrong. This is an arm of the neighbouring
  routine, not an entry point.

## Why this is an arm and not a function

1. **No caller.** Nothing in the USA image calls `0x80093950`. The single
   in-bound edge is a conditional branch inside `func_80093900`, taken when the
   requested byte count is not smaller than the whole data cache.
2. **It reads a value it never writes.** The cache-size constant that fixes
   where the sweep stops is produced by `func_80093900` shortly before the
   branch and is still live when the branch is taken. Nothing inside this range
   establishes it. A genuine entry point cannot depend on a register that only
   one particular predecessor sets.
3. **No parameters, and it returns for someone else.** The neighbour's two
   arguments are never touched here, and the range finishes by returning
   through the link register belonging to the neighbour's caller.
4. **It is one of three exits from a single call.** `func_80093900` returns
   early for a non-positive count, returns after a bounded walk for a small
   count, and hands control here for a large one. All three end the same call.

## Callers

None. One in-bound branch edge from `func_80093900` at `0x80093910`.

## Callees

None.

## Globals and access widths

None. No data loads or stores; the range issues cache maintenance operations
against a fixed address window derived from the cache's own geometry.

## Recovered behavior of the arm

Reached when the caller of the parent routine asked to write back a byte range
at least as large as the whole data cache. Rather than stepping the requested
range, this arm services the cache itself: from the base of the cached view of
memory it visits every line, sixteen bytes apart, writing back any modified
contents and dropping the line, and stops after the last line the cache holds.
It then returns to the parent's caller.

Worth recording: this arm is byte-identical to the corresponding arm of the
range-invalidation routine at `0x80087D48`. Both fall back to the same
"write back and drop every line" sweep, which satisfies both a write-back
request and an invalidation request at once. The two parents differ only in
what they do for small ranges.

## Status

Skipped, permanently. It should not have been queued as a function.

The loop body is the processor's cache maintenance operation, for which the
accepted compiler has no C spelling and for which the project rules forbid the
only alternative, inline assembly. Independently of that, the range is not a
compilation unit: no entry, no parameters, no prologue, and a live dependency
on a register set inside a different labelled range.

Recommendation for the orchestrator: drop `func_80093950` from the queue and
carry `0x80093900` .. `0x80093973` as a single hand-written assembly unit of
116 bytes (80 + 36).
