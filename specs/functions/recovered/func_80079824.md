# func_80079824 — update craft-specific articulated parts

## Verified boundary

- USA VRAM `[0x80079824, 0x8007ACEC)`, ROM `[0x7A424, 0x7B8EC)`,
  5,320 bytes.
- The return is at `0x8007ACE4`; its delay slot restores the `0x150`-byte
  frame at `0x8007ACE8`.
- The sole runtime caller is recovered `func_8007ACEC`, which invokes this
  routine during the per-frame update when the craft has a parts table.

## Inputs, callees, and globals

The argument is a craft state object. Relevant fields are its base matrix,
flags, steering values, age, cyclic angle, parts table, and a descriptor whose
first word identifies one of 23 craft layouts.

The routine calls `func_800181BC` to set a flag on one optional part,
`func_800156DC` to copy the base matrix, `func_80079714` six times to smooth
articulation angles, `func_8001745C` to construct rotation matrices, and
`func_80017BA8` to apply those matrices to non-null parts.

`D_800D7720` and `D_800D7730` hold controller axes. The doubles at
`D_800ADAC8` through `D_800ADAF0` provide steering scaling, an upper heading
bound, and cyclic-angle wrap limits and periods. `D_80120BF0` supplies the
per-frame scale.

## Behavior

If no parts table exists, the function does nothing. Otherwise it optionally
marks the part at table byte offset `0xEC`, copies the craft's base matrix, and
normalizes steering to `[-1, 1]`. It stops updating articulation once the craft
age reaches 76.

Six smoothed angles are then derived from steering for animation channels
`0x2E`, `0x2F`, `0x20`, `0x12`, `0x23`, and `0x15`. A second craft value is
doubled and clamped to the range 100 through 700, advances a stored cyclic
angle, and wraps that angle through the configured period.

The craft-layout word selects which nullable parts receive rotations. The
table below records each rotation group as `(x, y, z): part-table byte offsets`;
groups run left to right in the stated order.

## Status

Behavior-recovered C, not byte-matching. Exact linked comparisons with IDO 5.3
and IDO 7.1 each emit 4,688 bytes against the 5,320-byte canonical body and
first differ at byte `0x2`. As a structural audit, the compiled source retains
all 167 static calls in the canonical target order and with identical per-callee
counts; this does not turn the failed byte comparison into a match.
