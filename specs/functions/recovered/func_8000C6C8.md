# func_8000C6C8

## Boundary

- USA VRAM range `0x8000C6C8`-`0x8000C723` inclusive, ROM `0xD2C8`, size 92 bytes
  (23 instructions).
- Terminates with a return followed by an empty delay slot; the preceding
  function `func_8000C658` ends with its own return at `0x8000C6C0` and none of
  its branches reach past it, so the assigned entry point is a true boundary.
- Leaf function: no frame is allocated, no return address is spilled.

## Callers

20 direct call sites in the USA build, all in the same translation unit region
(`main_D138.s`). Every observed site passes a pointer formed as `base + small
constant` (a field inside a larger per-object record), three floating-point
values in the second through fourth slots, and a fifth floating-point value on
the stack.

## Recovered behavior

The function advances one stored floating-point quantity by an increment and
then confines it to a closed interval.

1. The product of the second and third arguments is added to the value the
   first argument points at, and the sum is written back through that pointer.
2. If the updated value is below the fourth argument, the fourth argument
   replaces it.
3. If the value is then above the fifth argument, the fifth argument replaces
   it.

Because the target is reached through a pointer, the stored value is re-read
between the update and each comparison, so the two limits are applied to
whatever is actually in memory rather than to a cached copy. The lower limit is
applied before the upper limit, so when the two limits are inverted the upper
limit wins. The comparisons are strict, so a value already exactly equal to a
limit is left untouched.

Typical call sites use this to integrate a rate over a frame delta and keep the
result inside a design range, for example clamping to `[0, 1]` or to
`[0, 10]`.

## Status

Exact. USA, Japan, Europe, and lrg_rev1 all verify byte-identical.
