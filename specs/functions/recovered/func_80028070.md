# func_80028070

## Boundary

- USA VRAM range 0x80028070 - 0x800280D7 inclusive (0x68 = 104 bytes).
- Terminates with the standard return instruction whose delay slot releases the
  0x20-byte stack frame; nothing follows inside the range.
- Three direct call sites in the USA image all target 0x80028070, so the label
  is a genuine entry point. No branch from the preceding function reaches into
  the range.

## Callers

Called from the initialisation sequence at 0x8004EB24 (and two further sites in
the same neighbourhood).

## Callees

- `func_80029A3C(group, index)` - the only callee, invoked sixteen times per
  invocation.

## Globals

None referenced directly.

## Parameters

One integer parameter. It is written to its incoming home slot on the frame and
never read again, so the arity is real but the value is unused. Nothing is
returned.

Relocated symbol in the regional builds: the callee is at 0x8002A2C4 (jp) and
0x8002C118 (eu). The regional bodies were read independently and are
instruction-for-instruction the same shape as USA.

## Recovered behaviour

A blanket reset helper. It walks the twelve members of group 0 in ascending
order, asking the shared per-entry reset routine to clear each one, and then
walks the four members of group 1 in the same way. Its own parameter plays no
part in what it does.

Two details of the source shape are load bearing:

- The first loop's bound is expressed as a "less than twelve" test, which the
  compiler turns into an immediate comparison; the second loop's bound is
  expressed as an inequality against four, which forces the count into a
  register. Writing both loops the same way changes the emitted comparison and
  breaks the match.
- The unused parameter must stay in the signature; removing it removes the
  home-slot store.

## Status

Exact in USA, and byte-identical in Japan, Europe and lrg_rev1 from the same
source.
