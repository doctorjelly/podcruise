# func_800059A8

## Boundary

- USA VRAM range: 0x800059A8 .. 0x80005AF8 inclusive (0x154 = 340 bytes, 85 instructions).
- USA ROM offset: 0x65A8.
- Ends with a return whose delay slot performs the final store; there is no
  frame adjustment at all, so the routine is a pure leaf.
- Three direct call sites, all targeting 0x800059A8. Assigned size 340 was
  correct; no boundary correction.

## Callers and callees

- Three direct callers in the USA build. One pointer argument, no result.
- Leaf function; no callees.

## Globals and access widths

- `D_8009A29C` — one 32-bit signed index, re-read as a full word once per copied
  element (sixteen separate reads).
- `D_800AEC80` — a table of 64-byte records (the index is scaled by 64). Each
  record is read as sixteen consecutive 32-bit floats at offsets 0x00..0x3C.

The single argument is a pointer to sixteen consecutive 32-bit floats.

## Regional addresses

The body is instruction-for-instruction identical in every version, and the
function keeps the USA address everywhere; only the two data symbols move.

## Recovered behavior

Copies one sixteen-float record — a four by four matrix — out of the global
table into the caller's buffer. The record is selected by the global index, and
that index is consulted afresh for every one of the sixteen elements rather than
being cached, so a change to the index part-way through would be observed.

Source-shape notes established by matching:

- The sixteen copies are written out one statement at a time. A counted loop of
  sixteen iterations does not reproduce the body: the compiler unrolls it only
  four ways and keeps a residual loop, which is eighty bytes short of the
  original and reaches the table through a running byte offset instead of the
  literal element offsets the original uses.
- Re-reading the index inside every element expression is what produces the
  repeated index load; hoisting it into a local removes fifteen loads.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
