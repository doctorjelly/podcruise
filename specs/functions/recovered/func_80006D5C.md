# func_80006D5C

## Boundary

- VRAM 0x80006D5C .. 0x80006DE8 (exclusive), ROM 0x795C, size 140 bytes.
- The body ends with the return instruction; its delay slot releases the
  eight-byte frame used to preserve one callee-saved register.
- Assigned size 140 is correct; the following label is a distinct routine
  (func_80006DE8, also in this assignment) and nothing branches past the
  return.

## Callers and callees

- Four direct call sites. No calls out (leaf).
- Call sites pass a record pointer in the first slot and a small literal
  (observed 8 and 9) in the second, and use the result as a pointer.

## Globals and access widths

- `D_8009A2A0` — 32-bit signed counter, read (as the loop bound) on every
  iteration in the source; the compiler hoists the load out of the loop.
- `D_800AF4C0` — array of 32-bit pointers, read with 32-bit loads.

Fields read through each listed entity: the flag word at 0x100 (32-bit) and
the attachment pointer at 0x124 (32-bit).

## Recovered behavior

Searches the global active-entity list for the first entity that belongs to a
given owner record and has a given kind.

1. A null owner pointer yields a null result immediately, without touching the
   list.
2. Otherwise the routine walks the pointer table from index zero while the
   index is below the global count. An empty (null) slot is skipped.
3. An entity qualifies when all of the following hold: its top flag bit
   (0x80000000) is clear; the low four bits of its flag word equal the second
   argument; and its attachment pointer equals the owner argument.
4. The first qualifying entity is returned. If the walk finishes, or the count
   is zero or negative, a null pointer is returned.

## Compiler note

The loop bound must be written as the global itself (`i < D_8009A2A0`). Caching
it in a local first lets the optimiser unroll the loop four ways, which
produces 404-484 bytes instead of 140. With the global in the comparison the
optimiser still hoists the single load but declines to unroll, giving the
original shape.

## Status

Exact. Byte-identical in USA, Japan, Europe and lrg_rev1.
