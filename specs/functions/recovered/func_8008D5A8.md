# func_8008D5A8

## Boundary

USA VRAM 0x8008D5A8 - 0x8008D5FB (84 bytes, ROM 0x8E1A8). Ends with the usual
return pair and a no-operation delay slot. Its one direct call site targets
0x8008D5A8, and the preceding function (0x8008D554) ends with its own return
before this address, so the boundary is correct.

## Callers

One direct call site, at 0x800888B0, in the same routine that also calls
func_8008D554 a few instructions later. It supplies a pointer taken from field
0x34 of one object, the result of a preceding allocation-style call, and a word
read from field 0x4 of a third object.

## Callees

* `func_80095AA0` (0x80095AA0) - the same registration helper used by
  func_8008D554.

Code addresses handed over: `func_8008F980` (0x8008F980) and `func_8008F950`
(0x8008F950).

## Globals

None.

## Object fields written

* +0x14: word, cleared to zero.
* +0x18: word, set from the third argument.
* +0x1C: word, set from the second argument.

## Recovered behaviour

This is the sibling of func_8008D554 for a different handler kind. It registers
the object with the shared subsystem entry point, passing the object, its pair
of fixed code addresses, and the selector value 6, then clears the status word
at offset 0x14 and stores the third argument at 0x18 and the second argument at
0x1C. Nothing is returned.

The only differences from func_8008D554 are the two code addresses and the
selector value.

## Status

Exact on USA, Japan, Europe and lrg_rev1 with the project's accepted profile.
