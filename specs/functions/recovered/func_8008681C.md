# func_8008681C

## Boundary

USA VRAM 0x8008681C - 0x80086930 (exclusive), ROM 0x8741C, size 276 bytes.
The body ends with the return jump whose delay slot performs the final store,
so the last stored field is written from the delay slot. The single direct
call site targets 0x8008681C. No boundary correction was needed.

## Callers

One direct call site.

## Callees

None. The routine is a leaf: it makes no calls, adjusts no stack frame, and
uses only the temporary floating-point registers.

## Globals and access widths

None. The routine touches only the two 4x4 single-precision matrices supplied
by the caller, always as 32-bit floating-point loads and stores.

## Recovered behavior

The routine writes the inverse of a rigid-body transform matrix into a caller
supplied destination matrix, taking the source matrix as the second argument.
Source and destination must not overlap.

The upper-left three-by-three block is inverted by transposition combined with
a fixed axis remapping: the first source row becomes the first destination
column unchanged, the third source row becomes the second destination column
unchanged, and the second source row becomes the third destination column with
every component negated. That corresponds to inverting a rotation that also
exchanges the second and third axes and flips the sign of one of them.

The translation row is then rebuilt so that the result really is the inverse:
each of its first three components is the negated dot product of the source
translation with the corresponding destination column. The routine reads those
destination columns back out of the destination matrix rather than from
registers, so it depends on the nine stores above having already landed.

Finally the fourth column is copied straight across from the source, all four
entries unchanged, which preserves whatever projective terms the source
carried.

## Status

Exact on USA, Japan, Europe and lrg_rev1. Matched on the first attempt from
the direct transcription of the behavior above.
