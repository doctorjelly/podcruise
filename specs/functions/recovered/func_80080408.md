# func_80080408 — look up a table entry from a lane index and a scaled position

## Boundary
- USA VRAM 0x80080408 .. 0x80080497 (144 bytes, ROM 0x81008).
- The final instruction pair is the return with the table load in its delay
  slot; the frame is released early, part way through the body, by the
  scheduler.
- Boundary confirmed: three direct call sites target 0x80080408, and the frame
  adjustment is the first executed instruction. Not corrected.

## Callers
Three direct call sites (0x80070CE4, 0x80080878, 0x80080C14). Each passes a
pointer 0xAC bytes into a larger object. Two of them store the result into a
32-bit field of that object and later feed it back to another routine as a
pointer argument; the third tests it against zero and passes it on. The result
is therefore a live pointer-sized value, not void.

## Callees
- `func_8003A568(object, 0)` — returns a small non-negative selector; the
  second argument is the constant zero.

## Globals and access widths
- `D_800ADC60` — a single-precision constant, value 0.9999989867 (the largest
  float below one), read with a single-precision load.
- `D_8011DCF8` — a table of 32-bit entries, read with a word load; the entry
  is the return value.

All three regional bodies were read independently and are the same shape as the
USA one apart from the relocated symbol addresses.

## Recovered behavior
The selector routine is asked for the object's lane, with its second argument
fixed at zero. The object's own single-precision position, taken from offset
0x08, is multiplied by ten to give a scaled position.

That scaled position is converted to a whole number in a way that rounds toward
minus infinity rather than toward zero: when it is negative, the largest float
below one is subtracted before truncating, so a negative fractional value lands
on the next lower whole number while exact whole values are unaffected; when it
is zero or positive it is truncated directly.

The lane is then multiplied by ten and added to that whole number, and the
resulting index selects an entry from the 32-bit table, which is returned.
Ten entries per lane, one per tenth of a unit of position.

## Status
Exact. Byte-identical to the original in us, jp, eu and lrg_rev1 under the
accepted `ido53_o2` profile. No per-unit flags needed.

Source-shape note worth reusing: the row offset has to be a separate local
assigned *after* the rounding branch. Writing the multiplication inline in the
index expression makes IDO put the product on the left of the addition; hoisting
the multiplication above the branch makes it fold the lane straight out of the
return register instead of copying it. Only "compute the lane, do the rounding,
then compute the row offset, then add" reproduces both the register copy and
the operand order.
