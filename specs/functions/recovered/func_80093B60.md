# func_80093B60 — 8-bit block check value over a 32-byte buffer

## Boundary

- USA VRAM `0x80093B60` .. `0x80093BF3` inclusive; ROM `0x94760`; size 148 bytes (37 instructions).
- Terminates with `jr $ra` and a real (non-`nop`) delay-slot instruction that
  produces the return value, so the body ends at `0x80093BF0`.
- Three padding words follow before the next label, and both direct callers
  target `0x80093B60`, so the entry is confirmed.
- No branch from the preceding function reaches into this range; the label is a
  genuine function boundary. **No boundary correction needed.**

## Callers

Two direct call sites, both in the USA text unit `main_91260.s`:

- one inside `func_80092198`'s region, invoked with a pointer derived from an
  object base plus 6;
- one near `0x80092A50`, invoked with a pointer that was reloaded from the
  caller's frame; the caller immediately narrows the result to eight bits.

Both call sites pass a single pointer argument and both use the returned value
as a small unsigned quantity, which agrees with the callee's own final
eight-bit truncation.

## Callees

None. The function is a leaf.

## Recovered behavior

The function computes an eight-bit block check value ("checksum" in the
polynomial-division sense) over exactly 32 consecutive bytes starting at the
address it is given, and returns it as an unsigned byte. The argument is not
modified for the caller; the walk uses a private copy of the pointer.

The running remainder starts at zero. The buffer is consumed one byte at a
time, and each byte is consumed one bit at a time from the most significant bit
down to the least significant bit. For every bit:

1. the remainder is shifted left by one place;
2. the bit taken from the message is folded into the low end of the remainder;
3. if the shift pushed a one out past the eight-bit window, the remainder is
   reduced by the generator constant `0x85`.

Steps 2 and 3 are expressed in the recovered source as the two arms of a test
on the message bit, because the reduction constant differs between them: when
the message bit is set, folding it in and reducing collapses into the single
constant `0x84`, and when the message bit is set but no reduction is due the
remainder is simply incremented. When the message bit is clear, only the
possible reduction by `0x85` applies. Note that the reduction leaves the
overflow bit itself in place; it is discarded only by the final truncation, and
by the fact that a bit at that weight can never survive the next shift's own
overflow test.

After all 32 bytes have been absorbed, eight further shift-and-reduce rounds run
with no message bits entering, which appends eight zero bits to the message —
the usual "flush the register" tail of this style of check value. The remainder
is then truncated to its low eight bits and returned.

The tail loop reuses the outer byte counter, which the preceding loop has
already driven to zero, and counts it up to eight; the recovered source relies
on that carried-over value rather than re-initialising the counter, which is
what keeps the loop un-unrolled and free of an entry guard.

## Status

**exact** — USA, Japan, Europe and lrg_rev1 all verified byte-identical
(`verified_match: true`, `first_difference: null`, sizes equal).

Two source-shape experiments were needed after the first draft: the flush loop
had to inherit the already-zero counter instead of initialising its own (which
suppresses IDO's four-way unroll), and it had to be written as a bottom-tested
`do`/`while` (which removes the entry guard the compiler otherwise emits when it
cannot see the counter's incoming value). The main byte/bit loops matched on the
first attempt.
