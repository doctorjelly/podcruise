# func_8008D7D0

## Boundary

- USA VRAM range: 0x8008D7D0 .. 0x8008D86C inclusive (0xA0 = 160 bytes, 40 instructions).
- USA ROM offset: 0x8E3D0.
- Terminates with a return whose delay slot is empty.
- Assigned size 160 was correct; no boundary correction.

## Callers and callees

- Two direct call sites in the USA build (0x8008DC34 and 0x80096398). Both pass
  a single pointer that they have just fetched from a table of records, and
  both ignore the result, so the function returns nothing.
- No callees (leaf function).

## Parameters and record layout

One pointer argument to a record with these members:

| offset | width | role |
|--------|-------|------|
| 0x00   | s16   | input value, read once |
| 0x02   | s16   | written with 0x4000 minus the halved input |
| 0x08   | s16 [16] | table filled by this function |
| 0x2C   | s32   | written with 1 |

Members at 0x04..0x07 and 0x28..0x2B are untouched and are only present to make
the offsets line up.

## Globals and access widths

None. The function touches nothing outside the record it is given.

## Recovered behavior

Prepares a sixteen-entry table of decaying gains for one record.

The record's first member is read and halved: it is scaled by 0x4000 and the
32-bit product is shifted right fifteen places, which is an exact halving in
the fixed-point convention where 0x4000 represents one half of full scale. The
halved value is stored back into the record's second member as the complement
against 0x4000, that is, the remainder needed to reach full scale.

The record is then flagged active by storing one into the word at offset 0x2C.

The table is written in three parts that share one running index. The first
eight entries are cleared to zero. The entry at index eight receives the halved
value itself. The remaining seven entries receive successive powers of the
halved value expressed as a fraction of full scale: the fraction is computed in
double precision as the halved value divided by 16384, and each further entry
is the running product of that fraction with itself once more, rescaled by
16384 and truncated towards zero into a signed 16-bit slot. The result is a
geometric decay curve whose first point is the input's half and whose ratio is
that same half.

## Source-shape notes established by matching

- The scaled product must be its own named 32-bit local, assigned before the
  shift. Folding the multiply and the shift into one expression makes the
  compiler use the destination register as the scratch for the multiply, which
  changes two instructions.
- The index must not be reinitialised between the zeroing loop and the powers
  loop; the compiler carries both the counter and the strength-reduced element
  pointer straight through, and a fresh initialiser would add two instructions.
- The entry at index eight is a separate statement that stores the integer
  value, not a first iteration of the powers loop. The powers loop multiplies
  before it stores, so its first stored value is already the square.
- The exponent scale 16384.0 is a double; the compiler builds it from immediate
  halves rather than loading it from constant data, and the divide and both
  multiplies are double precision.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
