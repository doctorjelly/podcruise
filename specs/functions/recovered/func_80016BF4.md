# func_80016BF4 — transform a 3-component vector by the rotation part of a matrix

## Boundary

- USA VRAM range: `0x80016BF4` .. `0x80016CA8` inclusive, 184 bytes
  (46 instructions).
- ROM offset `0x177F4`.
- Ends with a return whose delay slot holds the store of the third output
  component.
- The preceding function ends with its own return plus a stack-pointer
  adjustment in the delay slot immediately before this entry, and the direct
  call sites target `0x80016BF4`. Assigned boundary confirmed correct.

## Callers and callees

- 42 direct call sites.
- No callees; leaf function with a 16-byte frame.

## Globals and access widths

- None. Three pointer arguments: destination vector, source vector, matrix.
- The source vector is three consecutive 32-bit floats. The matrix is read at
  byte offsets 0x00/0x04/0x08, 0x10/0x14/0x18 and 0x20/0x24/0x28, i.e. the
  upper-left three-by-three block of a four-by-four float matrix stored by rows
  with a 16-byte row stride; the fourth row and fourth column are never touched,
  so no translation is applied.
- One 12-byte local (three floats) at the top of the frame holds the result
  before it is copied out, again making the call safe when the destination
  aliases the source.
- Every vector and matrix element is re-read for each output component; the
  compiler does not cache them across the three rows.

## Regional addresses

- Japan: `0x80016D24`, ROM `0x017924`.
- Europe: `0x80017084`, ROM `0x017C84`.
- Not probed, because the USA form is not yet byte-exact.

## Recovered behaviour

Multiplies a three-component vector by the rotation/scale part of a four-by-four
matrix and writes the result through the destination pointer.

Each output component k is the sum of three products: matrix element [0][k]
times the source x, plus matrix element [1][k] times the source y, plus matrix
element [2][k] times the source z. Because the matrix row index selects the
source component and the column index selects the output component, this is the
"row-vector times matrix" convention. The three components are accumulated into
a local and copied to the destination afterwards, so the destination may alias
the source.

## Status

Behaviour recovered, not byte-exact. The compiled body is the correct length
(184 bytes) and 40 of its 46 instructions are identical to the original,
including both scheduling fillers. The six differing words are three pairs of
adjacent float loads — in each output component the two operands of the third
product are fetched in the opposite order from the original, which changes only
which of two scratch registers holds which value; the multiply, add, store and
frame instructions are bit-identical. Eleven source shapes were tried
(operand order in the third product, all-vector-first and all-matrix-first
orderings, explicit re-grouping of the sum, per-product temporaries, local
struct versus local array, flat float arrays for both operands, and the 7.1
compiler): this compiler always evaluates the matrix operand of the final
product first, whichever way the multiplication is written, so the original's
evaluation order was not reachable from ordinary C within the experiment budget.
