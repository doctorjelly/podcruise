# func_80011DF0 — populate the seven-entry descriptor pointer table

## Boundary
- USA VRAM `0x80011DF0` .. `0x80011E53` inclusive; ROM `0x129F0`; size **100**
  bytes (25 instructions).
- Terminates with a return whose delay slot stores the last pointer.
- The preceding function ends with a return followed by three padding slots, so
  the entry is section-aligned and unambiguous. Both direct call sites target
  `0x80011DF0`. No branch reaches inside the range.
- **Size correction:** the assignment sheet and the generated inventory both
  report 200 bytes / 50 instructions for this function. The real span is 100
  bytes / 25 instructions; the inventory's instruction count is doubled. The
  correct size 100 is what verifies byte-exact.

## Callers
Two direct call sites (the same routine appears in two overlapping generated
listings). The caller spills its own two arguments around the call and passes
nothing, so this is a plain no-argument initialiser.

## Callees
None. Leaf function, no stack frame, no saved registers, straight-line code.

The five descriptor objects are spaced exactly 100 bytes apart (`0x800A1AB0`,
`0x800A1B14`, `0x800A1B78`, `0x800A1BDC`, `0x800A1C40`), so they are five
consecutive members of one larger record table. Only their addresses are used
here; nothing is read or written through them.

The Japanese build's counterpart initialises a **second** parallel seven-entry
table in addition to this one and then reloads element 0 out of that second
table to seed the current-selection pointer. That is a different function body,
not a relocation of this one, so it is deliberately left unmatched here.

## Recovered behaviour
The routine publishes a fixed menu of seven descriptors. It first records that
seven entries are available, then fills a seven-slot pointer table with the
addresses of five distinct descriptor records in a fixed pattern — the pattern
repeats two of the records, so slots 0 and 5 share one record and slots 1 and 3
share another. Finally it points the "currently selected descriptor" global at
the record used by slot 0. It takes no arguments and returns nothing; every
value it writes is a compile-time constant, so calling it repeatedly is
idempotent.

## Status
Exact. USA, Europe and `lrg_rev1` all verified byte-identical from
`src/functions/func_80011DF0.c`. Japan excluded (different body).
