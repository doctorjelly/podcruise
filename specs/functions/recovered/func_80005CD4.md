# func_80005CD4

## Boundary

- USA VRAM range `0x80005CD4` .. `0x80005DA7` inclusive, 212 bytes (0xD4).
- Ends with a return whose delay slot is empty; the 0x30-byte frame is released
  in the instruction before it. All three arms join a common epilogue.
- The single call site targets `0x80005CD4`; the assigned boundary is correct.

## Callers

- One caller. It passes the address of one of its own stack slots as the first
  argument, a track record as the second, a single-precision position pulled
  from that record as the third, and a segment index as the fourth. Nothing is
  read back from the return registers, so the routine returns nothing.

## Callees

- `func_80005CAC(track, f32 position, s32 index)` — returns the normalised
  position of `position` within segment `index`, as a single-precision fraction.

## Globals and access widths

None. All state comes through the argument pointers.

## Record layout used

| offset | width | meaning |
| ------ | ----- | ------- |
| 0x11C  | ptr   | array of single-precision segment boundaries |
| 0x120  | ptr   | array of single-precision values, one per boundary |

Both arrays are indexed by the segment index, and each segment reads the entry
at its own index and the one immediately after it.

## Regional addresses

Entry, ROM offset and the callee address are identical in the USA, Japan, Europe
and lrg_rev1 builds: `0x80005CD4` / `0x68D4`, with `func_80005CAC` at
`0x80005CAC`.

## Recovered behaviour

The routine samples a piecewise-linear curve at a requested position and writes
the sampled value through the supplied output pointer.

The curve is stored as two parallel arrays inside the track record: a list of
boundary positions and a list of values at those boundaries. The caller names a
segment by index; the segment spans the boundary at that index and the boundary
at the next one.

If the requested position lies beyond the segment's upper boundary, the routine
clamps to the value at that upper boundary. If the requested position is at or
below the segment's lower boundary, it clamps to the value at the lower
boundary. Both clamps write the stored value unchanged.

Otherwise the position falls strictly inside the segment. The routine asks
`func_80005CAC` for the fraction of the way through the segment that the
position sits at, and writes the linear blend of the two boundary values using
that fraction: the fraction weights the upper value and its complement weights
the lower value.

The comparison against the lower boundary is inclusive while the one against the
upper boundary is exclusive, so a position exactly on a boundary resolves to the
stored value rather than going through the interpolation path.

## Note on source shape

The interpolation arm holds the two boundary values in named locals, lower
first, before combining them. That is visible in the original: the frame is
eight bytes larger than a single-local version needs, and the register the two
values land in is decided by the order in which they are read. Writing the
expression against the record directly, or reading the upper value first,
reproduces the behaviour but not the bytes.

## Status

Byte-exact against the USA, Japan, Europe and lrg_rev1 ROMs. No per-unit
compiler flags were needed.
