# func_80089610

## Boundary

USA VRAM 0x80089610 - 0x80089667 (88 bytes, ROM 0x8A210). Ends with the return
pair and a no-operation delay slot; three padding words follow before the next
function. Both direct call sites target 0x80089610 and nothing branches into the
range from outside, so the boundary is correct.

## Callers

Two direct call sites, at 0x800082E8 and 0x800084A4, in the file beginning at
ROM 0x8944. Both pass a pointer loaded from another object and an unsigned byte
loaded from a global with a byte-wide load, which fixes the second parameter's
width at one byte.

## Callees

* `func_8008FC3C` (0x8008FC3C) - takes the address of the sub-object at offset
  0x14 of the first argument, the address of the locally built message, and a
  zero third argument.

## Globals

None; every value comes from the arguments.

## Object fields read (first argument)

* +0x14: start of a sub-object whose address is passed on. Not read here.
* +0x3C: signed word, an index.
* +0x40: word, the base address of an array of 0x30-byte records.

## Message built on the stack

A 16-byte local record, passed by address:

* +0x00: halfword, set to the constant 8 (the message kind).
* +0x04: word, set to the address of record `index` of the array, i.e. base plus
  index times 0x30.
* +0x08: byte, set to the second argument.
* the remaining bytes are not written here.

The local's placement in the frame shows a second, pointer-sized local below it,
which is the array base held in its own variable before the record address is
formed.

## Sibling functions

0x80089670, 0x800896D0, 0x80089730 and 0x80089790 are the same shape with other
message kinds (3, 4, 2 and 0) and other payload widths (halfword, float, byte,
none). They share the frame layout, which corroborates the 16-byte message
record and the separate base variable.

## Compiler profile

This body does not reproduce under the project's default optimisation level: at
-O2 the byte payload is re-read from the argument home slot with a byte load,
which costs one instruction in the wrong place and shifts the delay slot. The
same source is byte-identical at -O3, which forwards the homed argument register
instead. The proven flag list is:

    -G 0 -O3 -mips2 -non_shared -Xcpluscomm -signed -Wab,-r4300_mul

That is recorded as `exact_under_profile` in the result file, and it applies to
all four versions.

## Recovered behaviour

The function posts a message to the sub-object embedded at offset 0x14 of the
actor it is given. It takes the actor's record array base, forms the address of
the record selected by the actor's current index, and fills a small message
record with the kind value 8, that record address, and the caller-supplied byte.
The message is then handed to the dispatch helper together with the sub-object's
address and a zero flag word. Nothing is returned.

## Status

Exact on USA, Japan, Europe and lrg_rev1 under the -O3 flag list above.
