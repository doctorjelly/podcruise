# func_80009134 — is the selected mixer level above zero?

## Boundary

- **Boundary correction.** The assignment gave `0x80009134` with size 64. The
  body branches to `0x80009174` and to `0x8000917C`, and the block at
  `0x8000917C` branches on to `0x800091A8`. All three of those addresses carry
  heuristic `func_` labels, none of them is the target of any direct call in the
  image, and the block at `0x8000917C` consumes a scaled index that is only ever
  computed in the delay slot of a branch in the first block. They are internal
  arms of one function.
- Corrected USA VRAM range: `0x80009134` .. `0x800091AF` (inclusive), 124 bytes.
- ROM offset `0x9D34`, translation unit `main_9B6C.s`.
- Four return sites. Two carry the constant one in the delay slot, one carries
  the zero, and the last has an empty delay slot because the zero was already
  materialised earlier in that arm.
- The preceding block ends with its own return at `0x8000912C` and the following
  function begins a fresh stack frame at `0x800091B0`.

## Callers

Seven direct call sites. Every one of them passes a small constant as the first
argument and zero as the second, and every one of them immediately tests the
result against zero — so this is a two-argument predicate returning 0 or 1.

## Callees

## Recovered behaviour

The routine answers "is the level currently non-zero?" for one of two level
tables, choosing the table from the first argument.

The first two selector values, zero and one, both mean "look in the second
table" and use the *second* argument as the element index. Any other selector
value means "look in the first table" and uses the selector itself as the
element index; the second argument is ignored in that case.

In both cases the chosen float is compared against zero and the routine returns
one when the level is strictly greater than zero, otherwise zero. No value is
written and nothing else is read.

## Status

Exact, with the boundary corrected from 64 bytes to 124. Byte-identical in USA,
Japan, Europe and lrg_rev1.
