# func_8002F550

## Verified facts

- The USA body spans VRAM `0x8002F550` through `0x8002F74F`, ROM `0x30150`,
  512 bytes. Execution ends at the self-branch at `0x8002F734`; its delay slot
  is `nop`. The restore and `jr ra` after it are unreachable compiler epilogue
  bytes, not a behaviorally reachable return.
- The input is preserved and later becomes the fourth argument to
  `func_8008B810`. It is not the destination of either table copy.
- The routine calls `func_8008BAB0`, `func_8008A2F0`, `func_8008A3B0`,
  `func_8008BDC0`, `func_8008B810`, optionally `func_8008B960`, and finally
  `func_8008BFB0` before stopping forever.
- Each table is 80 bytes. Every assignment is emitted as six 12-byte copy
  iterations plus an eight-byte tail.
- Japan maps uniquely to `0x8002FFB0` / ROM `0x30BB0`, and its next callable
  entry remains 512 bytes later. Europe maps to `0x80032B00` / ROM `0x33700`;
  its following entry is shifted by an additional 16 bytes.

## Behavior

Initialize the associated runtime subsystem, select one of three 80-byte
display-register templates according to the current regional video mode, and
publish the selected table as the active register block. Apply it, initialize
the related service, register `func_8002F750` as a callback with the supplied
context, and optionally activate the registration object. Restore the global
runtime priority and then deliberately stop in an infinite loop.

## Status

Byte-matching C for USA. An exact IDO 5.3 `-O2` comparison of the recovered
six-function translation unit reproduces all 512 bytes. Compiling this function
alone gave the wrong phase to the compiler's internal `.align 5` directive;
restoring its contiguous source grouping at `0x8002F440` places the unreachable
epilogue at the canonical address. No non-USA byte-match claim is made.
