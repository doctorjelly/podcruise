# func_8001E6C0

## Behavior

Draws the options menu, highlights the current row, and processes controller
press/hold state. The first two options adjust byte-valued settings;
other rows toggle available options or return early when quit is requested.

## USA source shape and status

The recovered C remains nonmatching. Before the loop-lifetime correction,
IDO 5.3 `-O2` emitted 3,436 bytes against the 3,492-byte USA body, with 855
differing words. The whole function has the same 33 ordered direct calls as
the ROM. The ROM stack frame is `0x58` bytes; the earlier C build used `0x48`.

The two doubles `D_800A9C30` and `D_800A9C38` are each loaded once on the
positive-controller-count path immediately before the input loop. The USA
assembly loads `D_800A9C30` at `0x8001EE28` into `$fs1` and `D_800A9C38` at
`0x8001EE38` into `$fs0`; those saved floating-point registers remain live
across the loop backedge at `0x8001F428`. The C now snapshots each value once
before the loop and reuses it for both byte-setting controls. This source
lifetime is supported by the ROM independently of its score; it is not an
exact match and does not demonstrate a runtime bug.

The USA ROM stores both values as binary64 `255.0` at ROM offsets `0xAA830`
and `0xAA838`. Those addresses belong to the configured raw `remainder` binary
segment, not a classified `.data` or `.rodata` section. The C declarations are
non-const, and global immutability or original ownership is unproven. A scan
of generated USA assembly found reads in this function and no explicit stores;
the recovered input-loop helper chain also has no evidenced writes to these
addresses. This evidence supports the observed loop snapshot without claiming
that the globals are globally immutable.

After snapshotting the globals, the isolated canonical audit measures
3,424/3,492 bytes with 835 differing words (17 missing instructions, zero
extra). The source remains behavior-recovered and nonmatching.
