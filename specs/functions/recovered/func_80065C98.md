# func_80065C98

## Boundary

- USA VRAM range `0x80065C98` .. `0x80065CAF` inclusive (24 bytes, 6 words),
  USA ROM offset `0x66898`.
- Ends with `jr $ra` and an empty delay slot. The single conditional branch
  targets that return.
- `0x80065CB0` immediately after is itself a called entry (func_80065CB0), so
  the end is confirmed from both sides.
- Three direct call sites all target `0x80065C98`.
- No boundary correction was required.

## Callers / callees

- Callers: 3 direct call sites. All of them load the first argument from the
  same field (offset `0x314`) of a parent object and guard the call with their
  own null test, then pass a float in the second argument slot — sometimes an
  immediate constant materialised in the integer register, sometimes a value
  moved out of a float register with `mfc1`.
- Callees: none. This is a leaf.

## Globals and access widths

- None.
- Argument 1 is a pointer to an object with a 32-bit float field at offset
  `0x68`.
- Argument 2 is a 32-bit float. Because it follows a pointer argument it
  arrives in the second integer argument register and is moved across to the
  coprocessor before use, which is the standard signal for "argument 2 is an
  f32" rather than an integer.

All three regional bodies were read independently and match the USA shape
exactly; there are no relocations to differ.

## Recovered behavior

A null-tolerant setter. If the object pointer is null the routine returns
without touching memory. Otherwise it writes the supplied float into the
object's field at offset `0x68`, replacing the previous value. Nothing is read
back and nothing is returned.

The move of the float argument out of the integer register happens before the
null test in the original, which is ordinary instruction scheduling and not a
behavioral detail: the value is only ever stored inside the guarded path.

## Status

Exact. USA, Japan, Europe and lrg_rev1 all verified byte-identical.
