# func_80089670

## Boundary

USA: VRAM 0x80089670-0x800896C7 inclusive, 88 bytes, ROM 0x8A270.
The body closes with a return whose delay slot is a no-op. Both direct
callers target 0x80089670, the preceding routine (func_80089610) returns
before this entry, and there are no internal branches, so the assigned
boundary is correct.

## Callers

Two direct call sites, both inside the same routine near 0x80008320 and
0x8000848C. Each sign-extends a halfword immediately before the call, which
fixes the second argument as a signed 16-bit quantity, and passes an owner
object loaded from a pointer slot.

## Callees

- func_8008FC3C - posts a notice to a queue. It takes the queue address, the
  address of a notice record and a deadline word, and internally copies
  sixteen bytes out of the notice record into the queue's storage, which is
  what fixes the notice record's width at sixteen bytes.

## Globals

None referenced directly; everything comes from the owner object.

## Owner object fields used

- offset 0x14 - the notice queue; its address is handed to the callee.
- offset 0x3C - a signed 32-bit index, read once.
- offset 0x40 - a pointer to an array of 48-byte records, read once.

## Notice record fields written

- offset 0x00 - 16-bit code, set to the literal 3.
- offset 0x04 - pointer to the selected 48-byte record.
- offset 0x08 - 16-bit payload, taken from the second argument.

## Recovered behaviour

The routine builds a three-field notice on its own stack and posts it to the
owner's queue without blocking.

1. It caches the owner's record-array base and selects the record that the
   owner's current index designates. The selection scales the index by the
   48-byte record size and adds the base; the compiler expands that
   multiplication into a shift, a subtract and a second shift.
2. It fills the notice with the code 3, the address of the selected record,
   and the caller's payload value stored as a halfword.
3. It posts the notice to the queue that lives at offset 0x14 of the owner,
   with a zero deadline so the post never waits.

## Compiler notes

Two source facts are forced by the frame:

- the notice record occupies the top sixteen bytes of a 0x30 frame, which is
  only reachable when the function declares one further small local besides
  the notice; caching the record-array base in a local supplies it and also
  reproduces the original's early load of the base and its operand order in
  the address computation (scaled index first, base second);
- the second argument is a signed 16-bit parameter, which is why the payload
  is materialised in a scratch register before the halfword store.

The translation unit was built at -O3, not -O2. At -O2 the halfword parameter
is re-read from its home slot with a sign-extending load, which is one
instruction in the wrong place; at -O3 the compiler forwards the homed
argument register instead, producing the plain register copy the original
has. Only the optimisation level differs from the accepted profile, and the
sibling wrappers at 0x80089610, 0x800896D0, 0x80089730 and 0x80089790 share
the same frame layout, so they are all in that one -O3 translation unit.

## Status

Exact in USA, Japan, Europe and lrg_rev1, under the accepted profile with
-O3 in place of -O2.
