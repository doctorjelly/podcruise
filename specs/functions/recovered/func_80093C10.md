# func_80093C10 — read the CPU status control register

## Boundary

- USA VRAM `0x80093C10` .. `0x80093C1B`; ROM `0x94810`; size 12 bytes.
- Ends with `jr $ra` plus a `nop` delay slot; one padding word follows. The
  single direct caller targets `0x80093C10`. **No boundary correction needed.**
- Flagged by the disassembler as a handwritten function.

## Callers

One direct call site, at the top of `func_8008B580` (USA `main_8BDB0.s`). Its
result is kept in a saved register, ORed with `0x20000000`, and handed straight
to `func_80093C00`, forming a read-modify-write pair.

## Callees

None.

## Globals and access widths

None; no ordinary memory is touched.

## Regional addresses

| version    | VRAM         | ROM        | size |
|------------|--------------|------------|------|
| us         | `0x80093C10` | `0x94810`  | 12   |
| jp         | `0x80094900` | `0x95500`  | 12   |
| eu         | `0x80099160` | `0x99D60`  | 12   |
| lrg_rev1   | `0x80093C10` | `0x94810`  | 12   |

All regional bodies are the same three words.

## Recovered behavior

Takes no argument and returns the current contents of the processor's main
status/mode control register as a 32-bit word, so that a caller can inspect or
edit individual mode bits and write the amended value back.

## Status

**skipped** — not recoverable as C, for the same reason as `func_80093C00`: the
body is a single privileged system-control-register read that no C expression
compiles to, and inline assembly is out of scope for this project. It belongs
in the build as a handwritten assembly unit.
