# func_80039CD8 — save or restore three fields of a state record

## Boundary

- **Corrected.** The assignment gave `0x80039CD8`, size 88. The generated
  listing splits the region into two heuristic labels, `func_80039CD8` (44
  bytes) and `func_80039D04` (48 bytes), and the assignment size is twice the
  first label's length rather than the real extent.
- The real function is `0x80039CD8` .. `0x80039D33` inclusive, **92 bytes**,
  ROM `0x3A8D8`, translation unit `main_18B28.s`.
- `func_80039D04` is not a function: it has zero direct call sites, it is the
  target of the conditional branch that opens `func_80039CD8`, and its first
  instruction completes an address whose upper half was formed in that branch's
  delay slot. It is the second arm of this function.
- Both arms converge on a shared final return at `0x80039D2C`, and the first arm
  has an additional early return whose delay slot carries a store. The next real
  function, `func_80039D34`, starts immediately afterwards, sets up a stack
  frame, and is itself one of this function's callers.

## Callers

Fifteen direct call sites, in the routines at `0x80028E88`, `0x80039D34`,
`0x80039EC0`, `0x8003A440`, `0x80044370`, `0x80045314` and `0x80084CC4`. Sites
pass a small literal in the first argument register (0 or 1 are the observed
values) and ignore the result, so the signature is
`void (signed 32-bit selector)`.

## Callees

None (leaf).

## Globals and access widths

| Symbol | Width | Use |
| --- | --- | --- |
| `D_80114488` | 32-bit words at offsets `0x1C`, `0x2C`, `0x40` | read and written |
| `D_801144D8` | 32-bit words at offsets `0x2C`, `0x40` | read only |
| `D_8011453C` | one 32-bit word | read and written |

`D_801144D8` is `D_80114488 + 0x50` numerically, but it is addressed through its
own independently materialised base rather than as an offset from `D_80114488`.
That is the decisive fact: expressing the pair as two elements of one array
makes the compiler fold both onto a single base and emit two instructions fewer.
The two are therefore separate named objects of the same shape — a live record
and a reference or default copy of it — with matching fields at `0x2C` and
`0x40`. `D_8011453C` is a standalone word used as a one-slot save area.

  `D_801144D8` -> `D_80117748`, `D_8011453C` -> `D_801177AC`.
- Europe: the corresponding routine at `0x8003E5A8` is 120 bytes and is *not*
  the same function. Its save arm continues past the save, reads a further
  global and, when that global is zero, writes the literal `0x400` into both the

  European form is deliberately left out rather than forced to match.
- lrg_rev1: unchanged from USA and verified byte-identical.

## Recovered behaviour

The routine is a two-way save/restore switch over one state record.

When the selector is non-zero it *saves*: if the record's word at offset `0x1C`
is currently non-zero, that value is copied into the standalone save slot and
the record's own field is cleared to zero. If the field is already zero nothing
happens at all, so the save slot is never overwritten with a zero and repeated
save calls are idempotent.

When the selector is zero it *restores*: the record's field at `0x1C` is
reloaded from the save slot, and the record's fields at `0x2C` and `0x40` are
overwritten from the corresponding fields of the companion record. The restore
arm is unconditional and does not clear the save slot.

Nothing else is touched and there is no return value.

## Status

Exact in USA, Japan and lrg_rev1 at 92 bytes. Europe intentionally excluded:
the European build of this routine has extra behaviour.
