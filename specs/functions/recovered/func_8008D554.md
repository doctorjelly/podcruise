# func_8008D554

## Boundary

USA VRAM 0x8008D554 - 0x8008D5A7 (84 bytes, ROM 0x8E154). The body closes with
the standard return instruction pair; the delay slot after the return is a
no-operation. The single direct call site targets 0x8008D554 exactly, and no
branch from the preceding function reaches into this range, so the assigned
boundary is correct. The next label, 0x8008D5A8, is a separate function with its
own prologue and its own caller.

## Callers

One direct call site, inside the routine that begins near 0x80088790 (call at
0x800888FC). It supplies a pointer taken from another object's field 0x30, the
result of a preceding allocation-style call, and a word read from field 0x4 of a
third object.

## Callees

* `func_80095AA0` (0x80095AA0) - registration helper taking a target object,
  two code addresses and a small integer selector.

The two code addresses handed over are `func_8008DD80` (0x8008DD80) and
`func_8008DD50` (0x8008DD50); they are referenced only as addresses, never
called from here.

## Globals

None. Every value the function touches is either an argument or a field of the
object the first argument points at.

## Object fields written

* +0x14: word, cleared to zero.
* +0x18: word, set from the third argument.
* +0x1C: word, set from the second argument.

The first 0x14 bytes of the object are not touched here; `func_80095AA0`
presumably owns them.

## Recovered behaviour

The function initialises a handler object. It first registers the object with
the shared subsystem entry point, passing the object itself, the two fixed code
addresses that make up its behaviour pair, and the selector value 7. It then
clears the object's status word and records the two caller-supplied values: the
third argument in the field at offset 0x18 and the second argument in the field
at offset 0x1C. Both arguments have to survive the registration call, so the
compiler keeps them in the caller-provided argument home slots across it.

Nothing is returned.
