# func_800520C8

## Boundary — corrected

- Assigned size was 28 bytes (0x800520C8 .. 0x800520E0). That is wrong: the
  first conditional branch jumps forward to 0x800520E4, which the label scan
  treated as a separate function.
- True USA VRAM range: 0x800520C8 .. 0x80052130 inclusive (0x6C = 108 bytes,
  27 instructions), ending with a return whose delay slot is empty.
- USA ROM offset: 0x52CC8.
- The four heuristic labels inside the range (0x800520E4, 0x800520FC,
  0x80052114, 0x8005212C) have zero direct callers; every direct call in the
  build targets 0x800520C8. The default result is set up before the last
  conditional branch, so the shared tail belongs to this function.

## Callers and callees

- Two distinct direct call sites in the USA build.
- One pointer argument, returns a small integer.
- No callees (leaf function).

## Globals and access widths

Four consecutive 32-bit object-pointer slots, each read as a full word and
compared with the argument:

- `D_8011B1BC`, `D_8011B1C0`, `D_8011B1C4`, `D_8011B1C8`.

These are the same four slots that the neighbouring counting routine tests
against zero.

## Recovered behavior

Looks up which registration slot holds a given object. The argument pointer is
compared with the four slots in order and the matching slot number (zero to
three) is returned; if no slot matches, the function returns minus one. It is
the inverse of the slot table used by the counting routine next to it, and the
minus-one result is the module's "not registered" answer.

## Recovery notes

As with the counting routine, the four slots must be separate named objects
rather than one array, otherwise the compiler forms a single base address and
indexes it instead of recomputing a split high/low address per slot.

## Status

Exact. Byte-identical in USA, Japan, Europe and the large-cartridge revision.
