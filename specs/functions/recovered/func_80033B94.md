# func_80033B94

## Boundary

**Boundary corrected.** The assignment gave `0x80033B94` with size 40. The entry
address is right; the size is not.

- True USA VRAM range `0x80033B94` .. `0x80033BCB` (inclusive), 56 bytes,
  14 instructions. ROM offset `0x34794`.
- The generated listing splits this range into three heuristic labels
  (`0x80033B94`, `0x80033BA8`, `0x80033BC0`) because the function contains three
  separate return instructions. The two later labels have no callers of their
  own and are reached only by fall-through and by branches originating inside
  the first range, so they are interior code, not functions.
- The split is an artefact of the branch-likely idiom the compiler used: each
  conditional branch carries a copy of its target's first instruction in its
  delay slot, and the original copy of that instruction is left sitting just
  before the branch target. Those stranded copies are what the heuristic
  mistook for entry points.
- The last return is at `0x80033BC4` and its delay slot at `0x80033BC8` is
  empty; the next function begins at `0x80033BCC` with a genuine stack-frame
  prologue.
- Independently, the shared inventory doubles the size of every entry in this
  file, so the sheet's 40 corresponds to the heuristic first fragment's 20
  bytes, not to the function.
- Not a shared tail of the previous function: the previous routine
  (`0x80033B5C`, same shape but reading a different field) has its own copy of
  the whole sequence and never branches past its own final return into this
  range.

## Callers

26 direct callers, for example `0x80048C04` and `0x80048C38`. All of them target
`0x80033B94` itself; nothing calls the interior labels.

## Callees

None. The function is a leaf and uses no stack frame.

## Globals and access widths

None. All memory access is through the single argument:

- one full-word load at offset 0 of the argument, read as a pointer;
- one 32-bit floating point load at offset `0x114` of that pointer.

## Recovered behavior

A guarded two-step field read that yields a single-precision number.

The function is given a handle. If the handle itself is absent it answers zero.
Otherwise it follows the pointer stored at the front of the handle to reach a
second record. If that record is absent it again answers zero. Only when both
links are present does it return the floating point value stored at offset
`0x114` of the second record.

Zero is returned as a genuine floating point zero, not as a reinterpreted
integer, so callers can use the result directly in arithmetic. The two absent
cases are written as separate early exits rather than as one combined test,
which is why the compiled form contains three distinct returns.

A near-identical neighbour immediately before this function performs the same
walk but reads offset `0x110`, so the two fields are almost certainly adjacent
members of one record exposed through a pair of accessors.

## Status

Exact in USA, Japan and Europe, with the boundary corrected from 40 bytes to
56 bytes.
