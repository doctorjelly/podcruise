# func_8002FC80

## Boundary

- USA VRAM range 0x8002FC80 .. 0x8002FCD7 inclusive, ROM 0x30880, **88 bytes**
  (22 instructions).
- The assignment file gave 176 bytes. **Boundary corrected**: the inventory
  merged this function with the one that follows. The body ends with the return
  at 0x8002FCD0 and its empty delay slot at 0x8002FCD4; the next function
  begins at 0x8002FCD8 with a stack-frame prologue.
- Single return point. No stack frame, so the function makes no calls.

## Callers and callees

- Two direct call sites in the USA build. Callees: none (leaf).
- The one visible caller passes the constant 1 in the first argument register,
  but the body overwrites that register with a table address before reading it,
  so the value is never used. The recovered form therefore takes no parameter;
  the constant at the call site is a leftover of an earlier interface.

## Globals and access widths

- `D_800D9DD8` - array of 32-bit words, read with word loads. The element at
  index 1 is read first, then successive elements are walked. Read only.
- `D_80114538` - 32-bit word, read once with a word load. Read only.
- The disassembly also shows the name `D_800D9DDC`; that is simply the label
  the generated listing attaches to the address of element 1 of the same table,
  reached as a walking pointer. Only one array symbol is really involved.

## Arguments and result

No argument is read. Nothing is returned that any caller uses; the return
register happens to hold the word read from the single global at exit.

## Recovered behavior

The function scans a global word table starting at index 1 and stops at the
first entry that is zero, giving the number of used entries plus one. It then
compares the last non-zero entry with a global threshold word, using an
unsigned comparison, and takes a decision on the result. In the shipped code
the branch taken on that decision reaches exactly the same place as the branch
not taken, so the comparison has no observable effect at all: the whole
function reads memory and returns without changing anything. Whatever the
conditional body once did was compiled away in the retail build, leaving only
the test.

## Regional forms

Not investigated - USA is not byte exact, so per the brief the regional forms
are out of scope for this function.

## Status

behavior - the scan and the comparison are recovered and the reads match the
original exactly, but the residual conditional branch could not be reproduced.

Fourteen source-shape experiments were run against the original bytes. The
loop, the table walk, the index arithmetic and the unsigned comparison
reproduce exactly (confirmed by a variant whose only surplus was the body of
the conditional, which compiled to 92 bytes against the original 88 with the
first 0x38 bytes matching). The obstacle is the conditional itself: with an
empty body the compiler discards the whole test, and with any body that has an
effect it emits at least one extra instruction. Constructs tried without
success: empty compound statement; an early return from a void function; a
`goto` past the end; a `while` loop whose body is a single break; assignment to
a dead local; assignment to a dead parameter; assignment to a returned local;
re-reading the same global inside the body (removed by common subexpression
elimination); two identical returns (keeps the branch but adds a second
epilogue and two register moves); and a volatile-qualified threshold.

The evidence says the original body held exactly one register-to-register move
that the register allocator later coalesced away, which is why the branch
survived dead-code elimination but the block emitted nothing. Reconstructing
that requires knowing which two variables were coalesced, and the retail bytes
do not record it.
