# Conservative IP-safety policy

This repository is designed to minimize avoidable intellectual-property risk
while documenting an interoperability and preservation-oriented reverse-
engineering process. It is an operational policy, not legal advice or a
guarantee that a use is lawful in every jurisdiction.

## Material allowed in Git

- independently written, general-purpose analysis and build tooling;
- project documentation written from scratch;
- compact factual metadata such as cryptographic hashes, ROM offsets, virtual
  addresses, counts, automatically generated placeholder names, and aggregate
  comparison statistics;
- clean-room source written from behavioral specifications and independently
  verified against user-supplied inputs;
- third-party dependencies only when their licenses permit the intended use,
  with their notices preserved.

## Material prohibited from Git

- ROM images in any byte order, including renamed or compressed copies;
- extracted graphics, audio, text banks, levels, fonts, models, or other game
  assets;
- generated disassembly or bulk instruction dumps;
- proprietary Nintendo/LucasArts SDK headers, libraries, documentation,
  compiler binaries, leaked source, symbols, or build artifacts;
- code, symbol files, or documentation copied from prior-art repositories that
  lack an applicable license;
- third-party source with unknown or incompatible provenance;
- packaged game executables that embed or require redistribution of protected
  game content.

## Clean-room workflow

1. Analysis produces a compact specification: behavior, addresses, control-flow
   facts, hashes, and tests. It does not place bulk binary-derived expression in
   Git.
2. Source is written independently from that specification. Contributors must
   not paste output from Ghidra, IDA, m2c, disassemblers, static recompilers, or
   an unlicensed prior project into a commit.
3. Generated local output may be used as a private diagnostic aid but remains
   ignored and must be discarded or regenerated locally.
4. A matching build compares locally generated bytes against a legally obtained
   user ROM. The ROM and extracted assets never enter Git, CI, releases, or issue
   attachments.
5. Every new dependency receives a license and provenance review before it is
   vendored or required by release tooling.

## Prior art

Public prior art may guide questions and independently verifiable facts. If a
repository has no explicit license, treat its code and authored symbol naming as
all-rights-reserved: cite it, do not copy it. `sp00nznet/racer` is currently in
that category for this project.

## Automated and human gates

`make safety` rejects committable ROM extensions, known N64 ROM headers,
generated/binary file types, generated-content directories, and unexpectedly
large files. This catches common mistakes but cannot establish provenance or
legality. Human review must still check every staged diff and dependency.

Before any public release:

- audit every tracked file and its provenance;
- verify that repository history never contained prohibited material;
- confirm all third-party licenses and notices;
- publish tools/source only, requiring users to provide their own validated ROM;
- obtain qualified legal review if the project or distribution model warrants
  it.

The bootstrap round-trip uses GNU binutils from the official Homebrew formula.
The locally generated ROM/ELF/map files remain under ignored `build/`; only a
small JSON result containing hashes and match status may be committed.

The dependency and compiler-provenance boundary is recorded in
[`TOOLCHAIN.md`](TOOLCHAIN.md). No project-wide source license is selected by
this bootstrap commit; that is a maintainer decision to make before inviting
public reuse or contributions.
